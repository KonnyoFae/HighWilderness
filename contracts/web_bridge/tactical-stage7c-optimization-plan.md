## 1. 当前结论

2026-10-10 用户确认将**自适应模拟降速**纳入后续 7c.4：算力不足时优先整体慢速运行，负载恢复后逐步恢复至 1×。2026-10-13 已接通基础功能；正常速度性能与降速可玩性继续分别验收，当前优先处理实测的命令与画面等待。

当前主要问题在后台模拟。纯炮 4 对 4 的离线步进已低于预算，但真实页面仍过载，说明最终必须验证“模拟、发布、读取、传输、请求处理”共同运行的实际通路。前端短回放的解析和画布提交开销较小，现阶段不优先重写画布或降低显示质量。

代码已核实的优化边界：

1. [`missile_guidance.py`](../../backend/high_wilderness_sidecar/missile_guidance.py) 先做区域相交，再判断电子区敌我和反辐射例外；存在提前跳过无关区域的空间。几何计算使用多个生成器与 `sum`，可评估保持边界行为的标量实现。
2. [`tactical_observation.py`](../../backend/high_wilderness_sidecar/tactical_observation.py) 会按传感器和目标反复计算传感器位置、控制能力与距离；数据链也会按每条航迹重算同一舰对的距离。共享航迹的样本时间、来源与跟踪容量必须保留。
3. [`aviation_flight.py`](../../backend/high_wilderness_sidecar/aviation_flight.py) 的返航分支每步枚举接收舰，调用 [`aviation_recovery.receiving`](../../backend/high_wilderness_sidecar/aviation_recovery.py) 构造源/目的库存、卸弹、安置人员，只为判断能否接收；这是航空热点中最具体的可改项。
4. 航空受击、飞行、武器与终局处理会复制飞行状态；终局处理在没有终局或母舰离场时也先复制。可增加无变化分支或按实际修改内容复制，但要先查清可变对象的归属。
5. [`aviation_logistics.Work`](../../backend/high_wilderness_sidecar/aviation_logistics.py) 复制整个库存，作业计时也会进入全状态验证和物资差分。应与返航资格判断分开优化，保持资源预留、作业完成和提交原子性。
6. [`realtime_view.py`](../../backend/high_wilderness_sidecar/realtime_view.py) 读取时先编码做字节检查，再解码生成独立返回值，外层协议仍需编码。可以评估减少重复编解码，但不可直接取消大小限制或让调用者修改已发布快照。
7. [`battle_preparation.restore_design`](../../backend/high_wilderness_sidecar/battle_preparation.py) 会重新编译并核对存档，准备读取、接敌预览、部署都可能经过该路径。需先逐 API 归因，再引入有界的已验证静态设计复用。

以下已有机制继续使用：RCS 为相邻角度 O(1) 插值，不在固定步重建整表；库存 `fork` 已是浅复制；设备可用性已有按修订号的已提交状态缓存；航空后勤已有无作业快速返回；同位置 `set_location` 已跳过提交；F 阶段已有近防滚动预测，D 阶段已有紧凑弹体流/显示历史处理。7c 不把这些重新列为新增优化成果。

### 7c.0：先补足正确性判据

原摘要包含运动、库存、炮状态、弹体位置/速度/耐久/寿命、飞机位置/层/任务等，足以支持这次归因过程未偏离原记录；但不完整覆盖制导内部状态、观测来源/时间、威胁承诺和所有事件。

实施优化前补齐：

- 每步本地/共享/失效航迹、采样步、来源、分配/容量、锁定状态；记录合法观测，不让共享来源冒充本舰雷达照射。
- 导弹目标、导引阶段/记忆/重搜/换层状态，近防威胁、火力承诺、发射和命中事件；比较稳定的逻辑字段，不比较墙钟时间。
- 航空任务、挂载/弹药、返航/回收进度、飞机与机组身份归属、作业/预留、物资台账、打捞及终局结果；随机过程有可获取状态时也纳入。
- 缓存内容不要求新旧逐字相同，但必须验证失败步不提交、源状态不被修改、结果等价、占用有界、结束及下一场清理。

扩展摘要另存 7c 目录，保留原 7b 文件及哈希。失败时输出首个不同步及字段，而非只有“散列不一致”。补充专项覆盖短基线没有发生的事件，不能把 900 步比较当作完整航空周转或终局验证。

### 7c.1：首个生产优化包

7c.1a 与 7c.1b 已分别交付本轮范围，见对应实施记录。以下保留设计约束；1b 的公共输入严格限于单次观测规划/视图和单次电子场回调，未扩展为全步所有消费者的共享缓存。

**7c.1a 区域遮挡：** 按层、区域类型、敌我与反辐射例外提前排除无效区域；保留实体箔条/热烟的双向效果，只有正在工作的干扰源豁免电子区遮挡。评估用直接二维运算替代生成器，并增加保守的区域包围框粗筛；只有边界对照证明等价才启用。记录每阶段候选区域数、粗筛拒绝数和实际相交次数，计数仅在诊断模式启用。

**7c.1b 观测公共输入：** 在一个不可变的候选阶段内构建位置、传感器原点、设备/船员能力和舰对数据链资格表；把按航迹重复的舰对距离变成按舰对计算。按需要复用同阶段的目标集和控制能力，目标距离限制仍逐目标判断。阶段输入有变化时重建，不建立只凭 `fixed_step` 的全步缓存。

舰艇雷达距离受目标方向 RCS 影响，可能超过设备标称基准；不能先按标称距离剔除。若以后增加距离粗筛，需用保守上界。暂不优先重写已有 O(1) RCS 插值。

观测的 `sample_steps=6` 是采样间隔，不表示可以每 6 步才检查可见性和设备资格。保留每步即时失效、跟踪容量与已有目标的分配次序，不直接把整个观测流程降到 10 Hz。

### 7c.2：返航资格与实际回收分开计算

先引入无副作用、轻量的接收判断，完整模拟与现有逻辑相同的卸弹体积、机体入舱、机组去向和临时货舱占用；正式到达后仍走原子转移与完整校验。轻量模型与旧 `receiving` 逐例差分，不能只看“剩余容积大于机体体积”。

保持母舰优先、其他舰按距离及稳定序号排列；拦阻索忙碌/毁坏时的等待、转降和无容量打捞结果不得变化。同一步前一架回收、作业完成、损毁、人员安置或库存变动后，后一架的资格必须重新基于最新候选库存判断。

第一版优先使用阶段内的局部结果。若跨调用缓存，不能仅依赖物资总量变化时才更新的 `reservation_revision`：人员住房、航空位置和机组状态等也会改变接收资格，必须具备覆盖这些变化的版本或身份键。

之后再做按需复制：无伤害时受击路径、无终局/母舰离场时终局路径可快速返回，但调用方必须遵守对象归属；`task`、设备开关、冷却、航迹映射等可变成员要独立。标为 frozen 的对象也需核实其内部没有可变引用。后勤纯倒计时路径只更新作业字段，资源预留与完成操作仍统一提交并验证。

### 7c.3 复核结论与 7c.4～7c.5 入口

- 导弹防御：7c.3 已处理 `tactical_missile_defense.prepare_all` 的预留全表扫描及不合法候选；实际制导接触、舰艇观测和威胁预测仍占主要成本。扫掠几何试验未在代表场景获得稳定收益，已撤下。后续扩展复用仍要求观测来源、采样步、运动/层、目标耐久、制导和火力承诺条件兼容，不延后临近撞击威胁。
- 发布/读取：同一发布快照内复用控制能力；静态航空配置和库存摘要按真实版本生成。编码复用须同时满足 JSON 有效性、1 MiB 实时响应/既有结算上限和调用者隔离，保留弹体流游标、重同步与事件完整性。不要只删掉读取时的解码而将内部可变对象直接暴露。
- 实时调度：增加可选的排队等待、单次泵、发布、响应编码与传输计时，解释纯炮 4 对 4 “离线步进达标、页面过载”的差异。现有待处理工作快速继续机制已存在，过载暂停是当前保护策略；后续按 7c.4b 增加明确的兼容运行路径，不将降速申报为 1× 性能通过。
- 准备/入战：缓存键至少覆盖规范化设计内容、历史目录/策略版本及编译身份相关输入；缓存只保存可安全共享的静态验证产物，活动库存、损伤和仓库修订仍重验。缓存容量有界；显式迁移、版本不匹配和非法存档仍走原来的检查。

### 7c.4b：高负载自适应模拟降速（基础功能完成，交互性能待收尾）

在 7c.4a 发布/读取优化和整条实时通路计时的基础上实施，在 7d 完整战斗联测前交付。保留固定 1× 路径用于原基线对照，兼容运行路径在持续算力不足时整体放慢场景。工程量中等，涉及调度器、后台状态协议、显示时钟、界面与回归，不修改各战斗系统的物理步长。

**时间与指令规则：**

- 每个权威步骤仍推进 `1/60` 模拟秒；0.5× 表示两秒现实时间推进一秒战斗时间。舰船、航空、弹道、火控、装填、维修、整备、回收、寿命和效果持续时间统一沿用模拟步骤；双方同速，不跳步、不改变每模拟秒的射速或观测规则。
- 根据持续处理能力调整现实时间到模拟时间的映射，负载下降后恢复，最高为 1×。统计覆盖步进、发布、读取和请求处理成本，保留操作余量；采用平滑估计、及时降速和缓慢恢复，避免单次尖峰触发反复变速。采样窗口、余量、恢复速率和保护边界作为可调整参数，由专项测量定值。
- 降速只调整后续时间推进，不继续按旧 1× 速度累加新债务。已有可恢复积压分批完成，不清空欠算步骤、不重放已完成步骤；债务始终受保护边界约束，超出可恢复范围仍保护暂停，不能仅放宽阈值来掩盖超载。
- 正常变速不等同于暂停，不取消已接受的指令、不仅因变速递增输入代次。命令仍按权威步骤和原有回执协议执行，重试不重复执行；前端显示时间不得作为命令目标步骤的来源。
- 现实时间用于菜单、镜头、选择、输入服务、连接租约、请求超时和性能统计；战斗时间用于战场状态与事件。暂停/恢复/新战局重新建立时钟锚点，暂停期间不补算现实时间。

**接入位置与运行保护：**

- `tactical_scheduler.py`：增加速率控制与时间映射，保留有界泵和步骤间服务输入。普通负载超标优先降速；手动暂停、失联、计算失败、时钟异常、输出严重积压及终局仍沿用各自保护。
- `realtime_view.py` / `server.py`：发布有效速度与降速状态，记录实际模拟/现实时间比及积压；状态发布和请求服务保持独立的现实时间节奏，避免跟随慢速而饿死输入或连接租约。
- 前端实时协议与 `presentation.ts`：显示时钟同步有效速度，变速时连续衔接；保持仅采样已提交状态、不超前推算、事件不重复和观测过滤。`RealtimePanel.tsx` 显示“自动降速 · 0.5×”等实际状态，暂停/选择/镜头仍可操作。
- 单个固定步当前不可中途打断，降低运行速度不能消除一个昂贵步骤本身的等待。继续优化热点，并单列最长步骤及命令等待；若极端负载超过可玩范围，明确记录限制，后续再评估可安全分段的计算，不宣称任意规模均可流畅运行。

**专项交付与验收：**

1. 用可控时钟覆盖持续超载、短尖峰、逐步恢复、频繁负载变化及暂停/恢复；验证变速生效后债务不持续增长，不产生无限追赶循环。
2. 相同初始状态、随机状态和按模拟步骤输入的指令，在固定 1×、固定低速及自动变速下逐步核对现有 18 类状态；降速本身不得改变弹道、命中、资源、机组、事件和结算。
3. 持续下令时切换速度，检查接受/执行回执、代次、重试、暂停和失联；原计算失败/时钟错误/背压/终局保护仍有效。前端覆盖同一步状态更新、速率变化、断流恢复、事件只显示一次及下一场清理。
4. 六套冻结场景分别记录固定 1× 与自动降速结果；真实页面检查有效速度、积压、最长步骤、操作响应和画面连续性。报告模拟时间、现实时间、各速度停留时长和保护触发原因，不能只报“没有暂停”。原生显示仍由 7f 验收。
5. 兼容运行通过不覆盖原 1× 性能失败；战斗命令回执与状态可见延迟继续按现实毫秒记录，不能乘速度系数后声称达标。15 分钟节奏评估按战斗模拟时间记录，并单列降速后的现实耗时与体验限制。
