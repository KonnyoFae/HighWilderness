# X1a.3 战前准备界面实现与验证

日期：2026-09-11。基线：`438a73a` 加 X1a.1—X1a.3 工作区改动。状态：`X1A3_SCOPED_PASS / X1A4_NEXT / PLAYER_DESIGN_DEPLOYMENT_NOT_IMPLEMENTED`。

本片完成实际战前准备界面及存储接线。玩家可以导入已保存的自建栖装、选择多艘实例、设置弹药资源和货物装载目标、预装填武器，核对全舰队变动后保存。实际交战入口仍待 X1a.4；战术试航继续使用技术舰，不把准备界面完成写成战略玩法完成。

## 已交付

- 工作区新增“战前准备”。切换时沿用编辑/战术暂停协议，准备操作与其他领域操作共用后台串行队列，不在实时固定步循环解析设计。
- 从原生文件选择授予的句柄读取保存栖装，或从可信目录选择设计；不接收前端自报的资源包、库存、规则或部署参数。独立实例保存实际设计绑定，原设计文件不被修改。
- 舰船列表显示名称、完整度及战斗/结算占用状态，支持逐舰切换。当前准备合同上限 16 艘；本片端到端实测为 2 艘，不能据此宣称 16 艘实际战斗验证。
- 弹药资源按现有弹药库容量设置，货物按共享容积管理；装载目标代表预装填前的数量。选择武器的保留现状、补装整批或显式弃置重装，显示容量、批次成本和待发弹数量。
- 准备核对复用 X1a.2 全舰队候选事务。错误定位到舰船、部件或物资；整批不合容量时不能保存，修正后重新核对。结果显示各舰装卸、装填和弃置变动，保存后摘要使用已保存库存与待发弹。
- 每次准备会话覆盖保存一份草稿，修改停止约 700 ms 后保存。切舰、切换视图和重启可恢复；草稿不消费资源。界面最多保留 32 个准备入口，玩家可移除不需要的入口，已提交回执及舰船状态不随入口删除。
- 草稿保存失败后锁定继续修改，可精确重试或重新读取仓库版本。正式准备提交回执丢失时锁定编辑、放弃和切换，使用同一准备身份及版本重试，或读取既有回执确认；不再次装填扣费。
- 导入请求保留来源副本和稳定身份，选择句柄已使用、后台重启或回执丢失后可查询同一导入，不重复创建实例。陈旧草稿保留但不能覆盖更新的库存或战损。

测试供给明确标注为初始 1000 点统一弹药资源、每种技术货物 100 份，使用后不自动补满。当前技术货物为特殊合金，每份 5 m³。实例初始弹药、货物和待发弹为空，人员与满燃料来自现有技术部署预设，不提供额外推力倍率。普通弹首版每批 5 点资源装 1 发；特殊弹配方接口保留，尚未接效果的弹种不能启用。
