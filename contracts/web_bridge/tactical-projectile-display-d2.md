# D2：炮弹前端插值与本地尾迹

2026-09-21。本阶段已完成普通炮弹及近防炮弹通路；接续D3导弹显示。导弹仍沿用D1增量路径，完整生命周期清理、最大编制和长期性能验收留在D4/D5。

## 实现

- 显示流升级为`gaotian.projectile-stream/d2-v1`，新增`shells`状态锚点：步号、位置、速度及该点之前一段的插值方式。通常仅发送新发布端点，已有的前锚点不重复发送；少量误差超限段补关键点。炮弹常规增量响应不再包含`trajectory`，导弹继续使用`paths`。
- 前端用相邻位置/速度进行单调约束Hermite插值，防止倒飞或过冲；后台以每个已提交固定步之间的直线路径为参考，用Bezier控制点凸包给出整段误差上界。超过5厘米时拆分，仍不满足的单步段退为直线。真实碰撞、拦截、到期终点始终走明确的线性终段，不把碰撞后的速度平滑进舰内。
- 实际初速已经含舰艇运动和跨层折算，显示端不再次降速，也不按“当前速度×总飞行时间”推算。生存期、命中、观测及伤害仍由后台决定。
- 后台炮弹每步只向有界临时队列追加一个采样，正常约4步发布后只留端点；不再逐步复制最近32步。发布时维护约32步的压缩恢复窗口，异常长缺口临时队列最多33点，沿用显式重同步。终止记录进入D1独立有界队列，批量300枚结束不受旧128条显示上限限制。
- 前端按弹体ID保留有限状态窗口，0.06秒尾迹在世界坐标中按模拟时间取样。30/60/120显示帧率得到相同时间的相同尾迹，镜头移动和缩放不修改世界轨迹。曲线系数按不可变窗口缓存，窗口释放后可回收；暂停冻结、缺读不外推、不会通过延长寿命补播短命弹。
- 保留旧格式的普通读取及控制响应：仅这些请求按需从显示状态重建旧轨迹字段；常规D2读取不支付这一兼容转换。前端仍能读取D1录制数据，当前生产协商版本为D2。导弹的旧历史生成暂未移除。
- 敌方有耐久炮弹仍只显示合法观测位置，不能使用新缓存中的隐藏真实轨迹；失联裁掉旧显示。红蓝1像素点/3×3像素空心框继续在天气前景之上绘制。
