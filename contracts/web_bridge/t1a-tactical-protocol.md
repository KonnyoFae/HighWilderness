## 场景来源与生命周期

唯一产品样例为 `gtw.sample.web.two_ship.v1`，使用两艘阶段 F 常规有人舰，分属蓝/红阵营。初始位置为 `(0,-300)` / `(0,300)` 米、朝向 0 / π 弧度、速度为零，上层高度。每舰 2 层船壳、18 个模块。技术出航沿用阶段 F 人员配置和 800 单位燃料，不装散货；弹药库 20 发标准 76 mm 弹，每门武器备弹 1 发。创建时从当前资源重建实例、武器时钟与无事故持续毁伤状态，不加载旧完好实例文件。

模块目录和舾装通过已有具名、指纹受检迁移生成可排程推进资源；新场景直接初始化六个方向通道、已提交的安全 governor 和 v7 完整安全上下文。没有冒用旧 T0 场景名、跳过来源验证或升级旧场景。`tactical_scenario.py` 不导入测试模块和基准生成器。

表现资源清单保留源舾装/目录、迁移后目录、船壳、涂料、材料、派生快照、完整技术出航配置、武器时间、弹丸、持续毁伤及安全配置的指纹。`resource_bundle_sha256` 由清单生成。每次创建另分配 `scene.<uuid>` 作为桌面场景句柄，与确定性的技术样例身份分开；释放或重启后旧句柄失效。

## 请求

沿用 W0 `gaotian.web-bridge/v1alpha1` 信封和预留的 `tactical` 命名空间。编辑作用域 `session_id / expected_revision` 必须均为 null，成功响应的编辑修订也为 null。故无需修改 W0 信封/黄金。Rust 通过独立 `bridge_tactical_request` 命令白名单接入，不能经此入口调用编辑保存或文件授权。

| 方法 | params（全部字段必填） | 结果 |
| --- | --- | --- |
| `tactical.create` | `scenario_id`，只接受上述技术样例 | 完整初始表现快照；已有场景则拒绝，不覆盖 |
| `tactical.inspect` | `scene_id`、`known_static_sha256` | 只读表现快照；匹配静态指纹时不重复发送静态几何 |
| `tactical.close` | `scene_id`，必须精确匹配 | `{closed:true, scene_id}`，释放状态、绑定和缓存 |

`inspect.scene_id=null` 专用于重新发现当前场景，解决前端未收到创建结果时失去句柄的问题；不会创建或推进场景。无当前场景返回 `tactical.scene_missing`。`close` 不接受 null 作为通配符。`known_static_sha256` 为 null 或小写 64 位 SHA-256，未知但格式合法的指纹返回完整静态数据。

新方法与编辑命令共享容量为 8 的串行工作队列。系统心跳不进入此队列；队满明确拒绝。创建完成前不会暴露半个场景。未知/重复创建、错场景、错作用域及参数错误不改变当前状态。T1a 最多保有一个始终暂停的两舰场景，可与当前编辑会话同时检查；T2a/T3a 再引入明确的模式切换和实时所有权。

## 表现快照

`gaotian.tactical-render-snapshot/v1alpha1` 字段：

- `backend_instance_id / scene_id`：后台和桌面场景身份。
- `authority_interface`：v7；`paused`：本阶段始终 true。
- `fixed_step / fixed_step_s / time_s`：权威固定步、1/60 秒步长和模拟时间。
- `static_sha256 / static`：静态数据指纹与数据，复用时数据为 null。
- `ships`：每舰位置、朝向、线速度/速率、角速度、高度层、船壳完整度、物理/指挥状态和模块当前耐久。
- `events`：本阶段始终为空，创建或读取不伪造开火/命中事件。

`static` 使用 `gaotian.tactical-render-static/v1alpha1`，包含资源清单和每舰的名称、阵营、舰队、派生身份、各甲板轮廓及模块位置/朝向/本体/内部与顶挂占用/最大耐久。轮廓、锚点及本体坐标以米计；内部/顶挂占用为 `[层, x格, y格]`，每格 5 米。局部船艏为 +Y，航向弧度直接沿用内核。表现投影不改权威状态，也不把整份存档当作显示数据传送。

前端保留静态数据，只接受同一后台/场景、非过期步号和匹配的静态绑定。旧后台或已释放场景结果不能替换新视图。新增“建立两舰场景 / 读取场景状态 / 释放测试场景”入口显示暂停状态和两舰信息，明确提示画布与操纵待接入。

## 为 T3a 冻结的输入与事件形状

`gaotian.tactical-input/v1alpha1` 含 `scene_id/input_seq/target_step/command/arguments`。目前只定义 `command=control`；参数为 `ship_id` 与已有 `gaotian.tactical-propulsion-control/v2alpha1` 控制对象。序号严格递增，整数须在 JSON 安全范围内；`target_step` 指尚未积分的当前开边界，迟到和未来步均拒绝，不隐式换步；舰艇必须属于场景。方向命令继续由已有规则解析。纯校验器已有测试，**尚未启用输入请求能力或执行玩家输入**；后续控制仍须经过既有指挥仲裁。

`gaotian.tactical-visual-event/v1alpha1` 固定 `scene_id/event_id/fixed_step/type/ship_ids/payload` 形状；事件身份与固定步用于后续去重。此阶段只声明事件合同，真实事件投影随 T3a/T4a 接入，不宣称已验证开火事件序列。差量协议与独立回放仍后移。
