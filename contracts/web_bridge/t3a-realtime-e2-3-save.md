# E2.3 内部保存重建与续跑验证

> 2026-09-12 统一设计目标（优先于下文旧计划）：当前已开发的全部内容均属于战术模式，包含舰艇编辑、准备、交战、损管与保存；战略模式尚未开始开发，ST0 仅为未来衔接预留接口。未来大部分战斗是中远距离交战，由战略模式操作与战术模式近距离模拟、演出共同构成，玩家绝大部分游戏时间在战略模式经过。单场战术模式最大预期持续时长为 **15 分钟**，超过须整体调整游戏平衡；不新增强制计时结束机制。**两小时测试需求彻底取消**，不保留必测、可选、按需或恢复条件；既有 30 分钟测量仅为历史工程证据。详见[总规划第二章](../../高天荒野游戏规划归档.md#二战略层与战术层的战斗关系)。

日期：2026-09-09。代码基线：`4bef488` 加工作树中的 E2.1—E2.3 改动。新文件不兼容旧 v7 场景存档，不修改旧黄金或编辑器合同。

## 已实现的内部合同

[`tactical_checkpoint.py`](../../backend/high_wilderness_sidecar/tactical_checkpoint.py) 提供 `dumps(session)` 和 `loads(payload, seeds, safety_profile, direct_ship_id=..., allow_test_device_rebuild=False)`。版本为 `gaotian.tactical-checkpoint/e2.3-v1alpha1`，政策固定为六方向贡献、无配平、战术推进不耗油及旗舰失权锁存。

导出只允许会话拥有者在已提交的空闲边界执行。候选投影回调和其他线程不能保存。加载在新会话内完成，全部验证成功才返回，不修改原会话；新场景身份拒绝旧会话输入。加载者必须提供已严格准备的完整种子和安全资源，资源绑定还包含模型、贡献、模块、人员初态、控制配置、初始阻塞和测试重建权限；仅有相同资源 ID 不足以通过。

| 保存内容 | 加载处理 |
| --- | --- |
| 位置、速度、朝向、角速度、船体完整度、固定步 | 有限数/范围检查，舰船与世界步号一致；当前格式限制同高度层、无层间过渡，燃料与初态一致 |
| 模块耐久、操作序号及最后请求摘要 | 绑定模块顺序和耐久上限；校验最后请求与当前状态的基本一致性，重建宿主依赖及自身/宿主阻塞 |
| 工作模式、人员、供电策略、序号、跳闸锁存 | 从当前设备与发动机阶段重算供电、人员和故障事实，核对发动机阻塞；不自动复位 |
| 发动机阶段、目标/实际输出、响应锚点、到期步、各原因版本 | 严格解析并绑定发动机资源；用编译时间规则重演当前响应段，核对阶段与到期步；重新构造六方向能力/输出汇总和到期队列 |
| 六方向目标与安全上限、原因、介入/释放候选步 | 保留正在生效的安全限制和释放等待，校验时间、档位和原因的一致性 |
| 生命周期、失权原因/步号、退出原因/时间 | 重算当前功能和指挥派生值，同时保留 falling、旗舰失权及退出的历史锁存；不因设备恢复而重新授权 |

缓存键、资源分配结果、能力汇总、内部证明和内存地址不进入 JSON。逻辑版本保留，加载重算不产生新领域事件、不推进固定步、不增加存档中的版本。第零步要求与所绑定的已准备初态完全一致。

上一交付区间的 `last_result` 不是续跑输入，不在此格式内；加载后为 `None`，下一步生成的回执与不中断运行完全一致。E3 可靠请求回执与重连恢复另立合同，不能把这里的最后请求摘要当作可靠消息历史。当前存档也不是防篡改签名或可证明的完整操作历史。

未知/缺失字段、重复 JSON 键、非有限数、错误版本/政策/资源、错误船序、越界耐久、未处理到期、矛盾阻塞和权限状态等均拒绝。使用显式 JSON 字段，不从文件动态导入类，不接受 pickle。

## 支持范围审计

| 领域 | 本片范围与未接部分 |
| --- | --- |
| 血量/损毁/宿主 | 保存 E2.1 模块耐久与损毁结果；真实弹丸命中生产者到 E4 接入 |
| 恢复 | 保存已经接受的测试重建结果，默认关闭且权限必须与加载者一致；普通修复、替换和战斗复活未实现 |
| 人员/伤亡 | 保存当前人员计数；已准备资源中的伤员数量参与身份绑定；动态伤亡、救治、伤员流程尚无状态适配，不能导入旧事故状态 |
| 燃料/紧急断推 | 战术推进不扣燃料；保存已有内部不可用/紧急断推原因与版本；实际燃料损失、管线事故和紧急断推生产者仍未接入 |
| 指挥/退出 | 单旗舰 CIC/配置遥控核心、失权锁存和两种受控退出；无 RTS、旗舰替换、无线传播、距离退出或三维坠落过程 |
| 质量/结构/高度 | 固定编译质量和结构，保留船体完整度变化；动态结构脱落、质量变化与换层不在格式中 |
| 武器/事故/随机过程 | 未接装填、弹药、弹丸、火灾、殉爆和相应随机状态；格式无相应字段，旧完整战局不能静默丢字段后导入 |
| 产品保存 | 仅内部 JSON，未接文件对话框、磁盘原子写入、后台保存或玩家设计迁移 |

范围内的设备、资源、指挥、响应和重建闭环可以进入 E3 调度实验；完整 E2 生产者覆盖和产品实时不能据此宣布通过。

## 验证方式

新增 [`test_tactical_checkpoint.py`](../../tools/test_tactical_checkpoint.py) 15 项测试，相关回归 **108 项通过，28.866 秒**。覆盖初态、启动/响应/减速/转向、安全介入及释放候选、跳闸与显式复位、部分伤害和重建、遥控失联后恢复、CIC 损毁后重建仍坠落、两种退出在步首/步末生效、旧场景输入拒绝、错误存档原子拒绝、保存线程和重入限制。稳定读档会话的供电与生命周期重复求解被故障注入探针禁止，60 步运行仍通过。

[`verify_tactical_checkpoint.py`](../../tools/verify_tactical_checkpoint.py) 比较不中断运行与多次加载续跑。每类负载在 18 个边界保存重建，覆盖启动响应、集中资源故障、复位、CIC 失权及恢复，逐步比较完整舰状态和后继回执。每次加载生成新身份，未来请求按新身份重新绑定；不重发已经提交的请求。

吞吐沿用 E2.2b 两舰和三类输入带：预热 600 步，在边界 600 保存重建，再测量 3600 步，各重复三次。保存/加载、严格准备、输入带构造、对照和画像不计入热循环；保存与加载耗时单列。此处的人工电力/人员蓝舰夹具不修改玩家资源。

冻结证据：[`e2-3-20260909-checkpoint/result.json`](../../artifacts/t3a-realtime-experiment/e2-3-20260909-checkpoint/result.json)。54 次保存重建、三类负载合计 **12603 个边界**与不中断运行一致；另有相同输入的两个新会话比较及九轮计时终态核对。每个检查点保存原始 JSON，目录还含源码/资源归档、输入带、完整终态、逐步计时、独立画像和文件哈希；68 个证据文件哈希复核通过，运行前后源码/资源清单一致。

| 读档后负载 | 最差平均 ms/步 | 最差 P95 ms | 最差 P99 ms | 最大单步 ms | 蓝舰有输出步数 |
| --- | --- | --- | --- | --- | --- |
| 稳定飞行 | 0.287 | 0.376 | 0.503 | 1.300 | 3600 |
| 资源故障、恢复与复位 | 0.322 | 0.501 | 0.845 | 2.100 | 708 |
| CIC 停用后恢复，直控保持失效 | 0.329 | 0.475 | 0.616 | 1.764 | 1500 |

九轮通过既定范围内吞吐门。画像中旧配平、运行参数编译、静态指纹及时间能力解析均为零；三负载的供电/人员分配函数分别调用 0、156、3 次，与 E2.2b 对应负载一致。不能将本机运行波动解释为新优化增幅，也不能将断推阶段的耗时代表持续交战性能。

54 个检查点的 JSON 大小为 13521—13690 字节；导出耗时中位数 **5.616 ms**、范围 4.425—7.120 ms，加载中位数 **9.382 ms**、范围 7.235—13.312 ms。导出含资源绑定哈希和 JSON 编码；加载含新会话建立、绑定校验及动态重建，但不含调用者从磁盘严格编译种子、文件读写和 UI。这是单次边界样本统计，不是后台异步保存或端到端延迟承诺。

结论：`E2_3_IMPLEMENTED / IMPLEMENTED_E2_SCOPE_PASS / E3A_NEXT / FULL_E2_NOT_PASSED / PRODUCT_REALTIME_NOT_PASSED`。桌面默认运行路径不变。
