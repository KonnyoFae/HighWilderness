# 战前准备画布与部件操作设计

日期：2026-09-17。状态：5a 双方画布、部署、距离、测试补给、部件点选与五页已接通，见[实施记录](./tactical-stage5a-preparation-canvas.md)；5b 已接通单件/本舰同类补满及未毁部件战前维修，见[5b 记录](./tactical-stage5b-preparation-maintenance.md)；导弹准备随 5c 接入。依据用户对现有准备界面简陋、臃肿的反馈，具体化[导弹阶段测试改造](./current-tactical-test-plan.md#导弹阶段双方测试配置物资与界面重设计2026-09-16)。按[5a～5i 实施分解](./tactical-stage5-implementation-plan.md)继续推进，不作为工作包 5 完成记录。

## 已确认的页面结构

战前准备以展示、调整舰队排布的画布为主体。舰艇按实际设计外形与模块位置显示，允许选中舰艇调整排布，也允许点选舰上的具体模块查看和操作。布局不是从准备舰船列表进入逐舰长表单，而是在画布中选择对象后打开对应操作。

- 共用一块准备画布，同时显示上下两个舰队视区：敌方在上、我方在下，便于对比。顶部我方/敌方配置分页切换当前编辑方，不切走或隐藏另一方视区；选中另一方舰艇/模块时同步当前编辑方与右侧内容。
- 左侧浮动“加入舰船”窗口，可选择加入我方或敌方，并导入已保存的栖装文件。
- 右侧浮动部件窗口，包含“火炮 / 导弹 / 设备 / 损管 / 货舱”五个页面；部件详情及操作在对应页内展开。
- 点选具体模块后，右侧自动跳转至对应页面、定位并突出该模块，不要求玩家再从全舰列表寻找一次。
- 双方使用相同的准备操作能力；战前可配置敌方不改变战中的旗舰直控、AI、感知和火控规则。准备页的五个分类不取消已规划的战斗火控页面。

浮动窗口应保留足够的画布操作空间，窗口内操作不穿透到画布拖舰。窗口尺寸、折叠方式、舰艇拖放/朝向调整、甲板切换与缩放细节在具体界面稿中安排，不要求玩家先指定每个按钮。

## 导入与舰队排布

1. 玩家在加入舰船窗口明确选择目标阵营，再选择栖装文件。
2. 文件选定、开始加载时立即出现明确的“正在加载”提示，并标明正在导入的文件与目标阵营；不能只禁用按钮，让玩家猜测是否正在工作，也不能等导入完成后才提示。
3. 加载成功后自动在对应方画布生成新舰船并加入该方配置，不再要求从另一个准备列表二次勾选。可定位并选中新舰，方便继续摆放和准备。
4. 加载失败时显示可理解的原因与重试入口；取消选文件不生成舰艇。一次导入的重试不能重复创建，同一设计有意多次加入时则使用独立舰艇实例。
5. 导入开始时记录所选阵营，等待期间切换分页不应将完成结果放入另一方；重试仍对应原导入任务。

画布中的舰队排布须进入场景配置，实际部署保持保存的舰队内部排布。用户已确认双方编队配置时可以更改测试用的开始交战距离，提供明确的距离输入和单位，按既有双方旗舰测距口径生成初始部署；改变距离时移动舰队基准点、保留各队内部相对位置和朝向，预览与实际入战一致。上下双方视区仍同时显示，视区的屏幕间隔不当作实际交战距离。

该距离是测试场景参数，不修改正式上层 50 公里、云/雨层 25 公里的交战/脱离规则，不修改感知或武器射程。场景保存/重新读取须恢复该参数；非法值须说明原因，不能静默退回固定距离。坐标、阵营、舰艇实例与模块身份贯穿点选、准备、预览、部署和结算，不由固定测试敌舰或旧自动排布覆盖。初始摆放位置、允许编辑范围、朝向/高度控件另行细化；沿用舰艇不互撞规则，ST0 现有部署重叠拒绝须在 5a 对齐，不能从旧校验新增舰艇碰撞玩法。

## 模块点选与页面对应

| 点选对象 | 自动进入 | 主要内容 |
| --- | --- | --- |
| 火炮、近防炮塔 | 火炮 | 弹种、待发弹容量/余量、装填与库存操作、部件战损和修理入口、单部件/同类补满 |
| 导弹发射器、VLS | 导弹 | 兼容型号、VLS 选型、战斗部、已装弹与装填来源、部件战损和修理入口、单部件/同类补满 |
| 专用导弹库 | 导弹 | 库型号、整装弹库存、组装任务与进度、战斗部和资源；单库/本舰同类补满按组装规则安排，不将组装并发量当作库存容量 |
| 火控雷达、红外、指挥机、数据链等一般设备 | 设备 | 工作条件、配置与部件状态，提供其适用操作 |
| 损管设备 | 损管 | 损管耗材、准备状态、部件战损和修理入口、单部件/同类补满 |
| 油料储槽、普通弹药库、货舱 | 货舱 | 对应油料/弹药/货物库存、容量和装卸；油料与弹药库提供单部件/同类补满及修理入口 |

一般部件信息应始终标明所属方、舰船和部件，避免跨舰/跨方误操作。无法工作、已毁、缺料或不兼容时说明原因。模块跨多层甲板仍按一个模块身份操作；油料填充槽等非普通安装模块也需有稳定选择身份，不重复计数。

现有货物库存按全舰汇总，普通货舱点选可显示该舱容量及本舰货物管理；不能凭前端切页伪造已经存在的逐货舱分配。是否需要将货物进一步分仓不是本次补满油料/弹药/损管/武器的前提。

## 单部件与同类部件一键填充

油料、弹药库（包括专用导弹库）、损管设备、炮塔及导弹发射器均提供“填充此部件”和“填充本舰全部同类部件”。用户已确认全部同类仅作用于当前所选舰艇，既不扩展到同方其他舰艇，也不影响敌方；按钮与结果明确显示舰名和影响部件。

一键填充以各部件当前可用容量与已有余量计算缺额，目标是补满，不是简单地再装一批，也不先清空已有库存。操作自动生成装载计划及资源核对，玩家无需逐项输入数量；沿用统一准备事务落库，不由多个部件按钮各自无确认地写出不一致库存。预览/草稿不扣料，提交不重复扣料，具体保存入口在新界面中统一组织。

| 部件 | 填充目标 | 必须衔接 |
| --- | --- | --- |
| 油料储槽 | 补足所选槽的有效燃料容量 | 按实际缺额消耗燃料供给，不以高能燃料货物替代灵烷账户 |
| 普通弹药库 | 补足可用弹药资源容量 | 与武器预装填的原料消耗一起核对，显示最终库存，避免把装填前数量当作装填后余量 |
| 专用导弹库 | 按所选型号/战斗部安排补足整装弹库存的组装任务 | 仍扣配方资源并遵守组装时间和并发能力，不因点击补满即时生成无来源整装弹 |
| 损管设备 | 补足损管资源容量 | 5b 已支持部分余量补足，按缺额占满容量的比例逐材料向上取整扣费；原整批准备仍限空设备 |
| 炮塔 | 按该部件当前所选合法弹种补足待发容量 | 保留已有弹与选择；按实际缺弹数补齐，每项材料费用为完整配方成本乘缺弹数除以配方发数、向上取整，不能超容 |
| 导弹发射器/VLS | 按本发射器所选型号和战斗部补足装载量 | 兼容整装弹优先，无整装弹时按原料途径；已有型号、弹径容量与卸弹返还规则保持 |

同类批量填充让每个部件按自己的容量、兼容型号与当前选择计算，不能将所选炮塔的弹种强行套给不同口径，或把一具 VLS 的型号覆盖给其他 VLS。“同类”的设备分组在型号数据中明确，跨口径/跨发射器兼容性仍逐件校验。

用户已确认新增战前维修，消耗工程材料。在选中油料/弹药库/损管/炮塔/发射器后提供修理操作，展示战损与预计材料消耗；这是相对现有“战前准备不修复战损”的新增能力，须接入真实部件耐久、容量/功能恢复与准备事务。用户已确认仅修复尚未摧毁的部件。5b 保存准备时即时修至满耐久，材料由共享供给池支付，初值为每份工程零件修 25 点耐久、每件向上取整；普通模块及独立填充燃料槽均支持。已毁部件不可战前修理；不由此允许重建已判定为残骸的整舰，也不改变既定战中升力储罐紧急抢修规则。

补满与维修是独立操作：补给不恢复部件耐久，战前维修也不隐式补满油料、弹药或损管耗材。两者的材料和状态变动一起进入准备核对与原子保存，不能先扣维修材料但未保存修复，或保存修复后重试再扣一次费用。

资源不足时显示具体缺项和涉及部件；用户已确认整次操作不提交并显示缺项，不自动按余料部分填充。页面应区分供给池余量、舰内原料、部件库存及预计准备后的余量，保留手动装卸和数量调整。

## 接入顺序与验收

1. 先建立双方场景配置和排布数据、画布主体与两侧浮窗，接通阵营选择、栖装导入和加载/失败反馈，以及测试初始交战距离设置。
2. 再实现舰艇/模块点选、右侧五页自动定位，以及油料、弹药、损管和炮塔的单个/同类补满；与原预览、草稿、提交、保存和测试重置衔接。
3. 按导弹能力接入发射器/VLS、战斗部、导弹库、整装弹等准备操作；复用 5b 已接通的工程材料维修及一次准备提交，不另建库存或耐久保存链路。
4. 在实际界面验证敌方上/我方下同时可见，分页只切编辑方、两块视区均不消失；验证双方编组与排布、慢速导入可见提示、切页期间导入归属稳定、重复点击不重复生成、失败不留半成品舰艇。
5. 验证画布上每类模块都能跳到正确页并定位，跨舰/跨方选择不残留上一对象；浮窗点击不拖动画布对象。
6. 验证单部件补满、本舰同类批量且不改其他舰艇、部分已有库存、满容量无重复消耗、不同容量/口径/型号各自正确、缺料/超容/已毁反馈和保存重试。战前维修须验证材料扣除、耐久与容量恢复、缺料不产生免费修复、补给与维修互不隐式执行，以及重复保存不重复收费。
7. 验证摆放结果实际入战、敌我身份和库存不串写、连续两场与返回准备、强制放弃测试进度后能够重新配置。 同一编队设置不同距离入战，双方旗舰间距与设置一致、编队内部相对位置和朝向保持，重新读取场景能恢复距离。
