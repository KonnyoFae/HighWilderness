# D1a 损管资源与准备事务实施记录

日期：2026-09-11。状态：`D1A_RESOURCE_SCOPED_PASS`。完成[D1 规划](./d1-damage-control-plan.md)第 1 步的后台合同、资源事务、离线舰队准备与持久保存。本片不包含实际灭火、模块维修、船壳修复或玩家操作界面；默认导入仍使用 S1 策略，下一片为 D1b 真实火灾与灭火循环。

## 已接通

- 每具已安装损管设备绑定独立容量和准备配方，保存独立余量及必要准备状态。新建实例资源为零，入战/重开不补满；旧资源和旧存档继续使用原合同，无静默迁移。
- 工程零件使用全舰共享货物 `cargo.engineering_parts`。与武器特殊弹配方共用同一个库存及预留池，不建立第二份货物账户。预留仍占货舱容积，准备完成消费后才释放容积；设备内已准备资源不重复计入货物容积。
- 只有资源已空且没有准备中的设备可以开始准备。开始预留整个配方，期限到达后一次扣除零件并补满设备；取消仅释放预留。部分余量不允许额外准备、覆盖或免费补满。
- 耗用是可信库存原语，按整数单位扣除；没有维修或灭火驱动时不会自行耗用，也不因此产生任何修复效果。后续驱动必须将实际效果和扣费放在同一个模拟候选事务内，并验证供电、人员、启动与控制条件。
- 设备/宿主损毁、船壳归零时取消未完成准备；同边界损毁优先于到期扣费。已存在但位于毁损设备中的余量保留、不可使用，本片不加入回收或销毁物资规则。货舱损毁只减容量，不删除库存或预留，超容时仍可完成已开始准备。
- 合法结算完成已经开始且设备/宿主仍存活、船壳未归零的准备批次，复用相同扣费路径；不新建准备，不消耗余量做额外维修。未来驱动必须先取消因运行条件失效的批次，再进入此资源结算。精确重试只读已有结果，不二次收费。
- 后台战前准备支持逐设备明确预准备，整舰队预览、准备费用及库存修订原子提交。支持新旧舰船混合准备；未选择设备默认保留原存量。界面将在工作循环接通后一起开放。

## 合同与技术值

资源定义使用 `gaotian.persistent-ship-resources/d1-v1`，包含已有填充容量来源及 `damage_controls`；实例使用 `gaotian.persistent-ship/d1-v1`。准备策略、草稿和结果也使用各自的 `d1-v1` 合同。旧版本的字段集合及默认入口不变。

设备定义包含 `module_id / capacity_units / preparation_steps / cargo_costs`，实例包含 `module_id / quantity_units / preparation`。准备过程保存剩余步数，身份由精确资源绑定确定；缺失设备、未知字段、版本混用、超容量、非整数数量、重复预留均拒绝。活动准备不得直接冒充已结算舰船进入新战斗。

当前[独立技术策略](./fixtures/d1-preparation-policy.v3.json)：每具设备容量 **100 点**，每次消耗 **2 份工程零件**准备 **300 步（5 秒）**。1 份零件占 1 m³、50 kg；与现有货物一样，消费不动态改变编译飞行质量。这些均为技术测试值，不是正式平衡数值。

内部每点采用 1000 个整数单位，便于后续按时间连续扣除，避免浮点误差污染货物/资源对账。资料中的库存单位与玩家显示点数需要按该比例转换。已有武器弹药仍采用原有资源点与发数口径。

## 事务与性能

复用 `InventorySession` 的候选复制、精确命令重试、共享预留与变化摘要；到期时间并入已有最近截止时间缓存。无设备/库存变化且尚未到期时仅前进时钟，不复制库存、不重编资源、不重新校验整舰。资源操作失败及外层模拟投影失败均不发布候选状态，不丢失原截止时间或扣费。

这不代表已完成持续维修热循环：每步实际维修的速率、资源分配、效果投影及候选更新将在 D1b/D1c 实施，不直接把通用全库存命令重复调用当作最终维修性能方案。
