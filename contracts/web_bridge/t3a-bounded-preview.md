# T3a 试航可见性与战术燃料修正（2026-09-08）

状态：`BOUNDED_PREVIEW_IMPLEMENTED / REALTIME_PERFORMANCE_PENDING`。按用户确认，战术推进不消耗燃料。此前暂停单步接线直接沿用了技术夹具的逐步耗油规则，属于产品接线偏差，本次纠正。

## 燃料与试航资源

战术燃料策略为 `gaotian.tactical-fuel/no-propulsion-burn/v1`。在战术资源编译边界生成独立目录、推进原型和舾装引用，把推进耗油率设为零，再走原运行时聚合、安全判定和物理积分。原始模块和战略用途的耗油率不变；不是在结果中补回燃料或只隐藏显示。资源清单包含策略及投影前后目录/舾装 SHA。燃料可用性、贮槽损坏等事实仍受原规则约束，不把“不逐步耗油”扩展成“任意故障下仍可推进”。

原两舰夹具质量约 222.7 万 kg，两台主机各 10 万 N，满推力加速度仅约 0.09 m/s²。新增独立样例策略 `gaotian.web-two-ship/visible-maneuver-trial/v1`：主机和转向机额定推力取原技术夹具的 50 倍，使用独立资源身份及前后 SHA，保留响应、安全上限和全部动态约束。该调参不应用于用户设计，不宣称正式舰艇平衡标定。X1a 接用户设计时沿用战术燃料策略，不能套用样例推力倍数。

## 按秒推进

新增 `tactical.advance`：params 恰为 `{scene_id, input, step_count}`，沿用 v1 输入的当前开边界语义，step_count 仅接受 60、300、600，对应 1、5、10 秒模拟时间。单步仍执行 1/60 秒。这是可中断的有限试航，不是连续实时调度，不改变物理步长。

接受时验证模式、边界、序号和蓝方直控权限，返回 `gaotian.tactical-bounded-advance/v1alpha1` 回执。权威工作线程在请求之间每次执行一个完整固定步，期间保持本次输入，每步重新仲裁并校验上下文。界面约每 150 ms 读取表现快照；不读取也继续推进。停止、模式切换和其他请求在每步之间处理，心跳仍独立。

新增 `tactical.pause`，params 恰为 `{scene_id}`。停止保留成功前缀；返回编辑器先在权威线程停止，再释放编辑权限。后台关闭会终止后台推进。新控制不得覆盖正在执行的试航，须停止后重新提交。

advance_state 包含输入序号、规范输入 SHA、起始步、请求步数、已完成步数、状态和错误。状态为 running / completed / stopped / failed。接受本身不消费物理步，完成第一步才消费输入序号。每步积分和候选投影成功后共同提交场景、指挥状态、输入回执和进度；异常留下成功前缀并暂停，不自动重试。

前端共同核对输入、时长和回执；丢确认时禁用操纵，通过回读消歧，不重发不明结果。运行中锁定操纵表单，保留停止按钮；完成后可调整车钟。选中红方仍只改变检查对象。
