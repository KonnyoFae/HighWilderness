### 当前限制与可复用能力

- 当前战前界面选择准备舰船，但没有敌我双方编组入口；准备部署将所选舰放入蓝方，再追加固定红方测试舰。后台 ST0 已有双方持久实例及身份/结果关联能力，可复用到新的双边配置流程。
- 当前新测试供给初始为 1,000 点弹药资源、每种货物 100 份、燃料 10,000 单位，使用后不自动补满。现有货物目录也不足以覆盖已规划的导弹动力、战斗部、导引头和电子对抗配方。
- 当前准备界面以逐舰长表单为主，战斗界面沿用早期舰况/火炮/损管骨架；新增导弹、火控、数据链与电子对抗需要重新组织整条操作流程。

核对入口：[准备界面](../../apps/desktop/src/tactical/PreparationPanel.tsx)、[准备部署](../../backend/high_wilderness_sidecar/prepared_deployment.py)、[测试供给](../../backend/high_wilderness_sidecar/preparation_service.py)。本段描述本次核对的当前代码，后续实现时更新。

### 已确认改造范围与设计方向

| 部分 | 必须支持的行为 | 界面与实现衔接 |
| --- | --- | --- |
| 双方舰队配置 | 同一场景可分别选择并配置敌我双方战舰，支持双方多舰及各自装备/库存组合，能设置测试初始交战距离 | 复用已保存设计/舰艇实例、准备事务和双方身份接口；不再由固定技术敌舰替代玩家配置的对手；实际双方旗舰间距取配置值，保留各队内部排布 |
| 战前准备重设计 | 共用准备画布，上方敌舰队/下方我舰队同时可见，分页只切编辑方；左侧加入舰船、右侧部件浮窗。导入栖装自动生成舰艇，加载中明确提示；点选模块自动进入火炮/导弹/设备/损管/货舱页 | 调整舰队排布并用于实际部署；油料、弹药库、损管、炮塔和发射器支持单部件及本舰全部同类补满；新增消耗工程材料的战前维修，见[准备画布设计](./tactical-preparation-canvas-design.md) |
| 战斗界面重设计 | 重新安排战场、舰队选择、目标/威胁、火控、火炮、导弹、损管、电子对抗及结果反馈 | 延续共用战场、按所选舰艇切面板、直控限旗舰；火控页按目标组织，导弹页按发射器组织，使用同一份分配状态；不能仅增加两个标签就视为重设计完成 |
| 测试物资扩充 | 大幅提高各类测试可用材料数量，并补齐导弹/干扰装备所需货物种类，让双方可反复测试组装、装填、换装和消耗 | 覆盖火箭/涡喷部件、高能炸药、高能燃料、雷达/红外部件、工程材料及现有弹药、损管和燃料供给；正式名称/单位与配方统一 |
| 场景与测试框架 | 场景配置驱动双方舰艇、装备、库存与部署，专项样本能复用同一配置入口 | 场景构建、准备预览、实际部署、结算身份及自动化夹具一起调整，避免只改前端名单而运行时仍追加固定敌舰 |

物资扩充针对可用测试供给，继续经过真实货舱/弹药库容量、配方、装填与消耗链路；测试补给初值与正式经济平衡分开配置。需覆盖已有测试存档的补给更新或显式重置路径，不能只提高新仓库初值而让旧测试环境仍缺料；不把打开页面或普通结果保存做成隐式补满。具体各类数量及便捷补给入口在实施时确定，当前不硬定统一倍数。

战前能配置敌方，不改变战中原有操控权限、感知/干扰规则或 AI 行为；测试配置已知的敌舰资料不能直接成为本舰实时火控数据。双方使用独立实例身份、库存与装填批次，保存战果不能串写；复用同一设计时也须对应独立参战实例。保留现有“放弃全部测试进度并清空缓存”的重启能力。

### 实施顺序与验收

本轮安排：先在工作包 5 前部接通双方场景配置、测试补给与战前准备重设计，再随导弹/火控/电子对抗能力逐步接入新的战斗界面，最后完成双方组合联调。工作包 7 保留最终规模与节奏打磨，不把基本可配置、可操作性全部推迟到该阶段。

- 通过实际界面为双方各配置多艘不同设计/装备的舰艇，入战数量、阵营、旗舰、装备与库存和预览一致，不混入未选择的固定技术敌舰。
- 在编队配置中更改初始交战距离，同一舰队分别进行近/远距离样本；实际双方旗舰间距与设置一致，编队内部相对位置/朝向保持，读取场景能恢复距离，非法值有提示。上下双方画面同时可见，屏幕分区不决定战场距离；调整测试距离不改变正式阈值或弹药/感知性能。
- 双方可用扩充后的材料完成导弹组装、整装/原料装填、战斗部切换及干扰装备准备；实际消耗、货仓容量、缺料提示和余量保存仍可核对。
- 新建与已有测试环境均能使用更新的测试补给方案；重试保存不重复扣料，普通读取/保存不自动补满。保留缺料/容量边界专项，不因默认物资充足而失去这些检查。
- 在战斗界面完成目标选择、火控锁定、炮组操作、导弹分配/地点发射、自动防御开关、干扰投放和损管；读到相应目标、在途分配、导引状态、余弹及不能执行原因，切页不触发额外发射。
- 样本覆盖双方导弹攻防、近防炮与拦截弹协同、传感器/数据链、云雨与干扰、导弹库殉爆，以及战后在途/VLS 转向中弹不返还；不以固定对手或单枚演示导弹代替组合验证。
- 保存双方战果、返回准备、重启再战及强制放弃测试进度后重新开场均可完成；独立测试目录继续避免自动化样本遗留结算堵住人工入口。

2026-09-16 准备页面布局已具体确认：共用画布内敌方在上、我方在下且同时显示，分页切换编辑方不隐藏另一方；左侧浮窗选择导入阵营，栖装加载时明确显示“正在加载”，成功后自动生成到对应方；右侧五页随模块点选自动跳转。油料/弹药库/损管/炮塔/发射器支持填充此部件与填充本舰全部同类，新增消耗工程材料的战前修理。详情、分类映射与事务边界见[准备画布设计](./tactical-preparation-canvas-design.md)。

新增验收覆盖双方上下视区同时可见、分页/点选/浮窗状态一致、加载与失败提示、导入期间换页不改归属、排布进入实际部署；单件与本舰同类补满不影响其他舰艇，已有余量只补缺额，满量不重复消费；维修真实扣工程材料并保存部件耐久，缺料/重试不能产生免费维修或重复费用。

待细化范围收窄为具体控件、甲板/缩放与排布坐标映射、同类分组、维修范围/成本/耗时、装填批次不足和缺料处理，以及测试补给数量和旧测试环境更新。双方布局、可调测试初始距离、模块点选/五页、加载提示、本舰同类补满和有偿战前维修均不再列为待定。 对应事项的最迟收敛阶段见 5a～5i 表，5a 不等待维修和导弹战斗参数全部明确。

## 范围与已有结论

当前已开发的全部内容均属于战术模式，包括舰艇编辑、战前准备、交战模拟与演出、损管及战后保存；战略模式尚未开始开发。ST0 是当前系统为未来调用提供的双方入战和结果关联接口，没有正式战略遭遇界面。

未来大部分战斗是中远距离交战，由战略模式操作与战术模式近距离模拟、演出两部分构成；玩家绝大部分游戏时间在战略模式经过。单场战术模式最大预期持续时长不超过 **15 分钟**，超过须整体调整游戏平衡，不新增强制超时结束机制。两小时测试需求彻底取消，不保留必测、可选、按需或恢复条件。依据：[总规划第二章](../../高天荒野游戏规划归档.md#二战略层与战术层的战斗关系)。

- O4 已由用户确认实际完成，不再重开三舰往返、四类安装和留档验收；编辑器只在新功能关联或出现可复现回归时定向检查。
- 本次结构预检已通过前端类型检查及 85 项测试、测试总入口自身 3 项测试；这是当时的结构预检记录，不代表后续入口可用性验收。
- OP1、ST0、武器、损管及资源各片已有专项和浏览器/桥接验证记录。已有通过结论保留；本清单中的实际操作复测用于确认当前组合体验，不能把“尚未本轮复测”写成“功能尚未实现”。
- E3c 已完成的 30 分钟后台测量仅为历史工程证据，不要求重跑，也不代表单场玩法目标。

## 一、第一优先：自建舰完整操作与战后返回

使用一条已保存且合法的自建设计，导入支持当前弹药、填充和损管策略的新测试实例。已存旧实例保留原策略，不通过重新导入旧请求免费升级或补满。测试存档使用独立目录，避免消耗或覆盖玩家现有资产。

| 步骤 | 核对内容 | 通过条件 |
| --- | --- | --- |
| 战前准备 | 选择舰船、装卸货物和燃料、预装弹药、准备损管；核对预览和保存 | 预览不扣费；缺料或超容明确拒绝；保存按实际配方扣有限物资，不部分提交或重复收费 |
| 实际入战 | 保存准备后进入交战，确认旗舰、船壳和模块布局 | 使用所选自建舰和当前保存状态；技术样例的推力倍率不施加给玩家设计 |
| 操纵与交战 | 推进、转向、制动、镜头/选中、暂停/继续；自动和手动火炮；敌舰还击 | 操作影响实际运动与炮向；弹药与命中战损可核对；模式切换不产生额外射击；暂停冻结战斗推进 |
| 结束与结算 | 自然结束或主动撤离后查看各舰战损、余量和变动原因 | 场景冻结；仅完成有效的已开始装填，消费计入结果，不另开新批次；目标和锁定不带到下一场 |
| 保存战后舰船状态 | 点击“保存全部战后结果” | 所有参战舰船状态一起保存；既有损伤、余弹、资源与未灭火情保留，不免费维修或补给 |
| OP1 返回入口 | 保存前后观察“管理战后库存与下一场准备” | 未保存当前结果时禁用；保存后返回自建舰准备列表；查看已保存的历史结算不能解锁当前未保存场景 |
| 重启与下一场 | 返回准备、重启后台、重新准备原舰并再次入战 | 原舰身份、战损与余量连续；旧准备回执不能替代当前修订；不误入技术测试舰重新部署流程 |

“保存战后舰船状态”指本地实例持久化。当前界面需要手动点击保存，本轮按这个已实现流程验收，不将其改成自动保存。它不表示战略奖励、地图占领或世界战果应用。

最小操作样本是同一舰船连续两场的 A→保存→重启→B 往返；无需每次重新做完整编辑器验收。现有准备入口仍使用技术测试敌舰，双方持久实例的验收另见第三部分。

## 二、结合上述交战验证已接入的新功能

分为几个明确样本，不要求一场同时触发所有机制。界面验证可见反馈与操作；概率、事务回滚及难以稳定触发的毁伤由已有专项测试核对。

| 功能组 | 本轮重点 | 边界 |
| --- | --- | --- |
| 普通炮、穿甲弹、燃烧弹 | 自动选舰/模块目标、手动转炮及射击；实际炮向/射界；下一批弹种选择；普通资源与特殊合金/高能燃料成本；真实命中、装甲和模块损伤 | 待发弹与在途弹不因选择下一批弹种变种；受阻原因清楚；降级火控通过专项复核，不要求玩家反复破坏雷达碰运气 |
| 概率甲板与模块偏好 | 炮组指定模块后观察偏好与实际命中；手动偏好可清除；记录区分战场层、舰内甲板与本发候选概率 | 指定甲板不保证命中；跨层模块均分加成；跨帧不重抽，真实飞到抽中甲板才结算；装甲、模块、燃料和防火填充均读取受击层 |
| 表面火灾与蔓延 | 新导入舰装填燃烧弹，未击穿引燃舰外；同甲板邻区传播；查看火点与损管当前扑救位置；保存未灭火情进入下一场 | 不跨甲板或直接由舰外传入舰内；子火不在出生步连锁传播，寿命不超过来源；一具设备同一时刻扑救一处，暂停和失败步不推进；旧型燃烧弹不误标为新效果 |
| 结构材料与逐层填充 | 设计保存、准备与入战信息一致；结构冗余影响最大船壳耐久；每层单一填充、净容量、货架容量、防火效果分别生效 | 不重开 O4；比较同条件样本。防火只降低新点燃概率，不以单次未起火宣称验证通过 |
| 损管、火灾与维修 | 旗舰设备启停、手动/自动目标、资源与零件、灭火优先、维修反馈、暂停及跨场保存 | 不自动重建已毁模块或独立填充燃料槽；普通弹、穿甲弹不承担燃烧弹的点燃验收 |
| 灵烷燃料 | 准备装卸、逐槽存量、推进和转向零油耗、真实槽损毁后的一次性损失及保存 | 普通掉血不漏油；不因无关船壳掉血按比例扣油；不同槽独立，不能用高能燃料货物代替灵烷 |
| 近防炮与弹体耐久 | 30 毫米炮组开关；不同速度/高度的来袭弹、多炮齐射、雷达失效、缺弹、落空补射、保存与下一场 | 只自动处理有耐久的预测撞舰威胁；三档排序，已足量在途时等待/转移；实际命中才扣耐久，归零无后续伤害；落空弹可伤敌舰、不误伤友舰 |
| 人员与岗位 | 舰况查看人员总数与逐模块配员；人员舱受击、内部火灾、殉爆后检查伤亡记录；保存并再次入战 | 负伤/阵亡分别记账、伤员退出可执勤；小数累积，按岗位优先级配员；人工功能降效/停机，自动化功能保留；无免费治疗或补员 |
| 货舱与资源 | 缺料、货舱损毁导致超容、余量和预留、重新准备及下一场 | 超容保留现有货物与预留，禁止新增装载，允许消费及保存；不删除货物伪装容量正确 |

新功能均已有范围内实现与证据。这里核对联合操作和状态延续，不要求把技术参数直接验收为正式平衡数值。

### 升力冗余、下坠与储罐紧急抢修（2d 已接通）

按[升力冗余专题](./tactical-lift-reserve-design.md)明确计时与抢修参数后验证，不用原 D1/H5c 通过记录代替：

| 场景 | 通过条件 |
| --- | --- |
| 设计、准备与战斗冗余 | 采用干重及实际可用升力；挂载/货物不影响冗余，相关界面含义一致，负数不截成零 |
| 下坠触发与分段 | 负冗余才新触发，零冗余不新触发；缺口越大计时越短，按实际完成时刻逐层切受击层，雨层保留末段抢修机会 |
| 已毁升力储罐紧急抢修成功 | 未毁储罐仍提供满升力；已毁升力储罐按确定的门槛、时间和资源完成紧急抢修，恢复正冗余立即停止下坠并保持当前层；按最新决定自动补满储油，备用燃料槽实际补充后续接入 |
| 抢修失败与最终坠毁 | 无资源、未完成或再次损毁按最终规则处理；雨层末段仍未恢复才产生一次坠毁结果，战损与资源可对账 |
| 指令、暂停和资格 | 取消主动换层不能消除负冗余风险；暂停冻结读条和维修；可抢救下坠不提前永久剥夺旗舰控制、冻结胜负或生成残骸 |
| 战后连续性与零点边界 | 维修结果与消费真实保存；半途修复到恰好零冗余、仍在下坠时结束战斗等边界按专题最终规则验证，不自行按旧即时坠毁逻辑判定 |

这里的紧急抢修只针对提供升力的储罐，普通已毁模块及无升力的独立填充储油单元不因本规则自动获得重建能力。

## 四、交战节奏与运行体验

在上述功能场景中同时记录首个有效命中、结束/撤离时刻、操纵与暂停响应、明显卡顿，以及进入/退出后场景资源是否释放。记录实际推进的战斗时长；人工暂停、设置准备和菜单停留单列，避免混淆耗时来源。

15 分钟是单场最大预期，不是要求每场必须跑满 15 分钟，也不以测试人员提前撤离替代自然交战节奏验收。若代表性样本持续无法自然结束且越过目标，记录舰船配置、距离、弹药及行为，整体复核射程、命中、火力、防护、机动与结束/脱离规则。卡死或无法执行合法操作另外记为功能问题。

目前仍有技术数值，短样本可发现明显不符合目标的设计，但不能据一两场宣布全游戏正式平衡完成。未来中远距离完整链路依赖尚未开发的战略模式，本轮只能验证已有近距离模拟与演出。
