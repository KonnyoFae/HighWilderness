## 1. 要回答的问题与成功范围

探索假设：设计在进入战术前严格编译和验证，战术循环持有只读资源与独立动态状态；未变数据复用派生结果，事件使依赖失效，持续过程按固定步或精确到期时间推进。这样能减少重复证明的成本，并为武器、毁伤提供统一的状态更新基础。

需要用实验回答：

1. 固定贡献汇总、事件更新和紧凑飞行内核能否满足两舰 60 Hz 并留出战斗余量？
2. 变化标记能否可靠覆盖伤害、修复、供电、人员、宿主与时序变化，而不是依靠每步全量哈希兜底？
3. 新政策的增量结果能否与独立全量求和一致，未变领域能否共享规则，保存续跑是否确定？取消配平与血量直接缩放的预期差异是否单独记录？
4. 连续运行、慢界面、输入突发、暂停和保存是否保持队列有界、状态自洽？
5. 普通弹交战加入后，成本是否主要来自必要计算，剩余热点是否值得迁入本地模块？

两舰飞行原型通过只意味着路线可继续，不等于 T4a 完整交战、X1a 玩家设计出航或 6/20/30 舰性能验收通过。

## 2. 保留、共享与新建的边界

| 部分 | 处理方式 | 边界 |
| --- | --- | --- |
| 舰体/舾装编辑器、草稿、撤销、资源保存 | 保留当前框架 | 不因实验改写编辑文件或放宽设计合法性 |
| 设计与规则资源合同 | 共享 | 设计通过后才能编译出航；来源版本和内容身份可追溯 |
| 战术推进 | 新建具名固定贡献政策 | 不做配平，血量不直接缩放推力；旧推进保留为历史参考，不伪装成结果等价优化 |
| 装甲、弹药、毁伤、权限及未变机动/安全规则 | 提取并共享现有计算函数 | 未获准改变的规则不随推进简化删除 |
| 战术资源编译器 | 新建或整合现有准备入口 | 输出只读资源包、稳定索引、依赖图、初始动态状态和编译报告 |
| 战术会话、动态状态、循环与缓存 | 建立实验路径 | 单一权威所有者、候选提交、分类版本、可靠回执、有界队列 |
| Rust 桥、现有画布 | 先复用 | 新内部状态通过投影适配输出；必要协议变化显式版本化 |
| 旧战术严格路径 | 作为对照和开发回退保留 | 不默认在正式每步额外跑一遍，也不在故障时无声切换 |

第一轮继续使用 Python，目的是验证执行模型收益。通用 ECS、全量 Rust 重写、多进程舰队分片、多速率物理和降低 60 Hz 不作为实验前置条件。只有测量证明剩余热点需要时，才选择其中具体方案另开切片。

实验按场景创建时显式选择后端；一个场景只能有一个权威执行器。对照工具使用两个彼此隔离的世界副本，不能共享可写状态或让双引擎同时驱动同一 UI 场景。

## 3. “无变化不重复验证”的具体含义

### 3.1 数据分域与触发关系

| 数据域 | 典型内容 | 更新/验证触发 | 可复用内容 |
| --- | --- | --- | --- |
| 设计资源 | 船壳、甲板连接、安装关系、装甲边最大值、原型 | 场景创建、读档重建、具名设计转换 | 合法性证明、几何索引、额定参数与响应表 |
| 设备功能 | 独立耐久通道、工作模式、宿主、供电、人员 | 命中、事故、修复、配置指令及相关依赖变化 | 设备可用性和各方向贡献总量；推进不逐步扫描血量 |
| 质量与结构 | 质量、惯量、质心、有效承载状态 | 现有规则规定的弹药/载荷/结构变化 | 静态承载模型、未变部分的质量贡献 |
| 运动与安全 | 位置、速度、角速度、姿态、当前载荷 | 每步积分及相关能力变化 | 不依赖当前运动的静态系数；动态安全不可因无命令而跳过 |
| 武器与库存 | 弹药、装填、射击序列、火控条件 | 发射、补装、到期事件、目标/设备条件变化 | 武器索引、兼容弹药表、未变库存派生结果 |
| 持续过程 | 燃烧、损管、修复、响应阶段、制导 | 活跃过程每步演进或精确到期唤醒 | 静态参数；没有新外部事件不代表过程停止 |
| 指挥与生命周期 | CIC、遥控宿主、权限、退出状态 | 人员/设备/命令/位置条件变化与步骤边界 | 未变角色关系；执行命令时仍检查当前权限 |

依赖图至少支持“受损发电机→关联设备→有效推力/火控”“宿主→附属模块”“单台发动机失效→对应方向贡献差量”“弹药变化→现有规则要求的质量/运行状态”。不传播到配平组，不将发动机受损直接等同于模块质量消失。

所有写入经受控入口，同时产生领域事件、更新版本号并标记受影响派生结果。嵌套资源不能保留外部可写别名；版本号由后台生成，客户端不能提交 trusted 标记。每个缓存声明依赖域，区分步首、命令后、积分后、毁伤后和已提交边界；不能只按步号命中。

原型先用类型化不可变状态和写时复制，避免失败后整世界回滚。未经登记的写入应在开发检查中暴露；测试模式可强制全量重算与缓存路径对照，正常循环不靠全量指纹探测变化。

### 3.2 仍需执行的检查

外部输入、创建和读档继续严格校验。每步检查实际用到的时序、权限、数值有限性、安全与互锁；发生库存/耐久等变化时检查相应新状态。合法设计在战斗中损毁后不重新套用编辑器的完整安装合法性，但需要更新运行可用性。

固定资源非法、状态来源不明、版本不支持时显式拒绝。不能通过“缺失数据默认不变”接纳无法证明来源的状态。

### 3.3 必须保持的游戏语义

保留现有 1/60 秒步长、精确响应时间及舍入、换向互锁、非配平类软硬安全、I9 权限、确定性事件顺序和战术推进不耗油。试航推力倍率只用于具名样例。保留安全条件的接线以 E1c 的逐项映射清单验收，不为复用旧包装而恢复配平。

新政策预编译各方向固定贡献及完好基准；部分掉血本身不减推力，失效扣除贡献，恢复加回可用能力并经过启动/响应。转向固定等效力矩在编译时确定，不计算实时配平，不产生推进偏置转向或转向残余平移。旧半耐久 75% 曲线仍属于旧规则证据。损毁不清除已获得的速度/角速度；步首损毁与步内命中保持现有生效边界，不追溯撤销已积分运动。

## 5. 正确性验证矩阵

| 编号 | 场景 | 检查内容 |
| --- | --- | --- |
| V01 | 稳定飞行、空命令、重复车钟、左右转与制动 | 与新政策独立参考的力/力矩、运动、安全结果一致；静态资源不重验；必要运动计算仍执行 |
| V02 | 启动、2% 阶段、反转、到期前后改令 | 阶段、起点、到期步、互锁与事件顺序一致，未到期不能早执行 |
| V03 | 缓存命中后部分掉血/全毁、多额定推力与偏置安装 | 部分掉血不直接减推力；全毁按固定贡献扣除；不配平、不额外偏航，推进/左右转独立；无幽灵推力 |
| V04 | 发电机、CIC、宿主、人员状态变化，随后修复恢复 | 依赖向关联设备扩散，权限失效及时；无关缓存不全量重建；恢复不瞬间满输出 |
| V05 | 无新指令但持续燃烧、修复、装填、响应计时活跃 | 到期和持续过程仍运行，不能用“无新事件”跳过；相关未接功能到 E4 补齐 |
| V06 | 同一步命令、命中与故障；步首/步末分别损毁 | 依照旧步骤顺序提交，不重排因果；同一步不同阶段不误用缓存 |
| V07 | 外部别名修改、过期资源引用、陈旧缓存与漏标记故障注入 | 资源隔离/拒绝成立；强制重算工具能检出人为漏失效；错误不能污染已提交状态 |
| V08 | 候选计算中途抛错、回执丢失、重复/过期/越权输入 | 世界/步号/事件/回执一起提交或都不提交；不重复执行，未知结果明确查询 |
| V09 | 暂停恢复、切回编辑、断连、输入洪峰和慢消费者 | 不带入积压转向；编辑草稿不丢；队列有界；可靠事件不被快照合并丢弃 |
| V10 | 保存后连续运行与重载后相同输入续跑 | 动态状态、下一到期事件和必要随机状态一致；内部缓存/token 不持久化 |
| V11 | 普通弹合法发射、被遮挡拒射、命中装甲/部件、燃烧及殉爆 | 武器与毁伤端到端结果及权限条件一致；用真实命中补足 E2 人工注入证据 |

E0 固定比较字段：全部影响后续演化的动态状态、指挥状态、发动机阶段/排程/安全状态、力和力矩、库存、装甲与部件耐久，以及有序领域事件和命令执行事实。未迁移域在报告中列为 NOT_COVERED。

E0/E1a/E1b 的旧规则完整对照及黄金原样保留。E1c 起冻结新政策版本、独立资源/输入和期望，增量能力与独立全量求和逐步精确一致；与旧路径只在未变规则且前提相同的场景比较，配平/耐久衰减及其下游运动差异单独记录。新规则不能冒充旧 v7 审计或存档；兼容旧导出仍须保留原规范内容与 SHA，不兼容则版本化拒绝。不能通过删字段或改旧黄金让实验通过。数值实现若改变，另立误差预算，离散状态、事件与时序仍需精确一致。

对照在独立运行中进行：短序列逐步全量比较，较长确定性重放用分段检查点及事件流定位，发现差异缩小到首个分歧步。全量比较、规范哈希和强制重算不计入生产性能，也不与被测内核竞争资源。

旧测试受历史实例指纹阻塞时保留原状态；用当前合法资源新建对照案例，但不能据此宣称历史全量回归通过。

## 6. 性能与长期运行验证

### 6.1 基线与测量方法

已有短测约 47.18 ms/步，两项局部实验合计约省 19.7%；它们是当前两舰无交火负载的证据，不是新框架预测，也不与历史其他舰数成绩混比。E0 在锁定工作树、机器和资源后复测基线。

记录源码提交及未提交补丁身份、资源/输入 SHA、运行时版本、CPU/电源模式、调试或发布模式、随机种子（若使用）、活跃部件/弹丸/事故数。后台原始计算、快照、IPC/界面和保存分别计时；cProfile 等画像与无分析器性能运行分开。

测量分三档：

- 快速方向判断：固定 12 步预热、60 步输入带，与已有诊断口径对比，至少三次交替运行新旧路径；只用于选择热点。
- 吞吐门：10 秒模拟预热后测量 60 秒模拟（3600 步），至少三次独立运行，记录每次和最差重复；无墙钟节流，测出真实计算余量。
- 调度与战斗衔接：保留已完成的 E3c 30 分钟工程证据，取消固定 2 小时迁移前置及以超长单场战斗作为常规目标。E4 使用代表性小规模交战与必要短测，P3 使用多场进入/结算/退出检查状态延续、保存延迟和资源释放；具体场次数与负载在各片开始前冻结。长期驻留、持续增长或容量异常需要时再跑专项压力测试。人工补给/重建仅能用于具名压力夹具，不进入玩家默认规则。

长期内存按固定墙钟窗口采样进程 RSS、存活对象/缓存条目、事件及回执保留量、队列峰值。预热及达到保留窗口后应趋于平台；持续增长必须解释并修复。不能仅比较起止内存或用短样本断言无泄漏。E0 固定为每秒采样、每分钟汇总，区分预热/保留窗口填充/稳态；具体资源预算和斜率判定门槛在 E1 状态尺寸与 E3 保留窗口确定后、长跑开始前冻结，避免预设不存在的内核容量；后续调整须保留旧口径及原因。

### 6.2 待验证的工程门槛

以下是完整路线目标；阶段范围内已有通过结果见上方最新报告，未覆盖门槛继续保留：

| 指标 | 目标/判定 |
| --- | --- |
| 固定步预算 | 两舰代表性负载平均 < 16.67 ms，P95 ≤ 12 ms、P99 ≤ 16.67 ms 作为迁移余量目标；记录最大值及超时比例，不能只报最快重复 |
| 无节流吞吐 | 实时因子 = 模拟秒 / 实际计算墙钟秒，至少 ≥ 1.0；结合上述分位数判断，不能用平均速度掩盖尾部阻塞 |
| 60 Hz 调度 | 排除显式暂停后的累计模拟落后量有界且不持续上升；正常运行不触发过载保护、不丢权威步。节流后比值约为 1，不能拿它代替吞吐余量 |
| 操作响应 | 参考本机端到端输入生效 P95 ≤ 100 ms、暂停确认 P95 ≤ 100 ms / 最大 ≤ 250 ms 作为首轮目标；计入约定未来步窗口，记录 UI 和后台各段延迟 |
| 循环机制 | 静态构造完整验证/静态 SHA 重算/静态响应解析/内部 JSON 解码/自生成步骤完整重放在正常热循环均为 0；边界导出另计 |
| 局部更新 | 稳定飞行不重建设备有效能力；受损后仅更新受影响依赖闭包；活跃计时、动态安全检查仍有调用证据 |
| 队列与内存 | 容量和保留策略有明确上限，无累计历史世界引用链；慢消费者下执行已定义背压策略，不能无限分配 |

机制计数与性能采样分开运行，避免计数器本身改变结论。阶段性能门只适用于该阶段已覆盖规则；E1 飞行通过不能替代 E4 交战通过。

## 7. 调度、保存与故障恢复探索

E3 先冻结新版本输入合同：场景身份、输入序号、有界未来步窗口，接受/执行/取消的可查询回执。旧当前步输入语义保持。入队不等于生效；失去权限、暂停和模式退出按合同处理待执行输入。

模拟采用单调时钟、固定 60 Hz、有限追赶批次和请求处理预算。调度器负责编排到期任务，不能改变既有步内规则顺序。快照以约 10—20 Hz 发布，UI 插值；快速、慢速和暂停渲染不得改变同输入带的权威结果。

过载时不丢步、不扩大 dt，超过有界欠账阈值显式暂停；E3 冻结批次、队列容量和欠账阈值并测试。可靠事件输出背压时步间暂停，可替换快照允许覆盖旧帧。恢复应能查询最后提交步和已执行输入。

原型初期沿用当前“表现投影失败则本步不提交”。若 E3 将投影移出提交链，需在实验协议中明确：模拟已经提交，投影失败只影响显示并从已提交状态重建；验证回执可消歧后才接入 UI，禁止静默改变后自动重发输入。

保存捕获一个已提交边界，不夹杂前后步。原型先验证暂停保存/加载；运行中保存另测冻结快照及后台序列化，不阻塞固定步。新内部格式若不能无损导出旧存档，使用具名版本和显式转换；未覆盖字段拒绝转换。读档重新验证资源、重建依赖和到期队列，不恢复内存地址或缓存证明。

## 8. 继续、调整、停止与迁移条件

| 实验结果 | 决策 |
| --- | --- |
| 一致性、失效机制、性能和长跑均通过 | 进入下一阶段；E4 完成后才评审默认战术路径切换 |
| 一致性通过且重复工作已消除，但吞吐仍不足 | 对剩余热点做一次有明确范围的画像与修正，再测；必要时探索数组/批量或局部 Rust，保留同一正确性门 |
| 性能快但战损、时序、权限或续跑不一致 | 不迁移，定位首个分歧并修复；不能以速度换规则缺失 |
| 缓存依赖难以可靠维护或大量更新都使全舰失效 | 收缩缓存范围、明确所有权，允许局部保守重算；必要时保留现有严格路径并重新评估设计 |
| 实验收益不足以抵偿复杂度 | 停止扩大新框架，将已验证可独立复用的编译/计算优化回接旧路径，留下失败与收益证据 |

每阶段报告必须有明确 `PASS / FAIL / NOT_COVERED`、瓶颈和下一切片，避免以“继续优化”无限扩张。默认切换还需产品所需规则覆盖清单、保存兼容、编辑回归及用户可操作的联调证据；原型未覆盖功能不能随切换消失。

回退以关闭实验场景、重新创建旧路径场景，或加载明确兼容的已保存边界进行。禁止在运行中无声换引擎；实验版本存档不能保证旧路径可读时，应明确阻止回退载入。保留切换前资源和存档，不覆盖升级原件。

迁移完成后旧战术路径可逐步缩为合同验证/离线历史参考入口；编辑框架继续维护。未变领域共享规则，新战术推进使用显式政策版本，不长期扩建两个完整战斗系统。

## 9. 证据与计划衔接

实施时建议在 `artifacts/t3a-realtime-experiment/<run-id>/` 保存 manifest、覆盖表、首个差异、逐阶段计数、原始时间样本、资源曲线、输入/事件轨迹及决策报告。本次不生成空的 PASS 文件。短测、长跑、原生 UI 和历史回归证据分别标识。

旧架构 R1（静态编译）、R2（类型化计算）、R3（来源/审计分离）作为 E1/E2 所用技术手段，不再以完成现有热循环全部改造为新原型前置；R4 对应 E3，R5 由实验决策触发。

当前顺序为：已完成 E0—E3 范围内验证 → `P1 最小状态合同 → P2a 可操作武器 → P2b 实际命中毁伤 → P3 战后保存及多场衔接 → 产品接线/迁移评审`。跨战斗实例保存提前，X1a 玩家设计入口和 E5 产品工作流继续依赖对应规则覆盖。这仍是服务战略模式的基础设施路线。O4 规范实机留档保持非阻塞收尾；填充材料扩展、美术与高级控制、大规模 T0 矩阵继续后移。

本路线扩大了此前原地优化的验证范围，旧 10—18 开发日估算不直接套用为整套新框架工期。E0 明确规则抽取范围、E1 获得收益后，再按剩余阶段重新估算。
