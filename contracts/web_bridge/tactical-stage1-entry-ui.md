# 战术首版工作包 1：独立入口、界面骨架与升力冗余

日期：2026-09-15。状态：基础流程已实现并完成本页所列验证。用户确认采用共用战场、按所选舰艇切换面板的方案；唯一直控旗舰保留，其余舰艇的正式 RTS 命令在后续工作包接入。

## 启动与操作

双击根目录 [启动战术模式.cmd](../../启动战术模式.cmd)。启动器复用桌面构建检查，使用 `--tactical` 打开独立战术入口；[舰艇编辑器入口](../../启动舰艇编辑器.cmd)继续使用 `--editors`。

1. 在战前准备导入已保存的合法舾装，选择参战舰艇并管理库存、预装弹药和损管准备。
2. 核对资源、保存准备，以当前所选舰为旗舰进入交战。沿用实际设计和已保存实例。
3. 战场上方选择舰艇；右侧切换舰况、火炮与损管。旗舰操纵位于画布下方，选择其他舰艇不会移交直控权。当前火炮、损管操作仍限旗舰。
4. 通过“结束本场交战”进入现有结算，保存全部战果后返回准备。该按钮是阶段内技术结束方式；正式按距离撤离尚未接入。
5. 已结束但未保存的战果在重启后由准备入口恢复；先保存待处理结果，再继续准备。场景切换、入战和保存回执丢失均可按同一次请求恢复。
6. 需要放弃现有测试时，使用顶部“清空战术测试数据”，确认后清空战术进度并重新准备；设计文件与编辑器草稿保留。多份待保存结算的切换及保存回执衔接已修复，见[清空功能与修复记录](./tactical-test-reset.md)。

火情、全舰燃料和命中记录折叠在战场下方。画布操作说明可展开，侧栏在较小窗口中独立滚动。当前布局是后续三层、武器组、舰队命令和抢修的基础，不作为完整首版界面验收。

## 升力冗余的数据含义

设计、准备和交战共用后台投影：`(当前可用升力 − 干重 × g) / (干重 × g)`。干重取已编译设计的船壳与已装模块质量，不加入货物、额外挂载或战中载荷变化，也不随模块损毁减少。

- 编辑器采用合法设计预览；草稿非法时继续明确标注最近合法预览的修订，不将旧数值冒充当前草稿结果。
- 准备页用已保存的模块耐久、模式、供电、人员和宿主状态，沿用实际入战的升力功能求值链。
- 战斗快照使用场景绑定的设计干重和运行时已计算的可用升力；发布时只派生读数，不在固定步内重新编译设计。
- 正、零、负值分别显示余量、恰好悬浮、升力不足。极小负值仍保留负号，不能显示成安全的零值。储罐剩余 1% 耐久仍为满升力，完全损毁才损失该罐升力。

只读字段新增于编辑器派生预览、准备信息和战场快照，不写入舰船持久实例，也不修改资源指纹。历史设计及舰船保存格式沿用原版本。

**本阶段没有接入强制下坠读条、储罐紧急抢修或新的升力失能判定。** 当前运行时仍沿用旧失能语义；工作包 2d 必须将其替换为可抢救的下坠流程，不能把本页的负值显示当作该循环已经实现。
