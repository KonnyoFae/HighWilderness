# P2 混合战斗负荷归因与优化方案

日期：2026-10-15；实施状态更新至 2026-10-17。P2.0 归因、[原始证据及校验](../../artifacts/tactical-p2-attribution-20261015/README.md)已随 `05247c1` 提交推送，其生产基线为 `7f02db4`（P1c）。P2a.1a 轻量战局目标名册与生命周期接入已完成本片范围，115 项测试及六场完整对照通过，代码、规划与验证证据随本次提交归档。**下一片为 P2a.1b：侦测读取接入名册与候选筛选**，随后为灰色未发现目标 UI 和联合验收，详见[目标名册实施计划](./tactical-target-roster-plan.md)。当前仍使用原侦测入口，本片不申报性能收益。

主要结论：混合战斗增加了导弹接触检查与威胁预测、航空探测/回收和共享航迹处理。预测缓存已经消除了大量同阶段重复请求；低跨步复用多数来自新观测和真实运动变化。优先消除重复构建和重复资源试算，再处理更难保证等价的预测几何、状态复制。不能用扩大缓存或降低决策频率替代原因分析。

## 1. 当前版本测量范围与性能边界

原 7b 纯炮/混合 9 对 9 各完整推进 900 步，并在 1～60、601～660 步采集调用分析。混合另做一次 900 步失效分类、两次无分析器串行计时。所有运行逐步匹配原摘要；分类运行逐步匹配 P1c 的 18 类扩展摘要，两次计时末态也一致。没有减少飞机、导弹、航迹、人员或作业负载。

第 660 步混合场景为 18 舰、71 弹体（46 导弹）、6 架空中飞机、12 个飞机传感器、2 个航空干扰源、513 条共享航迹；纯炮同为 18 舰，有 127 弹体、162 条共享航迹。航空干扰源不包括实体箔条/热烟。**纯炮同样保留雷达、火控、数据链与箔条的用途，不能据场景名称跳过电子战。**

两次无分析器计时均为当前版本，不是新旧对照。单位除注明外为现实毫秒。

约 86.6%～86.8% 的本次离线服务调用时间花在模拟步进，其余在发布与读取。CPU 用时接近这些调用的墙钟用时，当前采样更支持计算负荷是主因，不支持将主要耗时归于等待 I/O。进程 CPU 计时有分辨率限制，短窗口不逐步作精确推断。

后段平均单步约 46 ms，是 60 Hz 的 16.67 ms 预算的约 2.8 倍，且还要留发布、读取与输入空间。本轮不按墙钟调度，没有浏览器/原生窗口参与，也没有重做自动速度控制器的服务验收。

本次绝对时间明显低于 P1c 的前日独立运行，但生产代码完全相同。只能说明不同采集时段的绝对时间不可直接比较；不能将其申报为 P2 提速、否认前日回退，或断言历史回退由某个外部进程导致。P1c 的独立混合三组 +2.46%/+6.40%/+9.22% 和单组自动服务约 +19.7% 继续保留为未解决限制。后续每个候选仍需同场串行交替配对与真实服务复测。

## 2. 主要耗时入口

以下来自混合 601～660 步的调用分析。分母为分析器记录的步进入口累计 7.407 秒，只用于定位；分析器开销明显，不是上表的正常运行时间。表内列顶层阶段；下文的预测、几何、复制和目录读取属于其子调用，不能再相加。

| 阶段 | 60 步累计分析耗时 | 入口占比 | 主要原因 |
| --- | ---: | ---: | --- |
| 导弹准备与制导 | 1.692 秒 | 22.8% | 2,784 次导弹更新、46,429 次接触判断；还包含部分威胁预测、预留和电子遮挡 |
| 舰艇观测 | 1.225 秒 | 16.5% | 61,650 次传感器可见性检查；保留观测来源、目标特征和区域遮挡 |
| 航空飞行/探测/返航 | 0.880 秒 | 11.9% | 飞机运动与探测、状态复制及逐舰接收试算 |
| 实际碰撞与毁伤 | 0.724 秒 | 9.8% | 已含 P1c；实际扫掠与空中拦截仍执行 |
| 防空观测和威胁表 | 0.542 秒 | 7.3% | 合法观测样本、预测共享及防御候选 |
| 航空武器 | 0.348 秒 | 4.7% | 合法情报合并、目标筛选和写入前复制 |
| 舰艇制导环境构建 | 0.256 秒 | 3.5% | 共享航迹遍历、合法来源检查和链路测量构造 |
| 航空电子场刷新 | 0.218 秒 | 2.9% | 更新移动干扰区与重新检查已有探测渠道 |

纯炮晚段碰撞累计 0.842 秒，反而高于混合的 0.724 秒，但混合全步负荷更重；这支持按传感器、共享航迹、制导/预测候选和飞机回收共同衡量负荷，而不是只数弹体。

几个明确的重复入口：

1. `tactical_observation.targets` 在三个阶段各调用 60 次，总 180 次 / 0.336 秒。舰艇和弹体部分可能相同；飞机目标会在运动、换层、回收、受击后变化。只考虑复用已证明输入一致的部分，不能拿同一步号复用整份目标/观测结果。
2. `ElectronicWarfare.environment` 60 次构建遍历 534,438 条航迹项，最后建立 21,816 条链路测量。代码按每艘接收舰反复扫整张航迹表。可按观察舰分组，再保留逐来源合法性；导弹链路还可按阵营和目标身份建索引，逐弹距离、新鲜度和稳定择优保持不变。
3. `can_receive` 2,304 次 / 0.446 秒；每步不同接收舰计数累计仅 1,080。整个 900 步为 22,257 次 / 11,817 个逐步接收舰身份，全部返回可接收。重复身份不是安全缓存命中：同一步仍可能回收、卸弹、完工或毁伤。当前 `eligible=list(candidates(...))` 还会先试算全部候选，之后才找可用拦阻索，可另评估按原顺序按需查询。
4. `aviation_catalog.model` 9,169 次 / 0.297 秒，每次通过 JSON 编解码返回独立机型数据。`quarters_available` 2,546 次 / 0.286 秒，包括人员舱分配。静态型号/舱室描述与动态空位需要分开；这些时间与返航等上层入口重叠。
5. 全部递归 `deepcopy` 为 991,561 次，最外层调用为 1,220 次，不能描述成近百万次完整舰队复制。航空飞行和武器规划主复制各 60 次，分别约 0.150 / 0.156 秒；任务、冷却、发射随机状态和联系人嵌套对象的隔离仍是回滚正确性的要求。
6. `blocked_channels` 95,046 次 / 0.603 秒，其下圆形区域求交 619,505 次 / 0.362 秒。遮挡广泛服务舰艇观测、导弹接触和飞机探测。进一步优化可评估层/阵营/干扰类别索引与保守几何筛选，不改变实体箔条双向、航空电子区仅影响敌方，以及正在干扰的辐射源豁免规则。

## 3. 预测复用到底在哪里失效

`Plan.collisions` 晚段请求 **9,586 次**：同阶段共享 **6,067 次（63.3%）**，跨步沿用 **367 次（3.8%）**，重新计算 **3,152 次（32.9%）**。整个 900 步为 91,697 请求、60,225 同阶段共享、3,597 跨步沿用、27,875 重算。

| 晚段重算主分类（互斥） | 次数 | 含义 |
| --- | ---: | --- |
| 上一阶段有同身份，但完整样本键变化 | 2,300 | 2,300 次时间戳/位置变化，其中 2,298 次速度变化 |
| 上一阶段存在相同完整键，但不能继续沿用 | 846 | 下述运动、到期或已过接触条件触发 |
| 上一阶段没有该身份 | 6 | 新出现或重新进入请求集，不等于总共只新发射 6 枚 |

846 次相同键重算中，舰艇运动失效标记为 792 次，到期标记为 139 次；标记可同时出现。792 次全部涉及速度及非线性位置变化。现有缓存把同阵营整组舰艇运动纳入有效性检查，不能将这些失效自动视作冗余。导弹自身的拦截预留另在准备阶段维护，不属于预测键；此次另外观察到 265 次已缓存目标预留失效，也不能归到预测缓存里。

3,152 次重算有 2,186 次由导引接触的威胁判定触发，966 次由防空观测触发。判断负荷需要追踪调用来源，不能把预测全部算到防空炮上。

路径锚点复用为零：3,146 次输入不属于阻力轨迹，另 6 次没有旧锚点；数值采样路径点为零。**此样本的重点不是扩大阻力轨迹缓存或减少曲线采样。** 当前精确几何仍有 12,156 次预测舰体路径检查，另有 16,212 个宽阶段排除；适合后续从候选/几何工作量着手，保持预测精度。

全程基础 `trajectory` LRU 为 443,903 命中 / 21,923 未命中（约 95.3% 命中）；导弹实际分段 LRU 为 46,833 / 51,008。容量达到 256 不代表本来可复用的项目发生了有害驱逐，可能只是新运动状态；尚无依据直接扩大缓存。上述计数在两次无包装运行中完全相同。

## 4. 建议实施顺序

每个候选独立落地、测量和决定保留；后台计算按现有玩法做等价优化。2026-10-17 增加的目标列表 UI 按用户要求公开非本方目标名称/类别和存在信息，未发现目标灰色显示，其余动态情报及火控资格仍按观测规则；这项展示变更单独验收。本表为计划，尚未实现，不承诺固定收益，也不预计单靠一项就能达到 1×。

| 顺序 | 具体内容 | 工作量 / 风险 | 首个验证重点 |
| --- | --- | --- | --- |
| **P2a.1a 已完成，下一片 1b** | 轻量战局名册与生命周期已接入；后续依次为按阵营/层筛选并访问实体 → 战术目标列表 → 联合验收，见[分片计划](./tactical-target-roster-plan.md) | 中 / 中 | 名称/阵营/层/类别按变化更新，实时状态与观测样本分离；同一步候选隔离；灰色条目不获得位置或火控资格；后台和 UI 成本分别计量 |
| P2a.2 | 航迹按观察舰组织，链路测量按阵营/目标组织，减少全表扫描 | 中 / 中 | 保持原顺序、同刻来源择优、数据链距离/年龄、来源设备禁用/毁伤和跨层导引；不缓存最终锁定 |
| P2b.1 | 编译只读机型/货舱体积/舱室静态摘要，保留对外可编辑数据的独立副本 | 小～中 / 中 | 版本键、不同舰配置隔离；共享目录不能被作业或测试调用者修改 |
| P2b.2 | 同一接收状态复用货舱/人员空位摘要；另测候选按需枚举 | 中 / 中～高 | 回收、卸弹、完工、预留、人员住房/伤亡、设备与舰体状态改变后立即刷新；无容量丢弃与有容量无拦阻索等待不能混淆 |
| P2c.1 | 重测预测宽阶段候选和实际几何，必要时拆分每舰结果与汇总 | 中～大 / 高 | 新观测、加速、旋转、换层、存活集合、近距与已过接触、负预测守护窗口；不能跳过真实变化 |
| P2c.2 | 明确航空可变数据所有权，再减少飞行/武器规划重复深复制 | 中～大 / 高 | 冷却、任务、发射随机状态、联系人及失败回滚深层隔离；只读样本也须审计嵌套成员 |

P2a 与 P2b 先降低数据整理开销；再用新热点决定是否推进 P2c，不要求一次完成所有条目。预测几何方向不自动恢复 7c.3 已撤下、没有稳定收益的扫掠列表试验。跨步延长预测期限、降低飞机/导弹决策频率、降低物理频率均不纳入当前等价优化。

空间候选索引、分批数值运算或独立执行线程保留为后续选项：先测真实排除率和数据转移成本。发布与命令交付继续归 P3；本次发布/读取仍有约 13% 的服务调用成本，不能因此忽略，但不混进 P2 算法收益。整体降速控制保留用于超预算持续运行，不能替代计算优化。

## 5. 下一片的验收与沟通边界

1. P2a.1a 已从 `05247c1` 冻结原参考方法，接入轻量名册与候选改动提交，并完成生命周期和旧输出对照。P2a.1b 接续替换侦测读取，逐一绑定各消费阶段的实际实体；跨阶段输入不同则重新解析，不以同一步号兜底。名册维护成本计入整步测量，不仅统计目标构建减少量。
2. 保留 P1a 主动箔条、P1b 候选隔离、P1c 碰撞边界专项。按原六场各 900 步、18 类权威状态及旧公开字段对照，新增名册摘要单独验契约；覆盖失败原子性、出生/过期/拦截、舰艇毁伤/离场、飞机运动/换层/回收再出动、同一步新电子场、灰色目标展示与观察舰切换。
3. 正式前后计时至少三组串行交替，运行前确认本任务没有其他分析进程；清物理缓存，关闭分析器、诊断计数和录制。分别记录单步分布、进程 CPU、发布/读编码及同输入负载，保留全部回退样本。
4. 再复测固定 1× 与自动降速真实服务；按相同 900 步报告现实完成时间、速度、峰值积压和错误。若只有局部改善、整场回退，继续列为限制，不能宣称阶段性能达标。
5. 后台保持战斗规则，UI 按目标名册计划扩展信息展示。若以后需要减少采样/决策频率、改变近距预测精度或输入调度，另行提出影响并沟通。250 ms、7d 完整战斗、7f 原生窗口验收仍未通过。
