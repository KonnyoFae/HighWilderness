# 6a：SCIC 核心与舰队编制

2026-09-20。工作包 6a 已接通；舰队命令与撤离机动的接续进展见[6b 记录](./tactical-stage6b-fleet-navigation.md)。正式距离撤离与战略交接仍待 6c。

## 本轮行为

普通 CIC 舰可以单舰出战，或作为 SCIC 旗舰的随伴舰。两艘及以上的舰队只读取指定旗舰的 SCIC 容量，不叠加其他舰艇的 SCIC；双方规则相同。换旗舰或加入新舰导致超额时，保存编队供继续编辑，在准备核对、提交与部署边界给出错误，禁止入战。空编队可以继续编辑，双方至少各有一艘才能入战。

战前画布显示核心名称和“随伴舰 已用 / 容量”，所选舰艇的设备页说明其编队资格。新校验只在准备及入场边界运行，没有增加每步设计解析。战中失去旗舰不会触发容量重算删舰；全队后续行为另归 6b/6c。

## 模块制作记录

| 模块 / 原型（均为 v1） | 随伴舰 | 干重 | 军官标准 / 最低 | 耐久 |
| --- | ---: | ---: | ---: | ---: |
| 基础 SCIC / `gtw.module.scic.basic` | 3 | 2,000 kg | 4 / 2 | 150 |
| 基础 SCIC（无人化） / `gtw.module.scic.basic.unmanned` | 3 | 2,400 kg | 0 / 0 | 150 |
| 高级 SCIC / `gtw.module.scic.advanced` | 8 | 4,000 kg | 8 / 4 | 200 |
| 高级 SCIC（无人化） / `gtw.module.scic.advanced.unmanned` | 8 | 4,800 kg | 0 / 0 | 200 |

容量两档及有人/无人化变体由用户确认；质量、人员、耐久和尺寸为可调技术初值。统一占基底甲板原点一个 5 m 内部格、不占外部格、不旋转，沿用 CIC 的核心职责和毁伤模型。额定耗电暂为 0，与现有 CIC 初值一致，不代表最终平衡。唯一参数来源：[战术舰队核心目录 v3](../../舰艇数据/模块/测试夹具/战术舰队核心目录.v3.json)。

SCIC 沿用 `cic` 类别，能力字段 `fleet_companion_capacity` 为唯一容量来源。省略字段的普通 CIC 保持原序列化内容与哈希；舰队判定直接读取已编译原型。型号增重进入原有质量、升力冗余与换层时间计算。

遥控核心舱新增同 ID v2，名称“SCIC 遥控核心舱”，100 kg、无人员、耐久 100，宿主槽为 `scic_internal`。v1 和所有旧核心原型不改写。SCIC 同时提供旧、新槽，编译和编辑均将两版核心舱视作同一物理槽，禁止叠装。目录默认显示最新版本，新装及更换宿主仅允许 SCIC。

旧 CIC＋v1 遥控核心仍可读取、编译、保存和单舰出战。编辑器可明确选择 SCIC 型号并点击“将舰艇核心替换为…”，保留核心实例 ID、位置、嵌入设备，支持撤销/重做及另存重开。改装设计导入为新测试实例；没有加入对既有持久舰艇的免费升级、重置战损或库存。历史目录代次用于恢复旧设计，不能把旧舰按当前目录重新解释。
