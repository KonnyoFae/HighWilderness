# E3b 快照发布与实验画布联调

日期：2026-09-09。状态：`E3B_IMPLEMENTED / E3C_NEXT / FULL_E3_NOT_PASSED / DEFAULT_BACKEND_NOT_MIGRATED`。代码基线 `4bef488` 加 E2—E3b 工作树；编辑器和原有限试航入口继续保留。

## 可测试入口

进入「战术视角 → 实时试航（实验）→ 建立实时场景 → 开始试航」，选择实时车钟后点击「执行车钟 / 停止转向」。左/右转按钮保持转向请求，下一次普通车钟指令解除转向。停车与暂停不同：停车经过发动机响应且船体保留惯性，暂停停止权威模拟时钟。暂停后恢复不会自动重放先前操纵，需要重新发令。

新入口仅使用具名两舰技术样例，与旧场景互斥；先释放原试航场景才能进入。画布复用舰壳、跨层部件、舰艏、速度向量、缩放和平移，另显示当前提交步、运行状态、操纵回执、旗舰失权和推进器实际输出。选中红舰只改变观察对象。战术推进仍不消耗燃料。

前端生产包和桌面调试可执行程序已重新构建；本轮没有自动启动用户桌面或覆盖默认试航政策。

## 后台与传输

[`realtime_view.py`](../../backend/high_wilderness_sidecar/realtime_view.py) 将 E3a 调度器接到原 sidecar 的唯一领域线程。该线程在处理请求之间 pump，运行时队列等待最多 2 ms；读取画面不驱动模拟。每轮最多处理一个请求和调度器有界追赶批次，复杂请求仍可能导致过载暂停，不能承诺线程抢占。

只读动态画面约每 66.7 ms 发布一次，保持一个最新值；静态几何只在建立/资源缓存不匹配时返回。静态 SHA 只在建立时计算，快照不调用旧完整场景导出。界面约 15 Hz 读取，不堆叠轮询；手动操作先等待正在完成的读取，再独占发送，避免多个旧快照抢写状态。当前直接绘制已提交快照，没有增加客户端物理预测或插值；插值和刷新节奏的优化按后续实测需要处理。

| 边界 | 本片约束 |
| --- | --- |
| 响应体 | 最多 256 KiB，超过则拒绝；具名样例首次完整响应约 17 KB |
| 显示缓存 | 一个最新快照，可覆盖旧帧；新场景身份/旧步号/旧控制代次不能替换当前视图 |
| 可靠事件 | 沿用 128 条上限，每次最多读取 16 个结果；显式确认后释放，不能通过快照合并丢弃 |
| 输入回执 | 沿用 256 条上限，返回仍保留的可查询状态；每次确认批次先验证合法性 |
| 通信队列 | 沿用 8 个输入/16 个输出帧的桥接上限；输出队列满时领域线程暂停实验，等待通信恢复 |
| 读取租约 | 正常运行超过 2 秒没有成功进入状态读取时暂停，取消待执行操纵；恢复读取不会自动运行 |

使用既有 `tactical` 命名空间内的新能力：`tactical.realtime.create/read/resume/pause/control/close`，Rust 宿主白名单与握手能力同时接线。独立响应版本为 `gaotian.realtime-view/e3b-v1alpha1`，其中 `view` 复用表现格式但明确标记新飞行权威版本，不伪装为旧 v7 场景存档。

`read` 携带场景身份、已知静态指纹、已确认输入序号列表和可靠事件确认位置；返回低频画面、最新提交状态、回执及尚待确认的事件。画面步号可以略落后于状态步号，不能把前者作为最新输入目标。前端在发令前先读取最新状态，选择之后第 2 个步首；发送后不重定位、不自动重发。错过未来步窗口即拒绝，并通过后续查询确定是否接受。

创建响应丢失时，重复建立返回同一具名实验场景，不重置权威世界。最近一次关闭保留一个有界记录，重复关闭可确认已关闭，不能关闭后来创建的另一场景。控制响应丢失时，界面锁住后续操纵并查询状态；确认已接受/执行或未被接受后再允许发令。终态已明确读到后才在后续请求中确认释放。

返回编辑由后台先暂停实验再释放编辑权限。隐藏界面尝试暂停，停止读取的租约作为断连后备。旧编辑内容与未保存草稿继续保持挂载，未把实验快照写入编辑文档。

## 投影失败的明确语义

E3a 的内核候选投影合同没有改动。但本片新增的低频显示发布发生在已提交步骤之后：显示失败不会撤销已经成功完成的物理步骤，也不会重跑它们。服务暂停，保留最后可用画面并提示重新读取；恢复显示从当前权威世界重新投影，不推进时间。重新开始前须完成错误状态读取。

一次浏览器联调发现领域事件中的不可变 tuple 尚未转换为桥接要求的 JSON 数组，导致事件出现后的读取被拒绝。已在输出边界统一转换，固定步中没有新增 JSON 解析；失败记录保留在 `e3b-20260909-browser`，未改写。随后 `r2`、加入无 eval CSP 的 `r3` 和最终界面整理后的 `r4` 均通过；最终源码证据另存为 `validation-r2`，保留先前版本。
