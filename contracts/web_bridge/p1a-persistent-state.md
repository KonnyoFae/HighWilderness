## 本片交付

[persistent_ship.py](../../backend/high_wilderness_sidecar/persistent_ship.py)提供独立版本的资源合同与持久实例，复用既有模块身份、设计来源、供电政策解析和实时飞行/设备领域。旧编辑文件、旧逐弹种库存、旧逐舱质量载荷、E2.3 检查点和桌面默认入口均未改义。

| 入口 | 已实现行为 |
| --- | --- |
| `compile_resources` | 将补充资源绑定到精确准备设计；完整列出安装货舱、弹药库、武器。声明货物单位/体积/质量、装填配方及可空的多货物成本、弹丸精确引用、炮塔参数、正常/降级两档误差配置 |
| `fresh_instance` | 创建具名舰艇实例的空库存状态；技术装载由明确调用方填入，不从旧库存猜测转换，也不默认免费装满 |
| `parse_instance / loads / dumps` | 严格读写船壳/模块耐久、工作模式、燃料、人员、伤员总数、供电政策、发动机跳闸锁存、存续原因、弹药资源、待发弹及装填预留、共享货物；可核对预期实例 ID 与修订 |
| `inventory_summary` | 派生共享容积、已用体积、货物质量、超容状态及预留量。预留仍占体积；容量由未损毁货舱求和，不按部分耐久比例衰减 |
| `validate_initial_loading` | 正常新装载必须不超容；与受损实例的解析/恢复分开，战损超容不能阻止状态保存载入 |
| `enter_battle` | 通过具名 P1a 技术适配进入真实简化飞行内核，稳定实例 ID 与场景船 ID 分开；按保存耐久重新建立设备与推进能力，货物/弹药作为不可变随舰状态保留 |
| `export_instances` | 在拥有线程的已提交空闲边界提取实际损伤、人员/模式、故障与存续原因，并保留尚无消费生产者的库存；不增实例修订、不替调用方执行战后结算 |

资源和实例对象只持有不可变来源及规范 JSON；读出的字典是独立副本。数量使用非负安全整数，货舱体积使用整数 cm³，`125 m³ = 125000000 cm³`。输入拒绝未知/缺失/重复字段、错误资源版本或模块身份、非有限数、布尔计数、负量、批次溢出、混合弹种及预留不足。货物/弹药预留分别按各自单位核对，不重复计入现有库存。

装填预留已能解析、保存和核对批次成本，但本片没有执行装填消费。用户最新确认：合法战后结算默认完成正在进行的装填，瞄准/目标不跨场保存；P1b 实现装填事务，P3 调用完成并保存待发结果。已装入弹不二次收费，未实际开始的额外补弹不由本片凭空创建。暂时切编辑器或断连仍是暂停，不是战后结算。

## 明确的支持边界

1. 本片无新桌面按钮、可用火炮、库存消费、战后结算画面或持久仓库；JSON 往返与新场重建只证明 P1a 合同和技术适配，不能当作 P2/P3 已实现。
2. P1a 飞行适配沿用准备种子的具名部署姿态及已编译质量/惯量；库存尚不动态驱动质量/惯量。这不构成任意玩家设计/装载的出航编译器，相关质量政策与实际装载接线由 P1b/X1a 明确。燃料数量可保存，但与准备模型不同的燃料状态入战会拒绝，不能猜测旧燃料可用性。
3. 非零装填/冷却可保存为合同数据，但当前无武器运行域，不能导入飞行适配后丢掉进度。按最新规则，后续 P3 先完成已开始装填，再输出跨战斗结果；同场暂停恢复仍需保存活动过程。
4. 发动机跳闸锁存、失权/坠落/退出等原因可保留和导出；当前不会自动恢复出战资格，带锁存或不可用状态的再次部署明确拒绝，等待具名处理规则。普通发动机/货舱损毁且舰艇仍可用的重建已验收。
5. 正在推进响应/转层或有活动安全限幅时暂不导出，防止 P1a 静默清除时间状态；既有 E2.3 同场检查点仍负责已支持的连续过程。P3 正式结束边界尚未接入，不能将本片导出动作当作战斗结束。
6. 货物损毁未实现，超容保留库存/预留。炮塔和两档精度只有静态合同，瞄准与锁定运行状态由 P2a 建立且不跨敌场持久化。旧合同不支持静默迁移。
