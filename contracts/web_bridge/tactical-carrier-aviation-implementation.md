# 舰载航空实施顺序与当前交付

更新：2026-09-28。AV0a 与 AV0b/AV1 已交付，规则来源为[航空统一规划](./tactical-carrier-aviation-design.md)。当前可使用正式航空库存、整备和弹射器预装；飞行、巡逻、攻击留 AV2/AV3。第 6 节为本轮记录，第 2～5 节保留 AV0a 历史记录。

## 1. 分阶段交付

| 顺序 | 实施内容 | 完成标准 |
| --- | --- | --- |
| AV0a 基础数据与设施（已完成） | E1/F1/B1 数据与挂点校验，三型机库及起降/指挥设备，20/40 人共享床位，航空人员归属清单与给养输入 | 目录可加载、安装可编译；共享床位不能重复使用；旧准备档精确恢复，新准备不额外补员；离舰机组不计母舰人数 |
| AV0b / AV1 后勤闭环（已完成） | 将航空清单接入舰艇库存、准备存档及界面；配方/工时、飞机与飞行员取得、资源和人员预留、修复/整备/取消、待命泊位、弹射器预装 | 玩家实际完成货舱取机、修复回舱、整备待命、改挂载、战前预装；取消与重试不复制资源；保存/重启不丢失人员与任务 |
| AV2 飞行与起降 | 独立飞机、编队/拆分任务、换层巡逻、弹射/回收、自动返航转降等待、共享指挥塔、机库/弹射器毁伤 | 预装机开局可弹射；起飞移交机组并释放舰内人员名额；回收即时退弹并安置人员；最小合法观测同步接入 |
| AV3 航空攻防 | 机炮、超小自卫弹、小/大型导弹、无动力炸弹和制导炸弹；舰艇/飞机相互攻击 | 真实伤害、有限弹药、独立返航与坠机人员记录，炸弹继承速度，无额外推进 |
| AV4 预警与干扰 | 机载探测、舰艇数据链、随动敌方雷达遮挡、反辐射真实干扰源 | 不干扰友方；干扰源仍可被反辐射锁定；不改变实体箔条和红外/复合导引抗性 |
| AV5 终局与连续战局 | 幸存舰回收、临时货舱人员、满载/全灭打捞池、伤亡与王牌、6c 原子结算 | 自动完工与毁伤顺序正确；舰船 50% 概率不套给飞机/人员；库存、身份与打捞跨场保存，领取重试不重复 |
| 7b～7f | 航空加入代表场景后接回性能、联合验证、节奏与原生体验 | 使用真实航空负载，不以纯舰队成绩代替；不恢复两小时驻留要求 |

AV0b/AV1 不等待所有平衡数值最终定案。参数、配方可使用明确标记的测试初值；改变人员/物资去向或战斗规则时再沟通。伤亡、打捞条目和合法观测随产生它们的功能接入，不能全部拖到 AV5。

## 2. 本轮新增确认

- 船员舱四类兼容：军官、普通船员、技术军官、资深损管，共享 40 人容量。军官舱兼容飞行员、军官、技术军官，共享 20 人容量。
- 机库维护工作人员另按舰艇船员计算；整备开工预留飞行员，完工进入飞机。
- **采用用户随后修正：起飞后飞行员随飞机离舰，释放机库人员名额。** 待命与弹射装载期间仍为舰内人员；在空飞机持有唯一机组记录，坠机结算不回扣母舰待命人员。母舰引用只用于归航，不等于仍在母舰住舱。
- 回收再将人员安置到接收舰；正常舱位不足允许临时住货舱。相关人数/健康/特殊身份作为战略给养输入，战术不扣飞机灵烷或给养。

## 3. 本轮代码边界

- 新设施目录采用增量目录，旧 v1 人员舱及既有目录内容不变；最新战前准备政策 v17 明确升级船员舱为 v2/40 人。旧战术实例读取时沿用自己的目录与政策，不因打开就改装、治疗或补员。
- 共享容量通过人员类别与舱室间的可行分配验证，不能只相加每类上限。接通舾装提示、出航校验、初始配员、人员伤亡暴露与既有伤亡/医疗/改装边界。
- 编辑器提供航空设施分类、容量说明和[航空设施测试舰](../../舰艇数据/舾装方案夹具/航空设施测试舰.v1.json)。该样本可编译、导入准备及恢复档案，初始不赠送飞机、飞行员或武器。
- [机型目录](./fixtures/tactical-aviation.av0.json)提供固定三机型、1/2/3 泊位对应 25/50/125 m³、用人、传感器和挂点数据。载荷表是后续武器的兼容分类，尚不是可发射的武器型号。
- [航空清单校验](../../backend/high_wilderness_sidecar/aviation_manifest.py)提供可编码保存的机体/机组唯一归属和健康/王牌修正、入库卸弹约束、离舰排除及临时人员给养输入；尚未写入正式舰艇库存或战斗调度。
- 起降设备净空复用现有安装几何判定；舰载机整备、运动、攻击、回收和打捞持久化尚未实现，界面已说明设施接入状态。

- 新增航空基础测试 14 项通过：机型/挂载约束、非线性体积、机组离舰与临时给养输入、唯一人员身份、共享床位、三机库安装、弹射净空旋转、合法测试舰准备与档案恢复，以及航空清单的目录指纹绑定/打捞机余弹保留。
- 现有战前准备、3e 人员伤亡、SCIC 舰队、准备服务与 7a 接触开局回归合计 52 项通过。SCIC 专项场景显式选择手动距离以隔离舰队行为，7a 的自动接触与过期指纹仍由独立专项验证。
- 编辑器、人员面板与准备相关前端测试 35 项通过；TypeScript 检查、Vite 生产构建通过。系统 npm 启动入口缺失，使用仓库已安装的对应工具执行，无依赖安装或版本变更。
- 旧舾装编译、出航配置两个独立脚本通过；阶段 I 人员伤亡/回写脚本在加载旧“常规有人舰”完好实例时遇到夹具与初始化结果不一致，尚未到达伤亡逻辑。用 HEAD 中修改前的领域模块运行同一脚本也在同处失败，记为既有夹具问题，不写成通过。
- 本轮未做真实原生窗口航空操作验收；设施可安装与自动测试/构建，不等于舰载机已能整备或作战。

以上为 AV0a 交付时的记录；AV0b/AV1 后续结果见下。

## 6. AV0b/AV1 正式库存与后勤闭环（2026-09-28）

### 已接通

- 新导入使用准备政策 v18，将机型目录、设施实例、配方及航空状态绑定进正式舰艇资源与准备档案；v17 及更早档案继续精确恢复，不静默赠送飞机、人员或升级规则。旧实例需要重新导入设计才能使用航空页。
- 准备与战斗均提供“航空”页。可从有限测试供给接收 E1/F1/B1 与飞行员，选择机库、逐挂点配置、修复、整备、改挂载、卸装回舱及弹射器装载。准备动作先保存草稿、预览，再通过既有全舰事务保存；真实库存只扣一次。
- 飞机和每名飞行员持有独立持久身份。已入机人员只存在于飞机的机组中，未登机和预留人员位于人员清单，不复制母舰人数。现阶段尚未起飞，离舰转移由 AV2 实现。
- 机体入货舱按 25/50/125 m³ 占容积；在工位、泊位、弹射器时不再重复占货舱。机库工位、待命泊位（含预留）和人员容量分别校验。
- 修复支付修复材料，占用一个工位，不占待命泊位，完成为空机回货舱。整备/改挂载占一个工位并预留泊位和足额健康飞行员，完工才将人员移入机组；战术不扣飞机燃油。
- 开工一次扣除完整配方，弹药由作业中的飞机持有；取消即完工，无免费返料。改挂载和卸装先按实际余弹退回对应库存。战前整备缺料时从有限供给补齐，战中只使用舰内未被其他设备预留的物资。
- 仅待命机可转交弹射器，并立即释放泊位。战前预装直接完成装载；战中按正常装载工时计时。预装状态已保存，真正弹射动作留 AV2。
- 开战后计划只预装所需物资，不提前取得工位、泊位或飞行员；战斗固定步进在设备可工作时启动，工位/泊位/人员/物资不足则等待。战后只自动完成已经开工的作业，等待计划不自动产出。
- 作业使用实际设备可用性和维护船员效率；运行中与最终结算共享候选库存。保存/重启、动作回执重试及整批提交重试均保持身份、库存、挂载与队列一致。

### 毁伤和安置边界

本轮用户补充确认：机库/弹射器损毁后余弹退本舰库存；弹射器机组复用 3e 伤亡系数；整舰坠毁时工位/泊位/弹射器中的飞机以受损机进入打捞记录；健康和受伤人员临时住货舱均每人 1 m³（可调）。

- 人员伤亡使用现有 3e 的实际耐久损失与伤亡/死亡比例，并累计小数；只对设备当时实际持有的人员结算。机库工作人员仍由原舰员系统负责。
- 机库或弹射器毁伤终止对应作业，机体受损退舱并卸弹；返回机体无空间时转为待打捞，保留原有其他货舱飞机。失去驻留设施的人员优先使用可兼容军官舱余位，不足才临时住货舱。
- 母舰“残骸”状态独立于船壳归零：升力失效和 6c 撤离失败形成的残骸同样终止航空作业，不允许终局自动完工再生成待命机。既有货舱备用机保留原状态，工位/泊位/弹射器飞机转为受损机；幸存人员入待打捞记录，阵亡者不复活。
- **当前待打捞条目保存在来源舰艇的航空清单中，已能随战后结果落盘。跨舰回收与独立战略打捞池、领取流程仍属于 AV2/AV5，并未宣称已可派船打捞。**
- 飞机出动、回收、编队任务、舰队指挥塔、空中观测/电子干扰、攻击与王牌性能计算尚未接入。

### 可调整测试参数

- 修复每格消耗 10 工程零件，整备每格消耗 2 工程零件；每枚挂载消耗对应载荷库存 1 件，机炮按实际装弹数消耗对应口径弹药。整备后的退弹按相同单位归还。
- 工时仍按 AV0a 的 60 秒修复、30 秒整备、10 秒弹射器装载；战前预装不重复计装载时间。
- 新航空物资沿用已有有限测试供给初始化口径，每种 100,000 单位，仅首次新增该物资时加入；重复打开和接收不补满。此为测试供给，战略采购、定价、生产配方留后续。
- 配方与人员临时体积集中保存在 [v18 政策](./fixtures/ammunition-preparation-policy.v18.json)，通过 [生成器](../../tools/generate_aviation_logistics_policy.py)复现；已有准备档保存完整政策，不随文件变化漂移。
