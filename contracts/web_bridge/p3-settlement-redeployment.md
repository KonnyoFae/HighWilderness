# P3 战后结算、持久保存与再次出航

日期：2026-09-10。状态：`P3_SCOPED_PASS / X1A_E5_NEXT / PLAYER_DESIGN_DEPLOYMENT_NOT_IMPLEMENTED`。基线为 `3e26613` 加 P1a/P1b/P2a/P2b/P3 工作区实现，尚未提交。当前顺序见[后续交付计划](./editor-tactical-delivery-roadmap.md)。

## 本片交付

技术舰已经完成“实际交战 A → 结束 → 待保存结算 → 重启后台 → 保存 → 同一受损舰进入 B → 再次保存”的实际界面流程。结算页面逐舰显示船壳、模块和局部装甲损伤、弹药资源与待发弹前后值、资源变动原因、货舱容积与超容状态。

合法结束时沿用 P2b 的冻结规则：完成已开始且仍有效的装填，取消无效预留，清除在途弹丸。自然结束立即准备恢复记录，不等待下一次界面刷新；暂停、编辑器切换、断线仍不构成结算。正在推进或转向不再阻止战后导出，也不要求为了保存继续模拟至完全停车。

结果先自动写入待保存记录，再由“保存全部战后结果”原子提交所有参战舰。重启后可以从结算记录查看并提交尚未保存的结果。提交成功后，本方舰船列表提供再次出航入口；敌舰的完整结果同样保存，但下一场使用新的技术敌舰，不沿用旧瞄准目标。

## 实例合同与再入场

新增 `gaotian.persistent-combat-ship/p3-v1`，组合原 P1a 状态、原资源定义、设计绑定及局部装甲耐久。P1a 内层合同没有静默改版；旧的单独 P1a JSON 不能冒充包含装甲的 P3 存档。

- 保留船壳比例、逐模块耐久与模式、人员/已有伤员、供电策略、发动机资源故障锁存、燃料、弹药资源、待发弹、冷却剩余步数及共享货物。
- 局部装甲按甲板 ID/层号、区域 ID、边索引保存；载入时逐边核对身份、数量及上限。不因下一场重新编译设计而恢复成完整装甲。
- 新部署重置场景位置、朝向、速度、操纵输入、发动机瞬态进程与安全调节瞬态、炮塔瞄准/目标/雷达锁定、弹丸及旧步号。发动机硬故障锁存另行保留，不能借重新部署解除故障。
- 入场从保存的真实耐久重建能力；已失去出航能力的舰船保留记录并明确拒绝出航。货舱损毁导致超容不构成拒绝条件，货物不删除，仍允许消费；新增装载继续遵守容量限制。
- 目前只接受已接通的技术普通炮资源版本。特殊弹效果、未知资源绑定或变化后的燃料质量模型不能以普通炮/完好舰状态静默替代。

解析、指纹核对、库存和几何重建发生在结算/载入边界。正常飞行不访问存档仓库，也不调用持久实例解析。

## 保存事务与故障处理

本地仓库为项目目录中的 `.local/tactical/settlements.sqlite3`，已经排除版本控制；后台参数 `--settlement-dir` 可指定独立目录，测试使用隔离仓库。

仓库使用 SQLite 事务和完整同步。待保存结果以稳定结算身份保存，内容校验和用于检查损坏及冲突。提交时先核对所有舰船的战前版本与完整原记录，再在一个事务内写入全部战后实例、递增版本并标记结算已提交。

- 同一结算的精确重试返回原结果，不再次扣费或递增版本。变动摘要必须与战前/战后资源数量对账。
- 任意一艘舰写入失败，整个事务回滚；原实例保持原样，待保存记录仍可恢复。测试覆盖进程在写入第一艘舰后直接退出，重启后恢复并重试。
- 已有更新版本时拒绝覆盖；冲突结果保留，不自动合并两场战损。当前不提供多后台并行使用同一舰船后的人工冲突合并界面。
- 存在未保存结果的舰船不能通过列表载入旧版本。当前场景未提交结算时，也不能关闭该结果或替换成下一场；停止应用后，已落盘的待保存记录仍可恢复。
- 首次恢复记录写入失败时，结果保留在当前场景，界面明确提示保持场景并重试。此时不能宣称重启后一定能恢复尚未写入磁盘的数据。
- 再次出航带独立请求身份，丢失回执后的同一请求发现原场景，不重复创建；新场景准备或显示失败时保留原场景。

这不是战斗进行中的完整检查点。后台在交战结束并生成恢复记录之前退出，不提供中途战斗恢复；已有跨场存档不因此自动变成同场续玩存档。

## 入口

新增后台操作通过现有桌面通信白名单接线：

| 操作 | 用途 |
| --- | --- |
| `tactical.realtime.settlements` | 本方实例与近期/待保存结算列表 |
| `tactical.realtime.settlement` | 查看指定结算及保存状态 |
| `tactical.realtime.save` | 幂等原子提交全部参战舰 |
| `tactical.realtime.deploy` | 校验实例/版本，从保存状态开始新交战 |

在“战术视角 → 实时试航（实验）”内结束交战后即可查看结算；重启后进入相同入口，使用结算记录和本方舰船列表。当前支持同一技术本方舰连续多场、每场新敌舰；敌方记录增多不会把原有本方舰从列表挤掉。
