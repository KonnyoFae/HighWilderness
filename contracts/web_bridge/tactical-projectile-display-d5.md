# D5：弹体显示传输联合验收

日期：2026-09-21。本记录汇总 D0～D4 新显示通路的战斗一致性、事件完整性、前后端性能及桌面正常交战/保存流程。Windows 最小化与可见性检查按用户要求从本次收尾范围中移除，不计为通过，也不再阻塞 D5；本轮不交付相关窗口行为改动。

## 测试范围与证据

三类测试分别回答不同问题，不能互相替代：

| 测试 | 输入与运行方式 | 验证范围 |
| --- | --- | --- |
| 后台旧/新通路对照 | 合法双单舰编队，上层/云层/雨层分别运行 120 秒模拟时间；每层旧/新各 7200 步 | 弹体及舰艇逐步状态、毁伤、库存和战后结果完全一致；出现/终止事件不遗漏 |
| 生产画布专项 | 使用真实 React/Pixi 组件；密集同输入重复回放，再以 15 Hz 回放上层 120 秒墙钟及云/雨各 20 秒 | 分开测解析、合并、观测过滤、采样、绘制 CPU、帧间隔与 JS 堆；不代表原生宿主或后台实时调度 |
| 实际桌面流程 | 打包的 Tauri/WebView2 程序、真实 Rust/Python 通信、隔离存档及合法四舰；正常准备、导弹发射、结束保存、再次入战 | 桌面入口、真实发射及连续两场清理和保存；不运行最小化检查 |

浏览器中重复画面是固定输入性能回放，便于比较同一场景的旧/新开销；不是正在进行一场真实战斗。它不能证明桌面窗口、原生通信或实际战斗保存已经通过。桌面检查使用原程序及原后台源码的隔离副本，不使用网页替代后台，不接触玩家存档。

## 后台传输与发布成本

沿用冻结的 D0/A5 两舰 29 炮短局，步数为 403/395、发射数 215/211、在途峰值 189/183，保持输入及观测范围。统计排除初次静态几何；这是短局同条件对照，不冒充 120 秒持续战斗。

| 指标 | D0 | D5 |
| --- | ---: | ---: |
| 弹体字段累计字节 | 22,537,958 | 9,373,767 |
| 全部响应累计字节 | 46,656,836 | 33,498,045 |
| 单次响应峰值字节 | 383,483 | 226,644 |
| 发布与读取 CPU 合计 | 3,530.10 ms | 1,481.06 ms |

弹体字节减少 **58.41%**，发布/读取 CPU 减少 **58.04%**，达到减半及减少 30% 的目标。混合持续样本单次响应最大 85,275 字节、保留窗口最大 91,785 字节，未扩大 1 MiB 桥接预算。保留事件容器有界，不按整场累计。

原始数据：[D0](../../artifacts/projectile-display-d0-20260921/report.json)、[D5](../../artifacts/projectile-display-d5-measurement-20260921/report.json)。这是同机测量；近防预测和整个模拟步耗时仍需独立优化，不能由这两个百分比推导“全部战术卡顿已解决”。

## 画布 CPU 与内存

密集输入使用同一版绘制器分别消费旧历史与新事件通路，不宣称保留了 D0 整个前端可执行版本。单位为毫秒：

| 分项 | 旧平均 / P95 | 新平均 / P95 |
| --- | ---: | ---: |
| 每次响应解析 | 0.361 / 0.500 | 0.295 / 0.400 |
| 每次响应合并 | 0.001 / 0.000 | 0.115 / 0.200 |
| 每帧轨迹采样 | 0.065 / 0.200 | 0.075 / 0.200 |
| 每帧几何准备 | 0.223 / 0.400 | 0.236 / 0.400 |
| 每帧绘制提交 | 0.509 / 0.700 | 0.505 / 0.700 |
| 每帧画布 CPU 合计 | 0.797 / 1.100 | 0.816 / 1.100 |

新通路增加缓存合并开销，解析与合并总均值约增加 0.048 ms/次；采样与画布合计 P95 均未回退。帧间隔 P95 两者约 4.3 ms，仅代表本机采样，不是通用帧率保证；没有测 GPU 执行时间。

D0 未实际冻结完整绘制 P95 数字预算，因此如实使用 D5 同输入配对，并采用 `max(旧 P95 × 1.25, 旧 P95 + 0.5 ms)` 的回归报警阈值；不能倒称这是事先冻结的 D0 数字。实测两项 P95 均与旧通路相同，不依赖阈值放宽才通过。

上层 120 秒连续显示有 1800 次发布，时间线最多 17 帧，弹体缓存峰值 26 条；40～120 秒区间强制 GC 后 JS 堆增长约 0.193 MiB，未出现明显持续增长。云/雨各 20 秒、场景清空及组件卸载通过。计数器包含切场准备阶段，所以记录中的 `maxDisplayed=122` 不能说成持续场景有 122 枚在途弹；实际持续峰值为后台记录的 22。

## 正常桌面流程与交付边界

实际桌面使用两支合法 SCIC 编队，共四舰、50 km 初始距离及有限库存；友舰通过正常导弹指令向空地点发射，随后结束/保存和第二场入战。最终短流程首场运行约5秒，在第331步结算，第二场在第39步结算；结束时分别清除8/2枚在途弹。第二场初始步为0、旧弹体和终止事件均为空，返回准备后画布已卸载。只读核对隔离数据库，两份结果均已完整提交。该场景用于通信及连续战局流程，与上文持续负载分开统计，不称为120秒负载。

桌面流程已完成，但收尾的诊断采集器错误地从精简活动行读取`kind`，导致“导弹峰值大于0”的统计断言失败。因此保留原失败日志，**不采用这次原生导弹计数作为性能证据**；连续两场流程依据已执行断言和数据库复核单独确认。采集器已按出现事件中的类型定义修正，按用户收尾要求不再重复运行。[正常流程与只读保存复核](../../artifacts/projectile-display-d5-desktop-final-20260921/normal-flow-report.json)、[原始检查记录](../../artifacts/projectile-display-d5-desktop-final-20260921/partial-checks.json)。
