## T1a 实施顺序

1. **建立独立命名的两舰产品样例。** 两阵营、固定技术舰和显式技术出航配置，记录船壳、模块、弹药、人员、燃料、涂料及推进安全资源身份。创建时暂停；选择 v7 完整安全路径。确认当前临时外挂 RCS 下能编译、初始化并推进一个固定步，不用旧派生快照或旧报告冒充当前结果。构建器不能依赖测试脚本里的组装函数，测试可复用产品构建器。
2. **冻结最小表现合同。** 静态数据含船体轮廓、模块位置、阵营和资源身份；动态快照含场景 ID、步号、模拟时间、位置、朝向、速度和耐久。视觉事件含稳定身份、步号、类型及涉及对象；输入含场景 ID、序号和目标步。表现版本独立于权威存档，首版传低频全量动态快照，静态几何只在绑定变化时发送。
3. **接入场景创建、读取、释放。** 建议在 `backend/high_wilderness_sidecar/tactical.py` 管理单一测试场景，经现有 sidecar 串行队列处理。方法名、作用域与错误码在落地合同中冻结；同步修改 Python 信封、宿主受控入口、TypeScript transport 和能力握手。模式退出/后台重启使旧场景身份失效，读取与表现投影不得推进或修改场景。
4. **完成最短跨进程验证。** 真实 Python 子进程经宿主创建暂停的两舰场景并读取快照，重复读取结果一致，静态几何可追溯到编译结果。验证错误场景、旧后台、未知能力及队列边界；为后续输入序号/目标步拒绝保留一致语义。T1a 不因尚无实时控制而假称 M4 通过。

拟新增的最小文件为场景适配器、表现合同/类型与相关测试；沿用现有桥接，不另建通用仿真框架。单步内核检查属于自动验证，用户可操作的单步控制在 T3a 接入。
