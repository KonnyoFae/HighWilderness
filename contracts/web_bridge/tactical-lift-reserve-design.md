# 战术升力冗余、强制下坠与抢修设计

日期：2026-09-15。状态：设计、准备及交战升力冗余见[工作包 1](./tactical-stage1-entry-ui.md)，主动换层见[2c](./tactical-stage2c-active-height.md)。下坠、零点冻结、10 秒储罐抢修及残骸记录已接入，验证范围见[2d](./tactical-stage2d-descent-repair.md)。本文替代此前“升力失效立即坠毁”的设计；CIC 损毁、船壳崩溃及仅推进失效的规则分别保留。

## 一、已经确认的规则

- 舰艇具有可读的“升力冗余”数值，作为战术生存状态更早进入设计、准备和交战循环，而不只在换层时计算。
- 升力冗余采用舰艇干重，挂载和货物不影响该数值，也不影响由它触发的下坠风险。
- 用户进一步明确：只有冗余为负时开始强制下坠；零冗余不用强行开始下坠。此答复替代最初“减少到 0 时开始下坠”的措辞。
- 负冗余对应的升力缺口越大，强制下坠倒计时越短；不采用各舰统一固定抢修秒数。
- 下坠按高度层推进：上层→云层→雨层；到达雨层后仍未恢复升力，则继续下坠，最终坠毁。进入雨层本身不等于已经坠毁，必须保留最后的抢修机会。
- 抢修使冗余恢复到正数后，立即停止下坠读条，保持当时实际所属层；已经掉下去的层不自动恢复。
- 储罐保留“未毁时提供满升力、完全摧毁才失去升力”的规则；允许紧急抢修已经摧毁的升力储罐，以提供恢复升力的途径。
- 2026-09-16 明确：灵烷贮槽本身无需船员值守，不占用岗位，不要求无人化改装，缺员不削减升力；维修和抢修使用损管设备自身的人员/自动化条件。当前原型为零人员需求，本轮以全舰零可执勤人员核对运行时，贮槽仍保持原有升力。
- 下坠途中仍是可抢救的舰艇，不提前转成残骸，也不因旗舰开始下坠就直接认定旗舰损失或结束战斗。

## 二、数值与计时的整理

首轮界面采用以干重为基准的升力冗余百分比：

`rho = (L_available - m_dry*g_ref)/(m_dry*g_ref)`

这里 `L_available` 是受损和修复后当前可用的总升力，`m_dry` 固定采用干重。`rho = 20%` 表示升力比维持该干重悬浮所需值多 20%；`rho = -20%` 表示缺少 20%。显示不能把负值截成零，否则会丢失下坠风险和计时所需信息。该数值由实际升力与干重派生，按战损和抢修更新，具体显示形式仍由界面草案确定。

主动换层继续保留此前确认的入战前基础计算及线性受损惩罚：`a0 = (L0 - m_dry*g_ref)/m_dry`，按对称加减速整理 `T0 = 2*sqrt(5000/a0)`；损失 25% 入战升力时，主动换层整段耗时增加 25%。这套公式要求正净升力，不能用于强制下坠。主动换层可以取消且与其他命令并行；强制下坠由当前升力状态触发，不能靠取消换层或反复下令绕过。

本轮用户已确认：各段独立按从静止开始、无末端制动的五公里下坠计算，雨层坠毁前的末段也为五公里，不保留上一段的加速效果。`a_fall = (m_dry*g_ref - L_available)/m_dry = -rho*g_ref`，仅在负冗余时为正；每段 `T_fall = sqrt(2*5000/a_fall)`。缺口相同，各段耗时相同；途中缺口变化保留当前进度并调整剩余计时。不积分真实垂直速度，不增加可操作的第四层。

本轮用户已确认零点边界：零冗余不新触发下坠；已在下坠时恰好恢复到零，冻结读条并保留进度，再次负冗余时继续。只有正冗余才立即清除下坠进度并保留当前层。

## 三、储罐抢修必须接通实际升力

当前实时升力按模块 `lift_tank.lift` 功能效率汇总；现有测试模块目录使用 `binary_until_destroyed`，测试明确剩余 1% 耐久仍提供全额升力、完全摧毁才失去升力。已有损管规则不允许在战术中重建已毁模块。因此仅增加下坠倒计时，不能保证玩家能通过现有储罐维修恢复升力。

用户已选择保留“未毁满升力”，同时允许紧急抢修已毁升力储罐。这是对原“战中不重建已毁模块”的储罐专项例外，不推广到所有已毁设备；不改成按剩余耐久线性衰减升力。普通储油填充单元不提供升力，不能把修复它们当作恢复升力。此前测试作为旧规则范围内的证据保留，新抢修能力另行实施和验收。

本轮用户将初值明确为：单具损管设备工作 **10 秒** 修好一具已毁升力储罐；沿用提议的资源成本与耐久门槛，即累计消耗相当于修复该储罐 25% 满耐久的损管资源，完成时一次恢复 25% 耐久和满升力。未完成时不提供任何恢复升力，不能靠微量普通维修复活。再被击毁必须重新完成一次抢修。

用户同时明确首版 **抢修完成自动补满储罐油料**，替代此前“不免费补回已损失燃料”的限制。此补油来源为暂时的自动供应，独立记入账本；后续改为使用备用燃料槽（如甲板空余填充燃料槽）的实际存量补充。当前不自动修复或抽取甲板填充燃料槽。

本轮工程默认：自动损管优先灭火，之后优先已毁升力储罐，再按原规则修其他模块/船壳；手选维修目标仍生效。同一储罐每步只分配一具设备，不叠加抢修速度。灭火、资源准备和停工暂停抢修并保留进度，更改维修目标重置该设备进度，已消费资源不返还。跨场不保留命令和抢修进度。上述协调行为为本轮落实方式，可继续调试，不作为用户逐项确认的新数值规则。

## 四、对开发顺序的影响

本专题正式纳入[首版开发规划](./tactical-first-release-implementation-plan.md)。2d 的前置行为决定已明确并落实；后续可继续工作包 3 的正式弹药与高速炮战，完整舰队撤离仍由工作包 6 接通。

| 阶段 | 需要纳入的工作 |
| --- | --- |
| 工作包 0：准备 | 对齐冗余显示、强制下坠计时、已毁储罐紧急抢修的成本与完成条件、零点与命令衔接；核对状态与结算边界 |
| 工作包 1：入口与界面 | 将升力冗余前置到设计/准备信息及战斗舰况，预留危险提示、下坠目标层/倒计时和储罐抢修入口 |
| 工作包 2：三层与升力生存流程 | 依次细分 2a 显示时间线、2b 三层画布、2c 主动换层、2d 强制下坠与紧急抢修；2d 完成后整包验收，不能把可抢救下坠当作终局失能锁死命令或维修 |
| 工作包 6：撤离与战果 | 仅最终坠毁才记录升力原因残骸；核对下坠舰的舰队成员、旗舰状态、全队换层阈值和战斗结束时的处置 |

CIC 损毁仍立即坠毁；既有船壳崩溃、仅推进失效最终结算条件和指定单舰撤离规则分别保留。因升力造成的残骸记录最终实际坠毁事件的位置和身份，不能在首次负冗余时提前生成残骸。战略打捞仍留待后续。

## 五、后续验证目标

- 干重一致时，挂载和货物变化不改变冗余与下坠风险；升力受损/修复正确更新显示。
- 正冗余不下坠、零冗余不新触发、负冗余才触发；缺口越大计时越短。
- 上层、云层按各段完成时切受击层；雨层保留末段抢修机会，不增加可操作的第四层。
- 抢修恢复正冗余立即停止当前读条，不跳层或回到原先高度；损管资源真实扣除。
- 取消指令不能消除仍存在的负冗余风险；正常移动、攻击等能力仍按其实际战损处理。
- 尚可抢救的下坠不提前触发旗舰永久失权、胜负冻结或残骸结算；最终坠毁只结算一次。

本轮验证覆盖三段真实下坠、零点冻结/恢复、抢修与资源/油料、末段救援及最终坠毁记录。完整舰队撤离时仍在下坠的舰艇、仅推进失效舰的最终处置以及战略打捞继续留在工作包 6。
