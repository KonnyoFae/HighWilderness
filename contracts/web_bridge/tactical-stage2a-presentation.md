# 战术首版工作包 2a：共用显示时间线

日期：2026-09-15。状态：实现与真实界面验证完成。后台仍以固定 60 Hz 推进、约 15 Hz 发布状态；前端随屏幕刷新采样已提交的战场状态。工作包 2 整体尚未完成；后续 2b 三层画布也已接通，当前进度见[2b 记录](./tactical-stage2b-layers.md)。

## 玩家可见的变化

舰艇位置和转向、炮塔方向、目标标记、舰名、炮弹及命中效果共用显示时间。画面在两次状态发布之间连续更新，点选舰艇和模块使用同一份屏幕位置。炮弹的实际速度、寿命、资源消耗和命中规则保持现有值；本片不替代工作包 3 的正式弹种和高速碰撞验收。

初值采用 100 毫秒显示缓冲。暂停直接对齐已提交的暂停状态并停止战场动画循环，镜头缩放和平移仍可操作；恢复不补播暂停期间的墙钟时间。读取暂时中断时最多播放到最近的真实快照，随后冻结；较长快照缺口（超过 0.5 秒）、后台/场景/几何身份更换时重新对齐，不倒放旧场景。隐藏页面和离场会取消战场动画，清空测试与新战斗不沿用前场轨迹。

本片取消的是战场绘制循环。Pixi 内部资源维护回调由渲染库管理，离场销毁渲染器；暂停验证分别计数，避免把维护回调误当作仍在模拟或绘制战斗。

## 数据与实现范围

- `presentation.ts` 维护有限快照缓冲和单调的显示时间，只采样已提交状态；舰首与炮向按角度最短路径插值，炮塔原点依附显示中的舰体。
- `TacticalViewport.tsx` 在持续绘制时复用舰体图形，舰名直接跟随同一帧更新，不以每帧 React 状态变更驱动画布；镜头和点选都使用已显示的位置。操作命令、库存及侧栏状态继续使用后台权威数据。
- `tactical_presentation.py` 在每个成功提交的模拟步后记录弹体出生和结束。存活弹体快照增加出生步、炮口与到期步；已结束弹体保留实际终点和命中类型，因此两次发布之间出生并结束的弹体也可采样。失败模拟步不产生显示记录，重复读取不重复产生事件。
- 显示历史独立于检查点和战果保存，不写入持久舰艇。当前直线匀速弹道按原速度显示，最后一个命中步止于实际碰撞点；以后增加阻力、导弹制导时须扩展相应轨迹采样，不能继续假设全程匀速。
- 已结束轨迹保留 120 个模拟步，最多 128 条，并报告超出容量的丢弃数量。超限仅舍弃旧显示轨迹，不改动弹体或命中；现有响应字节预算继续生效。高射速近防和代表性舰队规模须在相应工作包实测并调整，当前双舰验证不代表该规模已验收。

## 验证证据

- 前端类型检查及 100 项测试通过。其中 8 项新增验证覆盖中间帧、跨 ±π 转向与炮塔依附、短命命中、2,000/5,000 米每秒显示样本、出生/到期、重复与乱序快照、暂停/恢复、身份更换、长缺口及显示位置点选。
- 显示历史与实时视图 13 项后台测试通过，包括真实发射后在两次发布间到期、实际扫掠命中终点、失败步不留记录、历史容量边界和暂停/租约/重试回归。
- [真实界面报告](../../artifacts/tactical-presentation-20260915/result.json)：生产 React + 真实 Python 服务，使用隔离仓库中的合法自建舰实际入战、加速、瞄准与开火；暂停镜头、短暂读取失败、隐藏事件及强制清空后重新入战通过。
- 本次环境约 240 Hz 的刷新采样中，三秒窗口内测得约 215 次/秒的位置变化、40 个不同状态发布；战场动画回调耗时 P95 为 0.30 毫秒。显示相对最近已接收快照的滞后中位数为 66.5 毫秒、P95 为 100 毫秒；一次操纵至显示对应步数为 180 毫秒，其中至权威发布为 104 毫秒。这些是本机双舰样本数据，不是其他设备或大舰队的帧率承诺，也不把回调 CPU 耗时当作完整 GPU 帧耗时。

准备入战与强制重置的 15 项关联后台回归也已通过，本片合计 28 项后台测试通过。桌面 TypeScript 检查、前端生产构建与 Rust/Tauri 调试构建成功；仅有既存的前端包体提示及链接器信息。
