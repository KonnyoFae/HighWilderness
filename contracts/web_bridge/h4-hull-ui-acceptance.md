# H4 船壳 UI 最小验收

## 真实桌面操作

在 Windows Tauri 调试应用中，通过原生输入和文件对话框完成以下操作。后端实例为 `backend.c1138f6840f24bdb85eeb4d5ae909a94`；没有调用领域 API 代替这些 UI 操作。原有三个“新建船壳”恢复草稿保持不动。

| 样本 | 操作 | 重开结果 | 安装空间（内部 / 露天 / 侧挂） | 质量 |
| --- | --- | --- | --- | --- |
| 常规有人战舰 | 资源列表打开→另存 conventional.json→关闭会话→打开文件 | 合法、干净修订 0、两层甲板 | deck.0：75 / 57 / 64；deck.1：14 / 14 / 36 | 2207.93 t |
| 完全无人旗舰 | 资源列表打开→另存 unmanned.json→关闭会话→打开文件 | 合法、干净修订 0、一层甲板 | 57 / 57 / 46 | 1177.50 t |
| 最小合法舰 | 资源列表打开→另存 minimum.json→关闭会话→打开文件 | 合法、干净修订 0、一层甲板 | 45 / 45 / 38 | 942.00 t |

文件均位于 `artifacts/h4/`。重开常规战舰后切换至 deck.1，画布显示两个当前层区域以及淡蓝色半透明 deck.0 完整轮廓；界面明确标记正下层参考，切层不改变修订。

在重开的 minimum.json 上继续操作：

1. 将右上端点从 `(7.5, 40)` 向右拖动约 13 屏幕像素；端点强制落在 `(10, 40)`，只产生修订 1。界面提示缺少镜像边，保存及另存按钮禁用，安装格隐藏，最近合法预览仍标记修订 0。
2. 将该端点出边（舰首边）的装甲厚度设为 `0.1 m`，应用形成修订 2。
3. 点击“以右侧为准”，出现完整对称梯形的金色替换预览与“应用对称替换”。预览阶段其他修改、保存及撤销暂时禁用。
4. 应用后成为合法修订 3，仍只有一个区域。撤销恢复非法草稿，保存再次禁用；重做恢复合法修订 5。
5. 另存独立 edited.json，保存规范化后为干净修订 6。关闭会话并用“打开文件”重开 edited.json，显示合法、干净修订 0。

edited.json 的独立数据检查确认：单区域、六个端点、无中线内边；左右舰首半边均为 `0.1 m` 装甲。结构质量 `1,099,000 kg`，装甲质量 `78,500 kg`，总质量 `1,177,500 kg`。minimum.json 原始样本仍逐字段一致。

从空白绘制双层船壳的 UI 证据沿用 H2/H3 报告及 `artifacts/h2h3/drawn-hull.json`；默认单侧自动镜像沿用 `526efe4` 中的专项验证和用户试用确认。本轮新增的是三条正式测试夹具的实际文件往返与上述替换/装甲/多甲板操作。

## 可复跑的数据检查

从仓库根目录运行：

```powershell
python -X utf8 tools/verify_hull_ui_roundtrip.py
```

该工具要求四个真实 UI 保存产物全部存在；三条未修改船壳与原始 ResourceIndex 资源的完整权威预览逐字段比较，包括规范几何、所有安装空间、气动/RCS 等完整派生数据和资源指纹。编辑产物与独立构造的梯形及舰首装甲期望比较。它只重检文件，不会重新运行桌面操作，也不把文件存在当作 UI 验收证据。

机器报告：`舰艇数据/报告/阶段WebH4船壳UI往返.v1.json`。其中完整预览摘要使用 UTF-8、排序键、紧凑 JSON 的 SHA-256；资源指纹继续使用领域层已有定义。
