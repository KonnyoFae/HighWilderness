## 现有实现边界

旧 `高天荒野舰艇持续毁伤.py` 提供持续火灾、显式点燃、损管队指派和按有效效率降低火势；旧逻辑没有有限设备资源、工程零件补充或模块/船壳维修。新实时战术已接真实火灾、有限灭火、维修、持久保存与玩家界面。新导入舰采用包含 D1c 损管能力的 H5d 策略；旧舰保留原配置，普通弹/穿甲弹尚不点燃目标。

## 用户确认的核心规则

1. 每具损管设备拥有独立的损管资源容量与当前余量。工程零件是全舰共享货物，按货舱规则占容积；设备内已准备的损管资源与货物不能重复计数。
2. 设备资源用光后，必须消耗工程零件并经过准备过程才能继续使用。结构类似武器装填，配方定义工程零件成本、产出资源量、设备容量与准备时间。
3. 设备启动后优先消耗损管资源灭火；有可处理火灾时，不同时推进低优先级维修。
4. 灭火之后持续消耗资源修复指定部件；未指定部件时，默认从耐久最低的部件开始维修。
5. 最后有剩余资源时用于持续恢复船壳耐久。无可执行工作则待机，不空耗资源。

## 首片实施口径（工程默认，可调）

- 自动排序以剩余耐久比例判断，避免不同最大耐久的部件按绝对点数排序失真；同值按稳定模块身份排序。选中目标保持到修复上限、失效或玩家改令，不因每步数值变化反复换目标。
- 指定模式只维修指定部件，完成后转船壳；自动模式依次处理可修部件后转船壳。新火灾打断维修，灭火结束后恢复适用任务。
- 初版修复上限为设计最大耐久，使用按秒速率和实际恢复量对应的资源成本；不恢复局部装甲、不重建已经损毁的模块、不复活已判定失去作战资格的舰船。结构恢复按绝对耐久处理，不让不同材料以相同比例免费获得不同修复量。
- 灭火强度、维修效率、资源容量及准备配方在入场编译；具体数值标记为技术数值。仅在伤害、资源、设备可用性或玩家命令变化时重选工作，持续灭火/维修/准备按固定时间推进，不在每步重验整舰。
- 使用统一库存预留事务：准备开始预留工程零件，完成时扣货物并增加设备资源，取消只释放预留；缺料不产生部分准备。设备不可用时停止工作，已毁设备不得准备；暂停不推进。精确暂停/取消边界在实现测试中冻结。
- 多具设备独立存量，共用工程零件；同一事务边界有确定顺序，避免重复扣费、超额修复及重复灭火收费。
- 保存每具设备的剩余资源、实际工程零件库存、维修后的模块/船壳状态。结算不免费执行灭火或维修。建议沿用武器口径，仅完成已经开始且仍合法的准备批次，不自动新建准备；这是工程默认，并非用户已单独确认的损管结算规则。
- 战前准备提供工程零件装载及设备资源预准备，保留已有资源，不因入战自动补满。维修目标/启动命令不作为下一场自动执行命令；交战中断点续玩仍不属于目标。

## 实施顺序与验收

1. **D1a 已完成**：设备静态合同、独立资源存量、工程零件货物定义、准备事务及持久状态兼容，含后台离线舰队预准备。缺失新能力的旧设计保留原状，不免费迁移出设备资源；D1d 已为新导入实例启用新策略。
2. **D1b 已完成**：新实时循环接入最小真实火灾状态、受控测试点燃来源及伤害/灭火更新，含未灭火情保存和再入战；不得仅有“灭火”按钮而无实际火灾。首片不顺带完成所有燃烧弹、防火填充或火灾蔓延。
3. **D1c 已完成**：在已有后台启停与灭火循环上接部件指定与自动选择，实现灭火→部件→船壳的工作顺序，接原子资源消费、实际修复与设备领域更新。
4. **D1d 已完成**：玩家战前库存与设备预准备、旗舰战中启停/指定与自动目标/余量/准备/工作原因显示，以及战后逐舰资源及修复净结果展示。真实界面准备→火灾/维修→保存→重启→重新准备入战验证通过，见[D1d 报告](./d1d-damage-control-ui.md)。
5. 验证资源耗尽后准备再用、零件不足、多设备争用、新火灾抢占、目标损毁/修复上限、设备损毁、暂停、失败步回滚、重试、结算及重启再入战。必须使用真实火灾与受损模块验证结果，不能仅以库存人工消费替代。

H5c 灵烷槽已接通；H5d 防火仅降低整层新点燃概率，已有逐步烧伤、自然衰减和损管消费保持现有规则。已接真实燃烧弹来源并共同验收，见[H5d 报告](./h5d-fireproof-ignition.md)。微机修复材料不属于填充候选；战术推进不耗灵烷，仅槽损毁丢失其中存量；货物燃烧不列入当前或默认后续计划，其他货物损毁仍暂缓。
