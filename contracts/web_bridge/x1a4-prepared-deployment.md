# X1a.4 已准备舰船入战与战后往返

日期：2026-09-11。基线：`438a73a` 加 X1a 工作区。状态：`X1A4_SCOPED_PASS / H5B_NEXT / O4_NATIVE_EVIDENCE_PENDING`。本片接通编辑设计、准备库存、实际交战及战后持久状态的基础设施，不代表战略模式或玩法全流程完成。

## 实现范围

战前准备保存后，可以选择当前舰为旗舰，点击“以所选舰为旗舰进入交战”。全部已准备舰船加入蓝方，另有一艘明确标注的技术敌舰；玩家操纵旗舰并选择其火炮，其余友舰自动交战。该入口直接显示实时画布，不再要求玩家先手动建立技术场景。结束并保存结算后，“返回战前准备”回到实际舰船列表，可选择同一实例准备下一场。

`prepared_deployment.py` 在入场边界恢复精确设计及资源绑定，使用自建船壳、实际模块位置、局部装甲、耐久、库存及待发弹组装新实时场景。部署位置按船壳范围间隔放置，界面显示设计名称；不替换成技术蓝舰，不给玩家舰增加试航推力倍率。入场启用普通炮、传感器和火控的战斗工作模式，仍受耐久、供电和人员条件约束。瞄准、目标、锁定、位置和速度是新场景状态，战损、冷却、故障锁存和资源继续保留。

自动装填改为读取各武器已编译的实际配方，炮塔限制也读取其资源定义；不再强制请求旧 `recipe.p2a.ordinary`。待发弹耗尽后依配方装填，结算只完成已经开始的有效批次。当前命中内核仍仅接首版普通炮参数，不把未支持的弹种或弹丸参数悄悄替换成普通弹效果。货物容积及超容规则不变，货物质量沿用固定设计质量政策；战术推进不耗燃料。

## 入战身份、占用及异常处理

- 新增 `tactical.realtime.deploy_prepared`，只接受已保存准备 ID、稳定入战 ID 和旗舰实例 ID。完整前端库存或自报设计不能绕过准备事务进入场景。
- 构建候选场景后，在同一 SQLite 事务内核对各舰保存内容，写入入战身份并认领参战实例。场景挂接失败时回滚认领，可用同一请求重试；已经支付的准备成本保持原样。
- 同一次请求回执丢失可读取原场景，另有只读 `prepared_entry` 用于确认。更换准备内容、旧修订或在尚未结束的交战中请求另一场不会重置舰船。
- 实际准备交战不能直接关闭丢弃战损，需结束并保存结算。P3 在全部舰船原子保存时释放匹配场景的认领；重复保存不增加修订或重复扣费。
- 进程持有操作系统文件锁，另一个仍在运行的后台不能释放它的占用。进程退出后，准备列表恢复时检查遗留入战：已有结算就保留待保存结果；没有结算则标记中断、释放占用，恢复入战前已保存的准备状态。准备费用不退回，界面显示中断提示。

**既定规则（用户于 2026-09-11 确认）：结算生成前退出后台，恢复到战斗开始前已保存的状态；已生成的结算可跨重启恢复。** 交战中断点续玩不属于实现目标，后续不规划该功能，也不将其列为当前缺陷或迁移验收条件。入场存档包含已经完成的战前准备，恢复不会退回准备费用。

## 玩家测试步骤与后续

1. 打开“战前准备”，导入已保存栖装或从目录创建实例，选择参战舰船。
2. 设置弹药与货物；需要时选择预装填，核对后保存准备。也可直接保留现有库存。
3. 选择旗舰并进入交战，开始试航，右键选炮/左键指定敌舰，或使用现有火炮选择控件。
4. 结束交战，保存全部结果，再返回战前准备。选择原实例，核对余弹、货物及战损，准备并进入下一场。

当前合同允许至多 15 艘准备舰加 1 艘敌舰，并受原有响应大小上限约束；本片只声明 3 舰代表性实测，不声明 16 舰性能验收。敌方策略、友舰自动开火及人员/燃料部署仍为明确的技术预设，不包含战略补给或完整编队 AI。

统一顺序中的下一项为 H5b 逐层填充设置，O4 三舰原生留档结合用户实测收尾。特殊弹效果、损管消费、默认战术入口迁移及完整战略模式按原规划分别推进。
