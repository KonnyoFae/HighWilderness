# E1c.2 事件与简化飞行原型（2026-09-08）

状态：`E1c2_PROTOTYPE_IMPLEMENTED / DOMAIN_PRODUCERS_PENDING / REALTIME_NOT_PASSED`。

本片已让独立实验会话使用固定方向贡献实际推进舰船，而不只是提前编译数据。入口为 `backend.high_wilderness_sidecar/simplified_flight.py` 的 `build_sample_session(root)`，通过 `step()` 运行 1/60 秒。`realtime_flight.py` 的 E1b 对照路径和桌面默认路径仍保留；新会话没有接入画布、IPC、墙钟调度或真实交战。

## 1. 实现边界

只读资源来自 E1c.1 的贡献表，运动参数在进场时从合法技术舰准备。初次使用既有 I9 检查指定蓝方旗舰的直控资格，随后持有独立的紧凑权限状态。热循环不再保存/提交旧完整场景，不调用旧整舰推进解析、runtime 编译、配平、规范 SHA 或 JSON 导出。

运行时维护逐发动机阶段、固定数量的可用性原因及版本、各方向剩余能力/实际输出、六通道安全限制、活跃到期表和运动状态。正常飞行只读取方向总量；没有能力事件、改令或到期时，复用发动机记录和排程。每台最多一个活跃期限，取消时直接删除，不积累旧任务或历史世界引用。

原始输入仅在传入新控制时严格解析。`step(None)` 继续当前目标；自动制动根据当前速度选择现有反向 quarter 规则。该入口是同步离线工具，不是已发布的可靠网络输入协议；输入序号、未来步队列和可查询回执仍由 E3 实施。

### 能力变化

- 内部 `AvailabilityEvent` 带会话、舰艇、发动机、原因、版本和 opening/closing 边界。错误身份、阶段、类型和重复版本冲突拒绝；旧版本忽略，同版本同状态幂等。
- 同边界合并多个原因后再更新最终可用性。修复后仍断电时不加回推力；重复损毁不重复扣减。
- 剩余能力按固定整数贡献差量更新；实际输出同步扣减。恢复先回到 off，再按原启动和响应时间推进，不沿用损毁前的输出与期限。
- opening 事件影响本次交付，closing 事件影响下一交付区间；已获得的速度/角速度保留。船壳归零后在收边界断推并关闭操纵资格。
- 事件、阶段、排程、运动、最新结果一起候选提交；异常或表现回调失败不提交。重入和跨线程写入拒绝。

血量没有加入推进扫描。当前输入是“可用性原因改变”，并非直接传入血量；实际毁伤/人员/供电领域的事件生产者还未接入。

### 时间、运动与安全

发动机到期和改令直接复用原时间内核的计算函数，省去外部解析包装；只有发生变化时才构造新阶段。平移与转向分别积分，没有主机偏置偏航、转向机残余平移或健康发动机配平降额。

阻力、坐标变换、结构/乘员载荷、固定步积分及过载损伤继续共享既有机动函数。实际输出燃料率为零，保留当前燃料量。定向互锁等待对向实际输出归零，不能同时交付对向推力。

结构/乘员限制在收边界检查当前运动和下一到期候选，保留共同升阶否决、分级降档上限、释放等待与 OverG/乘员锁条件。阈值与释放函数共享旧实现，整舰候选调度使用紧凑表示；通过旧整舰安全判定器专项对照，而非凭新内核自证。

## 3. 验证

相关测试共 56 项通过，其中本片新增 17 项。覆盖：

- 主机和转向机各 240 个边界的严格时间参考对照，包含启动、非整数响应秒数、中途改令、停止/重启。
- 两发动机共同安全限制与旧整舰安全判定器 140 个边界对照，比较每台阶段和每通道上限、原因、限制/释放起点；另测乘员锁和 OverG。
- 40/30/30 加权损毁、断电叠加、恢复启动；重复/旧版本/冲突事件；到期同边界损毁；独立转向、主机偏置不偏航、反转和自动制动。
- 零阻力可解析案例验证 opening/closing 断推、惯性、位置积分和燃料不变。
- 400 步固定种子事件序列与独立原因账本/全量求和对照，检查精确整数总量和活跃排程上界。
- 稳态复用发动机/排程、不调用发动机解析；投影失败、非法事件、重入、非有限载荷均保留原已提交世界。

运行命令：`python -X utf8 -m unittest tools.test_simplified_flight tools.test_simplified_propulsion tools.test_internal_step_proofs tools.test_realtime_flight tools.test_tactical_realtime_baseline 高天荒野WebT3a单步操纵测试 -q`。

证据：[e1c2-20260908-flight-r2](../../artifacts/t3a-realtime-experiment/e1c2-20260908-flight-r2/result.json)。`tools/verify_simplified_flight.py` 冻结源码和资源，保存新的具名输入/事件带，两次独立创建并运行 360 步。361 个边界重放完全一致，722 个边界的能力/输出全量求和通过。仅会话 epoch 属于每次创建的所有权身份而不比较；动态状态和新事件不删字段。这里是确定性与增量机制证据，不替代上面的独立时间、安全和运动参考。首轮证据保留，r2 补正归档器沿用的旧 worker 构建描述，飞行代码未因此改动。

## 4. 短测口径

两舰，120 步预热后测 60 步，包含持续推进/转向和一次收边界发动机损毁；r2 三次无分析器平均为 **0.170、0.155、0.171 ms/步**。另一次机制画像中，`parse / to_dict / canonical_sha256 / aggregate_actuators / compile_runtime_ship_parameters / verify_derived_ship_snapshot_fingerprint / _parse_exact_timing_capability` 的热循环调用均为 0。

此数据仅含新飞行内核，未包含旧完整场景、武器/事故、旧表现投影、IPC 或 UI，不能与旧 E1b 20.4 ms/步直接计算优化倍数。还没有执行 3600 步吞吐门、墙钟调度或长跑，`REALTIME_NOT_PASSED` 保留。
