# D1c 实际部件与船壳维修

日期：2026-09-11。状态：`D1C_REPAIR_SCOPED_PASS / D1D_UI_NEXT`。完成[D1 规划](./d1-damage-control-plan.md)第 3 步：后台指定/自动选择目标、实际模块修复、船壳恢复、有限资源消费与保存往返。玩家操作界面仍待 D1d；默认导入仍使用 S1 配置，本片不自动升级已有舰船。

## 实际工作顺序

1. 先结算本步炮击、火灾及设备失效，再检查损管设备的运行条件与准备状态。
2. 本步开始有火情的舰船优先处理火灾，本步不修复；火情清除后下一步转入维修，避免同一设备在一个时间步同时满速灭火和维修。
3. 指定部件时持续修复该部件；未指定时，按剩余耐久比例从低到高选择，同值按稳定模块身份排序。自动选择保持到目标修满或失效，不因其他部件每步数值变化频繁换目标。
4. 自动模式依次处理可修部件后修船壳；指定模式修完指定部件后转船壳，不顺带改变其他部件的维修优先级。指定部件已经损毁时跳过重建，船壳也无需修复时显示目标已毁。
5. 同一设备每步只修一个部件或船壳。多个设备共享本步剩余缺口，不超过设计最大耐久，也不对已经完成的修复重复收费。

新火情打断维修，目标选择保持，灭火结束后恢复适用任务。设备损毁、失去供电/人员、关闭或舰船已失去作战资格时停止工作；资源耗尽后沿用 D1a/D1b 工程零件准备规则，完成后继续维修。没有工作可做时不空耗资源。

## 修复边界与成本

- 只修复仍然存活的模块。已毁模块不重建，已判定退出/失去作战能力的舰船不通过本片复活；装甲耐久、人员、燃料及货物均不随维修补满。
- 船壳按绝对结构耐久恢复，再换算保存的完整度比例。不同结构材料修复相同点数收取相同资源，不能因最大耐久较高而按比例免费获得更多修复量。
- 资源费用按实际恢复量计算，接近上限或资源不足时按缺口/剩余资源裁剪效果。费用向上取整到最小整数单位（1 点资源 = 1000 单位）；不会按完整一秒或完整一帧收费后只修一点点。
- 船壳恢复会按已有 H5b 规则增加货架填充的有效共享容量，但不生成货物；货舱部件已经损毁时也不会自动重建。
- 合法结算可以完成已开始的准备批次，但不执行免费维修。保存实际修复后的模块/船壳状态、剩余设备资源、工程零件和未灭火情；启动意图、指定目标及自动选择缓存不跨场保存。

## 版本与技术值

[独立 D1c 策略](./fixtures/d1c-preparation-policy.v5.json)采用新的准备策略、资源定义与实例 `d1c-v1` 合同，增加版本化 `repair` 配置，保留 D1b 火灾及 D1a 设备资源数据。旧 D1b 配置不会因为代码支持维修就自动获得维修能力。

技术配置：每具设备每秒修复 **6 点模块耐久**，每点消耗 **1000 资源单位（1 点资源）**；或每秒恢复 **60 点船壳结构耐久**，每点消耗 **100 资源单位（0.1 点资源）**。因此在完整速率下两者均为每秒消耗 6 点设备资源。此配置为测试值，尚非正式平衡数值。

内部目标命令 `repair_target` 的 `module_id` 指定本舰模块，空值选择自动模式；沿用独立命令序号、精确重试和所属舰检查。玩家启动、点选和目标显示将在 D1d 对接，此片没有新增玩家按钮。

## 原子提交与实时循环

新建独立维修提交边界，位于毁伤、库存及灭火工作之后、权威世界发布之前。资源消费、修复效果、库存中的健康/容量投影及最终观察结果一起提交；任何阶段失败均回滚候选，重试不重复扣费。

普通设备伤害命令不能夹带免费维修。维修边界明确拒绝已毁部件、重复模块操作、超上限修复和失去作战能力的舰船；保留原来明确开启的测试重建接口，不借用它实现玩家维修。部分模块恢复耐久不会改变已经编译的发动机推力贡献。

参数、模块最大耐久、身份索引和结构换算在入场准备。自动目标有效时不重扫全部部件；全舰无可修部件且设备修订不变时复用空结果。持续修复按固定步执行，不重解析资源、材料或整个设计。
