# 3e：人员伤亡与岗位效能

日期：2026-09-16。接续 [3d 弹药库殉爆](./tactical-stage3d-magazine-detonation.md)，完成首版人员舱伤亡、优先岗位分配、实际工作效能及战后保存。下一工作包为弹体耐久与近防协调；其他正式弹种、导弹、舰队指挥和完整首版验收仍按总规划推进。

## 已确认规则与可调初值

- 人员舱被炮弹或殉爆伤及，以及人员舱所在内部火区造成的实际损伤，均产生人员后果。舰外火灾、其他设备受击暂不直接伤人。
- 入战时按各人员舱对每类人员的容量，分摊全舰该类可执勤人数。本场分摊基数固定，不因随后伤亡重新分摊。
- 舱室每实际损失 10% 满耐久，造成其入战分摊人数 5% 的伤亡；完整损毁约损失分摊人数的 50%。伤害按实际剩余耐久封顶，过量伤害不重复伤人。修复后再次实际受损仍可产生伤亡，但不得超过全舰该类剩余可执勤人数。
- 伤亡初值为 75% 负伤、25% 阵亡，两者都退出可用人员池。本阶段不加入战中治疗；伤员及阵亡记录跨场保存。
- 人员数量使用整数，伤亡小数及死亡比例余数分别按人员类别累计、保存。小样本不必刚好符合 75/25；连续轻伤与火灾不会因逐步取整而全部丢失。
- 剩余人手按既有岗位优先级分配：先保障关键岗位最低人数，再保障其他岗位最低人数，最后分配标准人数缺口。缺员设备降效，低于最低人数的人工功能停用；原有自动化功能保留其性能。

可调系数位于[人员策略](./fixtures/tactical-personnel.3e.json)：满耐久损失伤亡系数 `0.5`，死亡占比 `0.25`。已确认规则不与数值平衡混为待定项。

## 实际战斗与保存

固定步按炮击、内部火灾、殉爆的实际模块损失顺序计算人员后果。完整内部伤害来源独立于界面最近记录，不会因显示条数截断而漏计。伤亡与模块、资源、指挥状态一起提交；失败步不扣人、不累计小数、不追加伤亡事件，重试从原状态计算。

人工岗位效能已作用于推进实际推力和安全载荷、炮塔转动、射击周期与装填、搜索和火控距离、损管灭火、模块/船壳维修及储罐紧急抢修。低于最低配员停机；最低人数为零但完全无人且无相应自动化的功能，也不能凭零效率完成工作。损管资源制备时钟维持原规则。

装填批次和射击周期在开始时确定本次时长，途中部分缺员影响下一批或下一周期；完全失去装填人员时取消当前人工装填、释放预留。批次保存其开始时的工作率，可正确恢复剩余进度。自动瞄准、自动射击与人工装填分别计算，不能用全模块统一系数抹掉功能差异。

持久实例新增可选 `personnel` 状态，保存各类负伤、累计阵亡和两种小数余量；可执勤数及舰上伤员总数同步更新。旧实例兼容；已有但未分类的旧伤员保留，不臆造其类别。舰上仅剩伤员时仍保留乘员安全锁。保存、重启、下一场准备与入战不自动补员、治疗或追溯伤害已毁人员舱。

界面入口：

- 舰况 → 舰上人员：可执勤、负伤、累计阵亡，以及按类人数和逐模块可展开的配员/功能效能。
- 战场记录与全舰资源 → 人员伤亡记录：实际人员舱、甲板、炮击/内部火灾/殉爆来源及分类损失。
- 战后结果 → 人员战后变化：本场前后人数，随全部战果保存。

首版不计算个人位置、其他有人设备受击伤亡、士气、医疗、逃生或搜救。已经归零的人员舱不再凭背景火焰持续扣人；未实现的伤亡来源留待后续扩展。
