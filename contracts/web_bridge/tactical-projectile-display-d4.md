# D4：显示生命周期清理与黄色细尾迹

2026-09-21。本阶段已完成，下一步D5联合验收；6c及其余舰队工作仍在后续队列。

## 本阶段交付

- 普通炮弹、近防炮弹、反舰导弹和拦截弹的尾迹统一为黄色（`#ffff00`）、固定1 CSS像素宽，移除浅色背景上的粗底线；缩放不改变宽度，DPR只影响物理像素密度。红蓝1像素点/3×3空心框仍独立保留。修复暂停炮弹的本地尾迹与旧`previous_m`不一致、可能不绘制尾迹的问题。
- 当前显示协议为`gaotian.projectile-stream/d4-v1`。新通路协商后，控制、暂停、结束等响应也使用新通路，不再因一次操作重建旧轨迹并清空前端游标。普通控制返回完整当前窗口用于独立恢复；`rebase`单独标识超窗、字节预算或发布缺口所需的时间线重对齐，普通控制不触发回放时钟跳转。
- 生产发布只构建简洁活动状态，轨迹窗口由显示流持有，不再先给每枚弹附完整历史再剥离。读取只编码一次用于字节校验和返回独立JSON对象，去掉此前整包深拷贝与重复编码；结果仍与同一已提交步一致，调用方修改返回值不会影响后台缓存。
- 终止事件由一份有界队列负责，提交后释放旧128条备份，避免预算淘汰的事件又从旧备份进入重同步。继续使用120步、4096条、2 MiB终止窗口及32批次/2 MiB发布窗口，常规累计增量超过384 KiB时重同步，实时完整响应仍受1 MiB限制。预算淘汰数量公开记录。
- 失联立即撤掉显示样本；同ID短暂失联后重捕也不能将两段观测相连。切换操作/观测舰只撤销旧敌方观测，保留友方平滑。后台原始缓存仍是本地调试/面板内部数据，敌弹进入显示时间线前始终由合法观测重建，不能取隐藏轨迹、导引头状态或真实出生信息。
- 超窗恢复、后台/场景身份更换和窗口重新可见时，从当前提交状态重新对齐，不补播积压弹体或旧命中效果；隐藏时不再向绘制时间线加入新帧。普通缺读只冻结在最新已提交状态。过期包不倒退或清空有效游标，格式损坏则请求重同步。
- 拦截效果按共同显示时钟出现，与发布之间已终止的弹体对齐；按“步号/拦截弹/目标弹”去重，不再等到下一整个发布边界才显示。战斗结束清空显示流并停止战斗效果绘制，保留供战斗日志和结算使用的真实记录。VLS待出弹记录不会提前生成飞行，仍按真实出弹时刻出现。
- 未协商新通路的旧客户端保持原读取行为；调试工具可显式按需恢复旧轨迹。前端仍支持D1～D3录制样本，不在生产中同时生成新旧两份滚动历史。
