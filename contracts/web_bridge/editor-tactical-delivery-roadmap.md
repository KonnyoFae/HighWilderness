## 二、后续实施必须沿用的规则

- 编辑器严格验证设计；战术入场编译静态构造，运行中只因实际变化更新相关能力。运动、弹丸和装填计时仍按固定步执行；不能把无变化免验证误作无命令不推进。
- 推进和转向按已编译贡献汇总，不做实时配平；部分发动机掉血本身不减推力，损毁/不可用失去其贡献。战术推进不耗燃料，技术舰推力倍率不施加给玩家设计。
- 弹药库储存统一资源，武器按批次成本 C 换 N 发；开火只减待发弹。特殊弹配方可附加消耗多种货物，先留接口，具体效果后接。
- 首批普通炮必须同时提供默认自动火控和手动瞄准。自动精度只有正常/降级两档；未锁定、失锁及无替代来源时的雷达损毁共用降级配置。位置/速度估计和射向误差后续调参，正常档也不保证必中；完全没有可用目标估计时暂停自动射击，不另立第三档。
- 货舱提供全舰共享容积，货物按种类/数量/单位体积计量；不绑定具体货舱。货舱损毁只减容量，库存与货物预留保留，超容禁新装载但允许消费、保存和载入。货物损毁算法暂缓。
- 船壳/模块完整度、各类资源、待发弹种与数量和必要活动状态跨战斗保留。设计、持久实例与单场检查点职责分开，换场不能补满、复活、重新收费或免费清除活动过程。
- 战术动作即时更新权威状态；战后按最终结果原子持久化，画面只展示结果。重试或重开结算不能重复扣除。
- 用户最新确认：合法结算时默认完成已开始的装填，按批次消费预留资源并保存待发结果；瞄准、目标与锁定不跨场保存。暂时切回编辑或断连仍按暂停处理，不触发结算补弹。

详细字段、装填与保存规则以[战后状态规划](./tactical-persistent-ship-state-plan.md)为准。

## 三、近期主线：依次交付六步

### 第 1 步：P1a 最小实例与资源合同（范围内完成）

实际已接接口、证据及限制见[P1a 报告](./p1a-persistent-state.md)。受损发动机/货舱可进入真实简化内核；活动武器、锁存/不可用舰重部署及动态装载质量尚未接线，保留状态或明确拒绝，不静默恢复。

交付：明确设计引用、稳定舰艇/模块身份和实例修订，保存船壳/模块状态；新增统一弹药资源、实际待发弹种/数量、全舰货物库存及货舱容积贡献。货物定义计量单位、单位体积及必要单位质量；武器定义版本化装填配方、成本 C、产出 N、容量、耗时及可空的特殊货物成本列表。

同时预留 P2a 所需的炮塔转角/转速等静态参数和战斗内实际炮向、自动/手动模式、舰艇/模块目标身份；它们的场景状态与跨战斗库存分开，不能把旧场目标直接写成下一场攻击命令。

自动火控预留正常/降级精度配置、目标估计来源与采样时间、有效锁定来源和必要可重放误差状态；没有雷达锁定不等于普通火炮禁止开火。

完成新状态的入战/导出与最小序列化往返，保留已有受损状态和货物超容。旧逐弹种库存及逐舱 kg 载荷显式适配；缺少转换依据必须提示，不能默默换算。必要新技术资源在同一片准备，不等正式平衡数值，不先建设完整战略仓库或配置编辑器。

退出：同舰同模块、损伤、资源、货物和待发弹往返一致；错误版本/身份/数值拒绝；战损超容可载入。人工样本仅验状态接口，不算真实毁伤已完成。

本片开工执行顺序与完成边界：

1. 在既有设计/实例与 E2.3 检查点职责上确定显式新合同，复用稳定身份和验证能力；旧逐弹种库存、逐舱 kg 载荷不直接改义。
2. 实现最小版本化状态解析、导出及入战适配：船壳/模块损伤、弹药资源、待发弹、共享货物和预留；容量由绑定的货舱及其状态派生。炮塔/火控先明确后续动态状态归属和质量配置，尚未支持的活动状态不得静默接受。
3. 准备有限技术装载及明确的受损/超容样本，补普通弹批次配方、货物计量定义和正常/降级配置合同；不等正式平衡参数。
4. 验证干净与受损往返、缺失/未知字段、资源版本和模块身份冲突、非法数量/预留、超容恢复及普通装载限制的区别。确认现有编辑资源与实时试航入口没有被静默迁移。
5. 记录实现范围和可复核产物，完成后立即进入 P1b。P1a 不交付库存消费算法、完整火控/武器、结算 UI 或战略仓库，不以这些尚未接线功能阻挡最小状态完成。

### 第 2 步：P1b 资源事务与装填基础（范围内完成）

已实现接口、冻结政策、真实内核事务证据与限制见[P1b 报告](./p1b-inventory-transactions.md)。货物与弹药资源消费不动态改变飞行质量/惯量；结算准备不判断合法结束，也不写入持久仓库。库存域检查点不是完整战斗读档。

交付：全舰库存增减、容量检查、预留/释放；普通装填按批转换；基础资源与特殊货物多项成本的原子事务。预留仍占容积，实际消费才释放容积；重复动作不重复扣资源。定义装填开始、完成、取消、武器损毁及暂停时的行为，并把必要活动状态接入保存合同。

冻结最小换弹限制、装填与冷却跨场时间口径，以及资源变化对已接质量/性能状态的更新边界；优先沿用适用规则，明确新政策，不把聚合值手填入存档。建立有界的逐资源/原因变动摘要，供 P3 汇总使用，不保存每步整舰副本。

最新装填口径已确定：提供“合法战后结算完成当前装填”的受控事务，复用正常完成装填的扣费逻辑，跳过剩余等待时间；P3 统一调用。不能重复扣预留、免费换弹或自动新建额外补弹。瞄准状态无需跨战斗保存；P1a 合同保存活动预留用于同场状态和结算输入，P1b 不再将跨场保留装填倒计时作为默认设计。

退出：C/N 配比、混合货物容量、缺料整批拒绝、多武器资源争用、幂等与装填恢复成立；货舱损毁/超容不删库存或货物预留。特殊配方可用合同样本验证，未接战斗效果仍明确不可用。完成后立即进入可操作武器，P1 不继续扩成完整后勤系统。

### 第 3 步：P2a 普通火炮的自动火控与手动瞄准（范围内完成）

实现与测试见[P2a 报告](./p2a-ordinary-gunnery.md)。两种模式和正常/降级已经同时接线；本片当时的技术弹丸尚不求命中；已由后续 P2b 接通。栖装显示容量和技术配方说明，实际玩家装载绑定仍由 X1a 交付；未宣称新完整战斗读档或原生 WebView 视觉验收完成。

交付：在新实时入口使用有限弹药的技术火炮，首批必须同时具备两种操作模式，默认自动火控。自动模式下右键点选本舰火炮，左键点击敌舰或特定模块指定目标，炮塔按目标位置、速度和适用弹道求提前量、转向，并在合法条件满足时自动持续开火与按批装填。手动模式下所控炮塔跟随鼠标对应世界位置转向，左键按下请求一次武器规定的射击动作，由玩家自行提前瞄准。默认自动模式不等于自行搜敌，没有指定目标时不自动开火。

两种模式共用真实炮塔朝向、转速、安装射界、弹药、装填与冷却；发射沿权威炮口方向生成弹丸，不能直接从枪口连线鼠标/目标来绕过转炮。支持敌舰与模块目标的稳定身份和实时位置转换；模块重叠/跨层有明确选择反馈。提供模式、所控武器、目标、期望瞄准点与实际炮向、装填/受阻原因显示。详细交互及状态边界见[双模式火炮规则](./tactical-persistent-ship-state-plan.md#火炮操作默认自动火控与手动瞄准)。

自动瞄准精度随当前目标的雷达锁定状态变化：有效锁定正常计算提前量；未锁定、失锁或来源雷达损毁且无替代锁定时，以粗略位置/速度估计和增大的火控射向误差继续开火。完全没有有效目标估计时才暂停。质量由实际观测/设备状态提供，不能因选择目标自动获得精确锁定，也不能用真实目标运动值伪装降级估计。用户已确认仅正常/降级两档，各无锁定原因共用降级配置；误差具体数值在本片功能可操作后调试，不扩展多级质量系统。显示状态及原因，P2a 必须包含该规则。

检查指挥、供电/人员及适用火控、射界和上层遮挡，使用现有规则的合适部分；静态规则预编译，动态合法性在动作边界检查。栖装面板同时显示该武器的容量、单批成本/发数等必要参数，不另建通用武器原型编辑器。

退出：自动模式可分别对移动敌舰和指定模块求提前量、转炮并连续合法开火；手动模式可随鼠标转炮并左键发射；两者资源消耗正确，切换不会叠加两个射击来源。遮挡、无弹、冷却、损毁等受阻原因清楚；暂停和重复命令不会制造额外弹丸或消费。自动与手动均为 P2a 必需项，不能只完成按钮单发就关闭本片；真实命中毁伤仍由 P2b 验收。

追加退出条件：有效锁定、未锁定/失锁、雷达失效与有效锁定恢复对应正常/降级质量；降级射击确实发生且估计/射向误差可复现。雷达锁错目标不提供精度加成，有其他有效锁定来源时不无故降级。旧缺少火控支持即拒绝的合同只能显式适配，不能把普通炮降级规则扩散为取消制导等其他武器的硬要求。

P2a 内部按“炮塔/射击共用基础 → 默认自动火控与两档精度 → 手动瞄准及输入互斥 → 双模式实机验证”接线。中间可演示已接部分，但只有两种模式、正常/降级切换及资源消费均成立才能关闭 P2a。降级参数调试使用相同技术舰、目标运动与固定种子，核对估计偏差和弹道结果；参数调优不改旧证据，也不要求当片完成正式数值平衡。

### 第 4 步：P2b 真实命中、战损与基本交战反馈（范围内完成）

实现与验证见[P2b 报告](./p2b-projectile-damage.md)。编译几何在入场准备，实际弹丸在固定步提交前产生装甲磨损、模块/船壳战损；能力变化、库存取消与战斗结束一起提交。装甲阻挡/跳弹使用独立编译内核夹具验证，现有画布技术舰仍是无装甲设计。

交付：弹丸对实际舰体/模块几何求命中，接普通炮弹适用的装甲和耐久规则；伤害进入已有设备/指挥失效通道。发动机损毁影响推进/转向，武器损毁影响发射，货舱损毁影响共享容量。画布与面板显示命中部位、损伤及功能变化。

实际命中并损毁提供锁定的雷达后，相关火炮按剩余有效来源更新精度；无替代锁定但还有粗略目标信息时继续降级开火，已经发射的普通炮弹不追溯改变。此项用真实战损验证 P2a 的火控质量接线。

使用可复现敌舰目标；在首条射击毁伤链路成立后，补最小脚本指定敌舰攻击目标，复用 P2a 自动火控进行还击，用于双向交战验证，不另写一套开火算法或提前扩建复杂战术 AI。冻结战斗结束、毁坏、撤离及活动弹丸/装填/持续过程在结束边界的处理。首批选用已接效果的普通炮；未接事故或持续效果需明确限制资源适用范围，不把旧完整毁伤系统宣称为已迁移。

退出：从实际发射得到可核对的未命中、装甲阻挡、部分损伤和损毁；能力变化来自真实命中，无人工 HP 修改替代。完成代表性小规模交战短测，确认新增弹丸/毁伤没有把整舰解析带回每步；未通过只优化实测热点。

### 第 5 步：P3 战后结算、保存及下一场（范围内完成）

实现及证据见[P3 报告](./p3-settlement-redeployment.md)。测试舰实际交战 → 结束 → 待保存结果持久化 → 重启 → 原子提交 → 同一受损舰再次交战已通过实际界面联调。局部装甲按稳定边身份保存，原 P1a 内层合同仍有效，P3 外层版本明确区分；库存及旧飞行检查点不升级为完整战斗读档。

P2b 已提供胜负/主动撤离冻结、在途弹丸清除和有效在装批次完成；暂停、切编辑器和断线仍不构成结算。P3 已扩展 P1a 的实例合同：局部装甲耐久按设计绑定与甲板/区域/边身份保存，不能只存船壳比例并在下一场重置装甲。现有库存域导出和旧飞行检查点不包含全部 P2b 状态，不作为完整战斗保存入口。

交付：合法结束/撤离后冻结权威结果，原子保存参战舰艇状态、结算身份及摘要，失败保留可恢复结果。提供逐舰结算画面，显示船壳/模块损伤、资源前后值、增加/消费/损失、待发弹、货舱容量和保存状态；未实现的货物损毁不产生损失。

冻结最终保存状态前完成已开始的装填，将这次资源消费一并计入结算；目标、瞄准及锁定不带入新战斗，重复提交不重复完成装填。

以同一受损舰建立下一场，保留资源和待发状态；新部署姿态由入战规则给出。当前无战略模式时由最小本地实例列表/测试调用方承接，不伪造战略调度。单场继续游戏的检查点与跨场最终状态分别处理；包含新武器/资源的同场保存若提供入口，必须覆盖相应活动状态，未覆盖不能宣传为完整战斗读档。

退出：真实 A 场开火/受损 → 结算 → 重启 → B 场，损伤、余弹、货物及已完成消费延续；未使用的货物也完整保留。逐资源汇总对账、两舰提交原子性、重复结算、回执丢失、崩溃重试和战损超容均正确；保存失败不以旧状态放行下一场。尚未接特殊弹/维修不能靠人工消费声称其战斗验收通过。

### 第 6 步：X1a/E5 玩家设计出航与产品入口（下一项）

本片按“绑定实际设计及资源版本 → 准备装载与部署 → 接入 P3 实例仓库 → 自建设计交战/保存/再次出航 → O4 三舰与原生界面留档”实施。先保留显式入口，验收通过后再评审默认切换；不先制作完整战略界面或扩展特殊弹效果。

交付：从实际保存的船壳/栖装版本创建独立舰艇实例，选择明确的初始装载与部署技术预设，进入新实时战斗。最小准备页显示弹药资源、货物/损管配件、已用/可用容积、人员/燃料等已接必需条件；允许调整当前需要的资源数量，禁止超容及不支持的武器/填充效果。设计容量与实际库存分开，复制蓝图不能覆盖既有受损实例。

栖装侧补齐新容量/装填参数与出航错误定位；O4 三舰规范实机留档与本片用户设计往返一起收尾，期间发现编辑阻塞即修复。完成设计 → 出航 → 交战 → 战后保存 → 再次出航的实际技术链。仅在新路径支持范围、兼容/回退和原生界面验证达标后评审默认入口切换；旧样例/旧存档不静默升级。

退出：至少一条真实自建设计完成上述操作，其几何、模块和实际装载参与战斗；规范三舰往返证据齐备，跨模式切换不丢草稿/实例；性能检查使用代表性小规模战斗，不设固定 2 小时单场门槛。

顺序：`P1a → P1b → P2a → P2b → P3 → X1a/E5`。P1a/P1b 只是原 P1 的实施拆分，不另起一轮架构实验；O4 留档可穿插真实界面检查，不阻挡前五步开发，也不能用自动测试冒充实机留档。

## 五、明确暂缓及恢复条件

- 货物损毁、逐舱货物分配、货物三维摆放：当前不实现；不得成为容量/保存验收前置。
- 全口径成品弹库存和逐口径采购：不属于已确认的简化后勤设计，不作为未来必补项。
- 更大规模舰队战术压力矩阵、固定两小时测试、Rust 热核/全面重写：只有当前代表性负载测出问题或发布需要时恢复相关工程工作；大战舰队属于战略层目标。
- 完整编队/航路 AI、观测共享/EW、制导/持续毁伤全量迁移、回放播放器、复杂特效：按具体玩法逐项恢复，原有公式不等于新实时入口已支持。
- 正式数值平衡、教程舰、无开发环境安装包：分别待可交战测试能力和实际分发需求就绪；当前技术数值必须标明。
