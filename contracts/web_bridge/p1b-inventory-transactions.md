## 已交付的事务

| 操作 | 当前行为 |
| --- | --- |
| 装载/卸载/消费货物 | 检查整数数量、共享容积及未预留余量；超容禁止新增，允许消费/卸载，保存载入不截断库存 |
| 装载/卸载弹药资源 | 按弹药库容量检查；不能卸掉已预留资源；损毁库不能新增装载或供弹，保留现有数量供后续规则处理 |
| 开始装填 | 按稳定弹药库 ID 顺序分配统一资源，并同时预留所有特殊货物成本；任一条件不足则整批拒绝，不消耗命令序号 |
| 装填完成 | 同一事务扣掉全部预留资源、增加整批 N 发待发弹并更新摘要；C/N 不要求一比一，覆盖主炮、弹仓与弹链样本 |
| 取消装填 | 只释放预留，没有提前扣费，因此不退款，也不增加待发弹 |
| 待发弹扣减 | 提供后续射击使用的 `discharge` 底层操作，检查余弹/装填/冷却/本体与宿主损毁，仅减待发弹并设置冷却，不再扣弹药资源；它尚未生成弹丸或核对完整射击许可 |
| 结算准备 | `prepare_settlement(id)` 完成所有已开始且仍有效的装填并冻结该域；重复同一 ID 无动作，不同 ID 拒绝。没有开始的装填不会自动创建 |
| 保存/恢复 | 持久实例可保存实际库存与余弹；独立库存检查点同时保存活动预留、剩余时间、最近命令回执及摘要，恢复后重复请求不会再次扣费 |

命令使用会话 epoch 和连续序号。只接受最新动作的完全相同重试；更旧请求直接拒绝，不为每条历史命令无限保存回执。新部署产生新 epoch，旧场请求不会执行。摘要按有限的资源身份和原因聚合增减数值，不逐步复制整舰，也不混加不同计量单位；检查点载入会核对“初始数量＋变动＝当前数量”。

## 本片冻结的最小政策

1. **换弹与补装**：有待发弹时只能按同配方补一整个批次，容量不足整批拒绝；换弹种须先打空。暂不提供退弹、丢弹或部分批次收费。
2. **时间**：只按模拟固定步推进，暂停不扣时间。装填使用完成步号，冷却使用到期步号，不逐步重写存档或重新核对全舰。冷却允许与装填同时计时；合法战后结算只跳过装填等待，冷却剩余步数保留到新部署，不因读档或结算免费归零。
3. **损毁与顺序**：武器本体、宿主链或已选供弹库损毁，取消受影响装填；不自动改选来源，之后可重新请求装填。损毁与完成同一步时先取消，避免制造免费待发弹。部分耐久下降不取消装填；现阶段不新增弹药库资源灭失或待发弹损失规则，损毁部件保存原量但无法发射/供弹。供电、人员、控制权限与射界等完整动作资格由 P2a 接入，不能用本片底层 `discharge` 当作实际合法开火。
4. **货舱**：容量只按本货舱是否损毁求和，部分受损不按比例缩容；货舱掉电/宿主不可用不消灭货物容积。货舱损毁不取消任何货物预留；即使容量为零，现有材料也能完成已预留装填。不计算货物损毁。
5. **质量和性能**：本片货物质量只作库存派生信息，飞行仍沿用入场已编译质量/惯量，不随弹药或货物消费改变。当前不从弹药资源点猜出重量，也不手填派生飞行性能。X1a 实际装载编译必须定义基准载荷与质量口径；以后如接动态质量，要显式变更政策并验证，不偷偷改变本片操纵表现。
6. **跨场**：新 P1b 技术入场保留冷却，拒绝尚未结算的装填；活动库存检查点用于该域的同场继续。没有瞄准/目标/锁定持久字段。持久实例修订不在实时步或本片结算准备中增加，正式原子提交由 P3 负责。

## 与实时循环的接线

`InventoryBattle.step` 将每舰库存候选状态接入既有 `SimplifiedFlightSession.step` 的投影/提交边界。先同步真正改变的设备域，再完成到期装填、处理库存命令；整步飞行和全部库存命令成功后才提交。后续投影失败、某舰命令失败时全部回退，投影回调也不能私自修改已提交库存。

编译只在入口进行；稳定飞行步仅推进库存时钟并比较最早装填完成步，不解析 JSON、计算来源指纹、扫描货物或拷贝库存。设备修订改变、资源命令、装填到期才处理相关数据。旧编辑合同、默认桌面入口和 E2.3 检查点没有改义。
