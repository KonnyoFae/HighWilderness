# 战略模式接入现有编辑、准备与战术系统

日期：2026-09-12。核对基线：`d6d9221` 与 OP1、ST0 工作区实现。状态：`ST0_SCOPED_PASS / ST1_NEXT`。ST0 双方持久舰船入战及结果关联已完成，见[实施记录](./st0-persisted-encounter.md)。其余步骤仍为规划；战略地图尚未实现。

## 沿用的规则

- 战略世界按舰队组织活动，战术负责小规模交战。按[总规划第六章](../../高天荒野游戏规划归档.md)，进入战术、编辑或特殊事件时暂停战略时间；战略工时只随战略地图推进，不用现实离线时间补算。
- 战术发动机不消耗灵烷燃料；仅燃料槽损毁丢失其中燃料。战略航行耗油另外实现，不回灌战术每步循环。
- 结算前退出丢弃本场临时战况，恢复入战存档；已经保存的战前准备和消费保留。不实现交战中断点续玩。已经生成的待保存结算必须恢复处理，不能以退出绕过战果。
- 结算只完成已开始的装填，保存真实余弹/货物/损管/火情；不免费补给、维修或熄火，不继承瞄准目标与锁定。
- 货物仍为全舰共享容积；超容保留现有库存，禁止新装载。货物燃烧排除，货物损毁暂缓。每层单一填充，微机修复材料不在填充候选中。
- 战略调用设计编译与状态验证应在入场、装卸、损毁、改装等边界发生；不把整舰校验放回无变化的实时循环。

## 实施顺序

### ST0：冻结战略与战术边界，提供可验证的双方入战合同（范围内完成）

本片已复用现有保存与准备层，提供遭遇合同、双方装配与持久回执。9 项 ST0 测试、57 项相关回归及 1 项真实宿主桥接通过，详见[实施记录](./st0-persisted-encounter.md)。战略世界修订与归属目前仅作为调用方输入记录，实际世界验证和战果应用留给 ST1/ST3。

1. 定义版本化遭遇输入：稳定遭遇身份、战略世界修订、双方阵营/舰队引用、舰艇实例及预期修订、各方旗舰、部署配置。场内舰艇身份与持久实例身份建立显式映射，不能依赖列表顺序或技术蓝红舰编号。
2. 定义结果关联：遭遇身份、入场各实例修订、结算身份、应用状态。后续保存结果不得被错误场景/旧修订替换；同一结果重复提交不重复应用。
3. 抽出双方使用相同设计/实例装配逻辑；技术测试入口继续显式提供测试对手，正式遭遇必须提供双方记录，不能缺敌方记录就生成满血新舰。
4. 用两方已保存设计验证入场和结算身份往返。覆盖重复实例、阵营冲突、旗舰不在名单、旧修订及被占用实例拒绝；验证敌方实际余弹/战损可延续到下一场。

退出：后台双方实例装配与身份合同成立，现有战前准备/技术试航回归通过。此时尚无战略地图、移动、经济或正式遭遇 UI；不将此片称作战略模式完成。

### ST1：最小战略地图、舰队与战略时钟（下一片）

交付连续地图中的舰队位置、稳定成员引用、旗舰、目的地、简单航行及地图保存。先用少量锚地和可辨识舰队图标，不等待完整地图美术。

战略世界是唯一战略时间来源；地图暂停/继续与界面切换统一管理，进入战术或管理界面后不偷偷计时。存档保存位置、成员、目的地和战略时间；这是战略存档，不是战斗断点续玩。

总规划要求同一锚地才能分拆/合并，遥控核心适配约束须由已有指挥能力提供依据。首片可只开放单舰队移动；未接合法性前不先提供任意地点拆舰按钮。

退出：航行、暂停、切界面和重启后的状态一致；同一舰艇不能同时属于多个舰队。真实耗油接下一片，开发样例明确标注尚未计费。

### ST2：战略燃料与锚地有限补给

将现有逐槽燃料储备接战略航行消费，按明确的航行政策批次计费；逐槽扣除顺序、缺油停止方式、速度/高度耗油参数先版本化，再接地图。不能只改总量而让各槽库存与总量失配，也不能从高能燃料货物隐式兑换灵烷。

把准备物资来源从技术补给库接到具体锚地的有限库存。装卸、统一弹药、特殊货物、预装与损管准备仍走现有事务，存档重试不重复扣费；不先扩成全商品市场和逐口径采购。

退出：航行真实耗油、暂停不耗油、缺油行为明确、保存往返对账；战术直控仍零推进油耗。补给只在满足地点/来源权限时开放，不允许通过菜单在任意空域免费重置库存。

### ST3：战略遭遇、真实双方交战与战果返回

从地图上的实际舰队生成 ST0 遭遇并冻结战略世界，调用现有战术系统；同一片交付返回链路，不能只开放入战而让战果无法落回地图。

- 入场前持久化遭遇与双方实例引用，冻结修改权限。玩家控制方和对手均使用有限的实际库存；局部部署与地图坐标转换单独定义。
- 正常结算后先保存全体舰艇结果，再确认遭遇应用。若不能同库原子提交，用可重试的持久回执收敛；在结果落库而战略应用未完成时，世界保持暂停，重启后继续应用。
- 退出未结束战斗恢复入场状态与遭遇前战略状态，已付准备不退款。待保存结算不能被这条路径清除。
- 更新可行动舰、失能舰及毁坏舰的战略标记；失能不等于删除资产。旗舰损失、拖救及残存舰队去向按总规划另列明确政策，未实现的处置不假装已完成。

退出：地图遭遇 → 双方实际开火/战损 → 结算 → 返回地图 → 同舰下一场，库存和身份对账；覆盖重复提交、保存冲突、结果保存后中断和退出恢复。采用代表性小规模短测，不设两小时单场门槛。

### ST4：锚地维修、改装与后续战略玩法

审计旧 I2 资源/工时算法并显式适配新合同，先接有限资源维修与完工应用，再做改装、建造、舰队分拆合并。已损毁模块的重建与战术损管维修分开处理，不通过打开编辑器恢复资产。

战略任务、侦察与隐蔽、城镇经济、区域建设、缴获和长期成长随后按玩法优先级拆片。完成前述技术接口与往返仍不等于整个游戏已形成玩法闭环。

## 进入对应片前需要冻结的参数

工程上建议沿用上述顺序；以下具体数值尚未作为本轮实现：战略速度与耗油率、燃料槽取用次序、空油处置、地图尺度及遭遇生成/脱离参数。总规划已有高度层与交战边界描述，须与局部部署及普通炮有效射程一起核对，不能把当前几百米测试站位直接当正式尺度。

火情在战略时间中的推进或冻结、旗舰失能后的处置也需在 ST3/ST4 明确；本轮仅保留既有持久火情，不增加免费熄火或后台离线烧伤。

O4 三舰原生文件往返与关键画布操作留档继续作为独立收尾，不用浏览器自动测试冒充完成，也不阻挡 ST0 后台合同工作。近炸/制导弹、火灾蔓延、燃料爆炸、动态库存质量和完整编队 AI 不作为 ST0—ST3 的前置。
