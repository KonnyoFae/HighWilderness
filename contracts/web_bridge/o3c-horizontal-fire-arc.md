# O3c 水平射界修正（2026-09-07）

原 O3c 只给出了无上层时的参考圆及有上层时的待检查状态，未实现上层船壳遮挡。此次补齐实际水平禁射方向，优先于 O4 收口。

## 共用规则

`gaotian.horizontal-fire-arc/higher-hull/v1`：原点取武器实际安装锚点，舰艏为本地 +Y，角度从舰艏顺时针递增。只取高于武器基底层的船壳轮廓；同层、下层及其他设备不构成遮挡。贴边、顶点相切方向也禁射。

各多边形顶点方位划分精确角区间，使用射线与轮廓相交判定区间并合并遮挡并集，不用固定角度采样遗漏狭小扇区。跨 0° 的扇区分两段返回。`intervals_deg` 和 `blocked_intervals_deg` 共用的端点按禁射处理。

## 编辑器

武器视图升级为 `gaotian.weapon-control-view/v2alpha1`。每件合法武器返回 `hull_occlusion_resolved`、原点、层级、可射/禁射角区间及边界和角度约定。非法安装仍不提供可用扇区。分组资源格式不变。

画布绿色扇区表示可射、红色表示禁射，红色虚线轮廓显示上层船壳投影。扇区只表示方向、不表示射程。旧后台显示更新提示，须显式重启并恢复已提交草稿后加载新计算。

## 实际开火限制

所有单发/批量弹丸生成共用的 `_build_projectile_from_weapon_event` 在使用发射方向时调用同一船壳射线判定；遮挡时抛出 `weapon_arc.hull_blocked`。统一场景在每个发射边界经过该入口，拒绝整个非法步骤，不交付已扣弹药或已推进时间的半完成结果。转向后的判定仍使用舰体局部方向。

低层弹药动作/排队请求只有距离，没有目标方向，不能独立判断射界；它们不是绕过弹丸入口的实际空间发射路径。后续战术 UI 应先用该判定过滤指令，减少整步拒绝，并可在此之上设计自动停火/重新瞄准行为。本次不添加自动选择其他方向，也不重新解释旧队列格式。

## 验证与边界

6 项专项覆盖跨零角、相切与共线、原点位于轮廓内、窄扇区、凹轮廓、并集/排序、层级及非法方向；使用合法三层船壳验证实际场景中朝遮挡方向拒绝且原状态不变、反向正常生成弹丸、舰体转向后的判定一致，并核对实际编辑器预览。

11 / 95 个相关 Python 脚本与 51 项前端测试通过，包含弹药、武器队列、弹丸及统一场景原有回归。完整历史指纹门禁和长战术矩阵本次未复跑，不宣称全量 PASS。原有报告语义内容保持一致。

可复现的便携三层设计：`artifacts/o3c/hull-occlusion-demo.json`。打开后选择 `weapon_upper_port`，查看第 1 层朝舰艏的红色禁射扇区。该文件由程序生成，不计作原生 UI 保存验收。原生操作遇到用户切换窗口后停止，本次未完成扇区实机验收，也没有重启正在测试的后台。

## 下层武器指示圈修正（2026-09-07）

实机确认 `two-weapons.json` 的下层 `weapon.0` 仍收到旧后台的 `requires_higher_deck_hull_raycast`，所以没有可绘制扇区；不是下层武器被计算成零射界。画布属性栏现直接说明该状态需要重启后台并恢复草稿，避免更新提示只出现在下方武器组面板。

另修正前端跨层显示：射界随所选武器在安装层、内部跨层及顶挂部分所在层显示；不能仅用当前层等于基底层作为条件。上层船壳投影始终相对武器安装层筛选，切换观察层不会改变射界规则。武器在当前层不可见时，属性栏明确提示返回安装层。完全遮挡绘制完整红圈，完全无遮挡绘制完整绿圈；未知或非法安装不伪造可用射界。

新增 6 项 SVG 渲染回归，前端共 57 项测试、类型检查和构建通过；6 项 Python 水平射界专项通过。本轮实机核对草稿修订 20、20 个模块，后续操作多次因检测到用户输入中断，尚未完成后台重启和新扇区的实机验收。恢复时应使用该最新草稿，不重新打开磁盘上的旧文件。
