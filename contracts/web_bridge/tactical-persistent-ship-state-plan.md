## 定位与优先级

用户确认：当前全部已开发内容，包括编辑器、准备、交战、损管及持久保存，均属于战术模式；战略模式尚未开始开发。未来大部分战斗是中远距离交战，由战略模式操作和战术模式近距离模拟与演出两部分构成；绝大部分游玩时间在战略模式经过。M5/X1 仍是当前战术模式的技术验证链路，不是完整游戏玩法闭环。

彻底取消两小时测试需求，不保留迁移、发布、可选或按需恢复门槛。单场战术模式最大预期持续时长为 15 分钟，超出须调整整体游戏平衡。已有 E3c 30 分钟结果继续作为特定负载下的工程证据保存，不解释为预期战斗时长。发现内存增长或连续多场资源不释放时，针对实际问题做多场往返与资源释放诊断，不恢复已取消的两小时要求，也不用延长单场时长或扩大交战规模代替战略模式开发。

立项时用户指出：当时没有能够在战术模式中实际使用的武器；此缺口现由 P2a/P2b 的技术普通炮补齐。旧武器公式、弹药契约和人工注入损伤都不能代替可操作武器，也不能作为真实交战毁伤的验收证据。可用武器必须是明确交付项，并作为真实毁伤及战后状态联合验收的前置。

围绕以下数据流，先确定必要状态接口，随后交付可用武器和真实命中毁伤，再完成实际战后保存验证；不先扩建完整存档系统而长期留下不能开火的战术入口：

`持久舰艇实例 → 进入战术战斗 → 实际损伤与消耗 → 战后结果提交 → 更新持久舰艇实例 → 下一场战斗`

战略模式尚未实现时，以最小舰艇实例仓库和明确的测试调用方验证该接口，不虚构战略地图、舰队调度或经济玩法已经完成。

## 立项时的基础与缺口（历史背景，完成状态以上文为准）

- 既有 `ShipInstanceSnapshotInput`、`ShipDesignStateInput` 和 [`高天荒野舰艇实例设计状态.py`](../../高天荒野舰艇实例设计状态.py)已经区分设计来源与当前舰艇状态；优先评估复用、显式适配或具名版本扩展，避免重新制造一套不兼容的舰艇定义。
- 既有 `ShipAmmunitionStateInput` 区分实体弹药库和武器待发弹药，但现有 `MagazineAmmunitionStateInput.inventory` 仍按 `munition_id` 分项；[旧装填结算器](../../高天荒野舰艇弹药与武器动作结算器.py)从匹配弹种的库存逐发扣除。这不符合用户确认的统一弹药资源模式。新路线只复用合适的状态分层、身份与原子操作机制，必须适配装填成本/批次和库存合同，不能直接沿用旧扣弹算法。
- E2.3 [`tactical_checkpoint.py`](../../backend/high_wilderness_sidecar/tactical_checkpoint.py)可保存船壳完整度、逐模块耐久、推进阶段、人员/供电及指挥状态，用于同一场战斗的检查点恢复；它没有弹药/弹丸/火灾状态，也没有跨战斗结算与持久仓库。
- 当前实时入口仍由固定样例创建舰艇，缺少从持久受损舰艇构建新战斗的入口。不能每次重建完好技术舰替代载入当前状态。
- 当前战术界面没有可完成武器选择、指定目标、发令开火、观察弹丸及毁伤的实际操作链。编辑器能放置武器、分组或显示射界，不等于这些武器已经能在新实时战斗中使用。
- 旧 `BulkCargoLoadInput` 以 `storage_instance_id` 将货物绑定到具体货舱，并只记录 `mass_kg`；货舱使用 `bulk_cargo_capacity_kg` 限制质量。这不等于用户确认的全舰共享容积库存。新合同需要货物种类/数量/单位容积及共享库存，并显式适配旧合同；不能把旧 kg 字段直接解释为 m³。

## 三种数据的职责

| 数据 | 职责 |
| --- | --- |
| 设计资源 | 船壳、栖装、材料与模块精确版本，定义构造、容量与能力上限；不会因一次战斗被改写 |
| 持久舰艇实例 | 跨战略回合及多场战斗存在的同一艘舰，保存损伤、消耗、当前装载和存续状态；将来由战略系统掌管 |
| 单场战术会话 | 场景身份、位置速度、弹丸、当前目标、输入队列等战斗过程；只服务当前交战，不要求同场检查点。结算前退出恢复入战存档 |

持久实例 ID 与本场 `scene_id/epoch` 分开；每次进入新战斗保留舰艇身份，产生新场景身份。场景内模块必须映射到持久模块实例，不能依赖临时数组位置或显示名称。

用户最新确认：合法战后结算默认完成已开始但尚未结束的装填，按其配方将已预留的弹药资源/特殊货物消费一次并增加待发弹，再保存结果；不等待剩余模拟秒数，不在下一场重复扣费，也不自动将所有未开始装填的武器额外补满。武器已毁或装填已取消时执行对应取消规则；资源/预留不一致不得凭空生成炮弹。P1b 建立这一完成事务，P3 在结算边界调用。

冷却、持续火灾、伤员及其他退出后的未完成过程仍须随相应规则接线定义持久归属和时间换算；这次装填完成规则不自动清零所有冷却/持续过程。未适配的活动状态应明确拒绝该种导出，或通过已定义结算规则处理；不能丢字段后声称保存成功。原战斗绝对步号不直接成为下一场的到期步；战斗耗时可提供给战略时间映射，但本片不自行设定战略时间倍率。

## 战后提交边界

1. 入战时绑定参战实例的 ID、修订及当前状态摘要，阻止同一实例被两个战斗或修复/补给事务同时无声修改。
2. 在合法战斗结束或撤离边界停止接收新操纵，取消未执行命令，从最后已提交的权威边界生成战后结果。界面关闭、断连和进程崩溃只触发现有暂停/恢复，不自动算作战斗结算。
3. 结果携带唯一结算 ID、战斗 ID、参战实例基准修订、最终状态及必要来源。以最终状态更新为主，不向舰艇重复叠加伤害/扣弹差值。
4. 仓库先完整验证参战集合和版本，再将实例更新与“已应用结算”记录一起原子持久化；同一结算重试返回已应用结果，同 ID 不同内容或旧实例修订必须拒绝。不能出现只扣了部分舰弹药或记录提交却没保存损伤的半完成结果。
5. 下一场只从已提交的持久实例建立舰艇，重新编译/验证资源并重建能力。新位置、部署朝向和操纵初态由具名入战规则提供；不能从完好蓝图重新生成耐久和弹药。

先复用本地原子文件写入能力和最小实例仓库；此接口供未来战略系统调用，不以先做完整战略 UI 为前提。后续修复、补给、改装分别通过有来源的实例修订事务改变状态。

## 货舱模式：全舰共享容积与可变库存

用户确认以容积简化货舱：每个安装货舱提供一定可用容积，全舰相加；每种货物定义每计量单位占用的容积，库存按货物种类与数量聚合，不再要求玩家或后台把每件货物分配到具体货舱。此项取代此前“特殊弹材料按来源货舱逐舱记账”的规划；货舱保留模块身份用于耐久和容量贡献，货物预留绑定舰艇库存与动作批次。

- `总可用容积 = 各有效货舱的容积贡献之和`；例如 1 格且高 5 m 的货舱按 `5 × 5 × 5 = 125 m³` 提供容量。其他尺寸由货舱原型明确声明可用容积，不能只凭二维占格推断所有部件的高度或重复计算跨层占用。
- `已用容积 = Σ（货物数量 × 对应单位容积）`。新装载必须满足装载后已用容积不超过可用容积；恰好装满可接受，超限整批拒绝。数量和容积采用明确整数/定点单位，货物单位容积为正；可分割货物另定义最小计量单位，不做货物三维摆放或装箱模拟。
- 普通弹药资源仍由弹药库承载，已装入炮弹由武器承载，不重复占用货舱。特殊材料、作为货物的损管配件等才占用共享货舱；物资被装填或维修实际消费时释放相应体积，预留阶段仍在库存中、仍占体积。`可消费数量 = 当前库存数量 − 已预留数量`，不把预留重复计入库存或容量。
- 质量与容积分别计算。容积是本方案的货舱装载限制；货物若参与舰重等已有性能规则，保留单位质量并按数量派生总质量，不把容积当质量，也不把旧逐舱 kg 限额继续暗中作为新货舱的第二道限制。既有舰艇整体航行约束独立评估；战术货物变化是否更新飞行质量在相应接线时明确，不能静默更改当前推进政策。

P1 加入全舰库存、容量贡献和货物增减/预留的最小状态接口。入战编译货物身份、单位与容积，正常飞行不重扫库存；只在货物事务或货舱状态变化时更新受影响数量、已用/可用容积与版本。战术特殊装填、损管等已实现动作使用该入口，战后结果保存同一份真实库存。增减动作保留来源和原因，负数库存、重复消费或无来源增货必须拒绝；未实现维修、补给、拾取或掠夺不因存在接口就被视为可用玩法。

用户已确认当前货舱战损规则：部分掉血不按比例缩容，损毁时失去该货舱的容量贡献，保留共享库存和现有货物预留。若容量下降后已用量超限，明确保存战损超容状态，禁止新增装载，允许正常消费/卸载使其下降；不能阻止战后保存或下一场载入、自动补回容量或截断库存。即使所有货舱损毁、可用容积降为零，也按同一规则保留和消费现有库存。只有后续装载满足容量限制时才能新增货物。P1 必须允许表示容量下降这一事实，不能以旧正常装载校验拒绝真实战损。

货物损毁规则明确暂缓，不列为 P1—P3 的实现或验收前置；当前不计算货舱受击导致的货物灭失、比例损耗或对应预留损失。容量变化本身不消费货物、不取消货物预留，结算仅反映容量变化及实际已接动作的消费。武器损毁或装填取消仍按该动作的预留释放规则处理，不与货舱容量损失混为一谈。

旧按舱质量载荷仅在具备货物种类、单位质量/容积与数量转换规则时显式迁移到共享库存；信息不足则报告需补充的资源定义，不静默按质量数值生成件数或体积。

## 战后结算画面与保存职责

建议纳入 P3 的必要可测试界面：逐舰展示本次交战造成的损伤和资源变化，作为未来返回战略模式的衔接点。画面读取权威结果；战术动作发生时已经结算实际消耗和损伤，战后只汇总并持久提交最终状态，不能到打开画面时再根据发射次数重新扣一遍资源。

| 画面内容 | 展示口径 |
| --- | --- |
| 舰艇概况 | 名称/身份、存续或撤离结果、船壳完整度前后值、受损/损毁模块 |
| 逐项资源 | 每舰每种资源的战前数量、本场增加、消费、损失、战后数量和净变化；默认突出变化项，可展开全部资源 |
| 弹药与待发弹 | 弹药资源点与各武器待发弹种/发数分开列；装填成本和实际发射发数分开，不能把资源点与发数相加 |
| 货物及损管配件 | 使用共享库存原条目，按用途分组展示即可；作为货物的损管配件不在另一账户重复计数。可展开特殊装填、维修、损毁等实际已接原因，未实现用途不伪造消耗 |
| 货舱容量 | 战前/战后已用与可用 m³，显示货舱损毁造成的容量下降及超容状态 |
| 保存状态 | 正在保存、已保存或保存失败；失败给出原因和重试入口，成功后可返回并用于下一场 |

冻结入战基线与合法结束边界的最终状态，按稳定身份和各资源单位生成汇总；每行满足 `战后 = 战前 + 增加 − 消费 − 损失`，净变化为战后减战前，预留单独显示且不算已消费。只有已提交动作进入统计，取消动作和重复命令不计入；资源转换的输入、产出分属各自条目，以同一动作关联。可维护按原因聚合的计数及必要来源，无需为了结算保存每步完整快照或无限事件列表；汇总必须与最终状态对账。

建议流程为 `合法结束 → 冻结并生成可恢复结果 → 自动提交持久状态 → 展示/更新结算与保存状态 → 返回`。打开、关闭、重开画面或点击“继续”均不产生新一笔结算；不增加逐舰确认扣资源流程。原子保存同时写入舰艇状态、结算身份和可重看摘要，回执丢失可查询同一结算；提交前失败保留可恢复结果并重试，不能放行下一场使用旧状态。界面崩溃不应使结果丢失或重复消费，保存失败也不能显示“已保存”。多人控制、完整战利品分配、修复/补给操作面板后续再接，不阻挡当前小规模交战状态保存。

## 弹药模式：统一资源与武器装填批次

用户确认沿用简化后勤模式：弹药库部件提供统一的弹药资源容量与当前储量，不要求玩家按各种口径、弹种或武器型号采购和分配不同炮弹库存。同舰符合供弹条件的弹药库仍可形成共享可用资源池；保留每个部件的物理余量是为了容量、供弹中断与局部损毁结算，不增加玩家手动分库负担。

口径和武器种类决定装填规则。每种武器在资源中定义精确版本的 `单批资源成本 C`、`单批装入发数 N`、`待发容量` 和 `装填时间`。这些是待冻结的概念字段，不表示代码已有对应接口。

| 示例（仅解释机制，不是平衡数值） | 消耗统一资源 | 增加待发弹 |
| --- | --- | --- |
| 小型武器弹仓 | C 点 | 一仓若干发 |
| 连射武器弹链 | C 点 | 一条弹链几十至上百发 |
| 大口径主炮 | 数点资源 | 一发炮弹 |

一次完整装填的资源转换为 `可用资源减少 C，武器待发数增加 N`；射击 k 发只使待发数减少 k。不能因为一条弹链含很多发就重复收取每批成本，也不能把主炮强制套成“一点资源一发”。资源数使用明确的整数单位或定点最小单位，批次成本与发数分别精确计账，避免按单发浮点成本反复舍入。

装填在唯一权威提交边界原子扣除来源资源并增加待发数；如装填开始时需要预留，预留来源与批次必须进入状态，多个武器同时装填不能重复占用同一资源。资源不足、供弹不可用或待发容量不足时明确拒绝，不能截断批次却仍收取整批成本。部分补弹、换弹、装填中断与损毁时的预留处理在 P1/P2a 冻结；未支持的操作明确限制，不静默丢弃已有待发弹，也不产生免费弹药或重复退款。

弹丸的穿深、伤害、速度和引信等仍由武器/弹丸配置决定，这是战斗计算所需的内部资源。它们不转化为弹药库内分别管理的库存类别。首版 UI 显示全舰可用弹药资源，以及各武器待发量、单批装填成本/数量和进度，不增加按口径管理炮弹的后勤面板。

战后与跨战斗保存保留弹药库剩余资源、武器未打完的待发弹，并在合法结算时完成尚在进行的装填；当前交战内保留装填/预留进度，不要求同场存盘续玩。例如上一场装好弹链后只打出一部分，下一场仍保留余下弹链，不重新收取其装填成本，也不恢复弹药库已消耗的资源。装填资源消耗、发射发数与损毁损失分别留账，按各自单位核对。

这是用户确认的玩法口径，不以旧代码的逐弹种库存反推设计。旧合同、资源和历史黄金保留原语义；P1 明确新接口/政策版本和适配范围。现有按弹种库存不能在缺少转换口径时任意一比一变成资源点，不做静默迁移；先使用具名、按统一资源构造的有限技术装载。

### 特殊弹扩展：从货舱消费对应资源

用户补充要求：为特殊弹预留装填时消耗货舱货物的接口，延续统一弹药资源模式，不增加各口径成品特殊炮弹的后勤库存。按“基础弹药资源＋特殊货物”的配方扩展装填：普通弹的附加货物成本为空；特殊弹装填一批时，除基础弹药资源外，消费配方指定的货物。具体数值后续标定。

| 特殊弹示例 | 附加消耗的货舱资源（数量待定） |
| --- | --- |
| 燃烧弹 | 高能燃料 |
| 穿甲弹 | 特殊合金 |
| 近炸弹 | 先进引信 |
| 制导炮弹 | 电子元件 |

接口预留以下概念字段，P1 冻结最小合同，不代表现有代码已经支持：

- 装填配方具有稳定身份和精确版本，关联适用武器、装入弹种/弹丸配置、基础弹药资源成本 C、装入发数 N、装填时间，以及可为空的附加货物成本列表。列表项使用稳定货物资源身份、数量和计量单位，支持同一批次需要多种货物；不按上述四种示例写死分支。
- 货物来源是本舰共享货物库存，按稳定货物资源身份记账，不绑定具体货舱；库存及必要预留与动作批次关联。弹药资源点与货物各自的单位保持独立，不直接相加，也不复制一份可重复消费的“特殊资源余额”。
- 资源配置与配方在入战等边界验证并预编译；装填请求、库存/供给状态变动时检查数量和可用性，不在每个稳定模拟步重新解析整舰配方与货舱。

一次特殊装填将基础弹药资源、所有附加货物和新增待发弹作为同一事务提交。任一资源不足、来源不可用或待发容量不足，整批拒绝，不先扣普通资源再发现缺货。如采用开始时预留，所有来源统一预留并绑定装填批次，完成时只消费一次；多个武器竞争同一货物时不得超额占用。中断或武器损毁时如何处置预留，沿用 P1/P2a 冻结的动作取消规则，不能重复退款或返还已完成装填所耗材料。当前货舱损毁只减少容量，不扣货物、不取消货物预留；超容不阻止使用现有材料装填。发射只扣对应待发弹，不再次消费货物。

选择特殊弹配方只改变后续装填意图，不能将现有普通待发弹直接改名为特殊弹。保存“选择的配方”和“实际已装入弹种/数量”两种不同状态，已装入弹可按同类批次聚合，无需为每一发建立独立库存对象。首个特殊弹接线切片可限制单一弹种、待发清空后再换装；带弹换装、卸弹回收或混合弹链未定义前明确禁用，不能免费转换、静默销毁旧弹或凭空返还材料。

当前战术状态保留货物余量/预留、实际待发弹种和数量、活动装填配方版本、来源及进度，不新增同场检查点要求。合法结算按最新规则完成进行中的特殊弹装填，再保存已完成转换的特殊弹和剩余货物，不恢复所耗货物，也不再次收费。弹药资源消耗、逐类货物消耗、实际发射及损毁损失分别核对。装填燃烧弹消费货舱高能燃料属于明确的装填动作，不改变“战术推进忽略燃料消耗”的既定规则。

范围：P1 预留可选配方成本、共享库存来源、待发弹种及活动装填状态；P2a 普通炮使用空附加成本走同一合同，并用小型合同用例验证扩展能力。特殊弹的可选 UI、真实货舱消费及各自毁伤/引信/制导效果在后续切片接入，不要求先做完四类武器效果才能交付普通火炮。尚未接线的非空货物成本或特殊弹配置必须明确拒绝，不能忽略附加成本后照常开火。

## 可用武器与真实毁伤的最小交付

首批使用一种具有明确原型、内部弹丸参数和有限初始弹药资源的普通火炮，装填成本/数量遵循上述统一资源模式。优先适配已有资源与计算规则，技术数值明确标注，不将本片扩成全武器设计或正式平衡标定。

玩家必须能在实验战术界面完成默认自动火控和手动瞄准两种操作，看到炮塔实际转向、弹丸运动和发射结果，并查看待发弹药、库存及装填/冷却状态。两种模式均属于 P2a 首批必需范围，替代此前仅“选择目标、单次开火”的交付要求；不以完整 RTS、导弹或复杂舰队 AI 为前置。

### 火炮操作：默认自动火控与手动瞄准

| 模式 | 玩家输入 | 权威行为 |
| --- | --- | --- |
| 自动火控（默认） | 右键点选本舰可控火炮，左键点击敌舰或特定模块指定目标 | 保持攻击目标，依据可用的目标位置/速度及炮弹弹道计算提前量，自动转炮；瞄准、射界、装填/冷却、指挥等条件满足时自动开火，并按既定批次成本装填后续弹药 |
| 手动瞄准 | 明确切换所控火炮为手动，鼠标在战术画布上给出瞄准位置，按下左键开火 | 炮塔朝鼠标对应的世界位置转向，玩家自行判断提前量；一次按下生成一次武器规定的射击请求，按实际炮口朝向发射，不自动追踪/修正到敌舰 |

自动模式是“指定目标后自动瞄准开火”，不要求首版自动搜敌。没有有效指定目标时不发射；射速和装填时间决定后续动作，不能按 UI 帧率重复发射。可显式停止攻击/清除目标；目标失效或模块已毁时停止对该目标开火并给出反馈，不擅自换打另一模块。短时超出射界等条件只暂停发射，条件恢复且攻击命令仍有效时继续。

炮塔静态规则在 P1/P2a 明确并预编译：可用转角范围、转速、安装朝向、炮口位置及适用瞄准条件；缺失参数使用具名技术配置，不宣称旧代码已有完整提前量与炮塔运动。实际炮塔角度、期望方向、控制模式、攻击目标/命令和手动瞄准点属于战斗动态状态。目标模块使用舰艇 ID＋模块 ID，按当前火控质量允许的舰艇姿态/运动估计更新瞄准位置与速度，不能一直瞄准点选时的旧坐标，也不能绕过降级误差。

自动提前量根据适用弹道模型及当前火控质量所允许的目标估计解算，考虑自身运动对弹丸初始状态的既有规则。未锁定或雷达损毁应进入下述降级火控，不一律拒绝普通火炮开火；只有连最低可用目标估计也没有，或无合法射击方向等条件不成立时才暂停。目标持续运动、炮塔尚未对准、弹丸飞行和目标之后的机动均可能造成偏差，正常锁定也不保证必中。对移动目标的瞄准与转炮是持续过程，即使玩家不再点击也须更新；只重算相关武器/目标的动态计算，不每步重新编译整舰。

#### 自动火控精度与雷达锁定

用户确认：自动模式的瞄准、提前量及开火精度由当前目标的火控锁定状态决定。此为 P2a 首批规则，不能后置为纯显示提示或完整雷达/EW 系统的扩展项。

| 精度档 | 适用状态 | 提前量与射击行为 |
| --- | --- | --- |
| 正常 | 有可用火控雷达对当前目标的有效锁定 | 使用正常质量的位置/速度估计计算提前量，采用正常火控误差；仍保留武器本身的固有散布和正常弹道限制 |
| 降级 | 尚未锁定、失锁，或来源雷达损毁/失效且无其他有效锁定，但仍有粗略目标信息 | 共用降级配置，以较低精度的位置/速度估计求提前量并增加火控射向误差；普通火炮仍可按正常武器时序自动开火 |

用户已确认精度只有“正常”和“降级”两档。未锁定、失锁和无替代锁定时的雷达损毁共用降级档，仅分别记录/显示原因，不增加第三档、连续锁定质量曲线或各原因独立的精度等级。“目标信息失效”是无法继续自动瞄准的可用性状态，不是第三个精度档。

降级档的位置估计误差、速度估计误差与附加射向误差作为可调技术参数，具体数值在 P2a 可操作后调试，不以正式命中率标定阻挡开工。P1 先明确字段、单位、约束及配置版本；P2a 使用明确标记的初始技术值做正常/降级对照。观测更新周期和估计有效期作为支持参数分别定义，不借此新增精度档。每个验证场景绑定确定配置，后续调参保留版本和测量来源，不能静默改变已保存场景的误差政策。

降级同时影响运动估计和最终射向误差，不能只更改 UI 或命中后随机减伤；误差应实际反映到瞄准点和弹丸初始射向，通过碰撞自然决定命中。正常档保留已有适用的正常误差和武器固有散布，不代表必定命中。

锁定与目标、来源雷达及火控分配关联，由后台根据实际观测/设备状态产生；选中目标、装有雷达或锁定另一艘舰都不等于当前目标已锁定。模块瞄准采用其所属目标舰的有效观测质量，不因点中模块获得精确运动信息。还有其他有效锁定来源时可按明确来源选择规则继续正常解算，不能任一雷达损毁就降低全舰所有武器精度。

降级估计需携带信息来源、采样时间、位置/速度及质量。失锁后可按有期限的旧观测外推或现有粗略观测更新，误差/有效期依据质量配置；不能读取场景真值持续做精确提前量，再把模式名称写成“降级”。目标长期不可观测、估计超期后明确暂停自动攻击，不能永久追踪不可见目标；“没有雷达锁定”与“完全没有可用目标信息”分开判断。最低范围不要求完整观测共享、EW 或自动搜敌，可先适配已有本舰观测及锁定机制。

火控误差与武器固有散布分开配置，合成时明确口径，避免同一误差重复施加。若使用随机误差，采用可重放的战斗种子和观测/射击身份，在实际更新或提交边界取样；不因 UI 刷新、失败重试、切换模式或重读存档重新抽样。当前会话保留必要的估计质量、来源/时间和随机状态或等价可重建身份；不要求将它们持久化以恢复同场；跨场重新建立锁定，不继承旧场目标锁定资格。此次要求针对自动火控，手动仍由玩家给出瞄准方向，不擅自增加雷达失锁强制偏移鼠标；武器固有散布与设备限制在两种模式下都有效。

设备失效、锁定获取/丢失、来源变化及估计过期触发受影响武器的质量更新；运动预测与转炮仍按约定时序推进。雷达损毁后的下一次发射判定必须使用新质量，已经发射的普通炮弹不追溯改写。界面显示“已锁定 / 未锁定·降级 / 雷达失效·降级 / 目标信息失效”等状态，并使期望瞄准点或误差范围反映当前质量。

旧[观测与火控模块](../../高天荒野舰艇战术观测与火控.py)已有目标、跟踪/锁定与来源分配，但 `validate_weapon_fire_control_support` 对缺少必需支持会直接拒绝。P2a 须显式新增或适配普通火炮的降级政策，不能直接套用该硬拒绝路径，也不能全局删掉旧支持检查；其他武器的必要制导/照射要求不随此次普通炮规则取消。P1 先预留质量配置及战斗状态字段，P2a 接真实锁定状态与质量计算，P2b 用实际命中雷达验证降级。

手动模式将画布鼠标位置转换为世界瞄准点，不把像素坐标传入物理规则；转炮受同样的机械转速、射界和上层遮挡约束，鼠标跳到另一侧不代表炮口瞬时跳转。手动开火无需绑定敌舰目标，但仍需满足指挥、设备、弹药/冷却及适用安全条件；不能因未选敌舰而拒绝所有手动射击，也不能绕过己舰遮挡向禁射方向开火。瞄准点与实际炮向分别显示，让玩家能判断炮塔是否已经跟上。

交互接线必须改造当前“左键只选舰、任意按钮拖动平移”的画布输入：武器操纵时右键单击负责选炮，自动模式左键负责选目标，手动模式左键负责发射；相机平移使用中键等不冲突入口，滚轮继续缩放。舰艇观察选择与攻击目标分开。模块点选有明确高亮及身份，重叠/跨层用层选择或候选列表消歧；点击 UI、拖动镜头或切换模式不能同时触发一次开火，鼠标离开画布/失焦时不生成新手动射击。

模式和目标变更使用可靠、可去重命令；连续鼠标瞄准采用有界最新值更新，手动击发单独可靠提交，使用执行边界的实际炮向并遵循已定义的输入顺序。模式切换在权威边界原子生效，同一火炮不能同时被自动和手动两套来源驱动；切入手动终止该炮自动攻击，返回自动需重新明确目标，不能补发旧手动点击。切换不重置炮塔角度、弹药或装填/冷却，也不影响未被接管武器的有效命令。

暂停时炮塔、装填与射击不推进；断连或切离按现有规则暂停，显式恢复后才可继续有效的自动攻击，不重放已经执行的点击。不要求单场检查点或双模式存盘续跑；跨战斗持久实例保留弹药与必要进度，但不直接沿用上一场目标 ID、鼠标位置或未执行击发。新场默认自动模式且未指定目标，炮塔初态与其他部署状态由明确入战规则提供。

### 武器与毁伤接线要求

| 环节 | 必须实现的行为 |
| --- | --- |
| 武器与弹药准备 | 入战预编译武器、内部弹丸参数、装填批次规则及安装位置；建立各弹药库的统一资源余量与各武器待发发数，使用有限技术装载 |
| 控制与瞄准 | 默认自动模式按指定敌舰/模块解算提前量、转炮并开火；手动模式朝鼠标转炮、左键击发。两种模式共用真实炮向、资源和合法性检查 |
| 火控质量 | 当前目标有效雷达锁定使用正常提前量/精度；未锁定或雷达失效使用粗略估计和更大的火控误差，只要最低目标信息及武器条件有效仍可开火；按来源和目标更新，不使用全舰单一锁定开关 |
| 发令与合法性 | 发射前检查指挥权限、武器可用性、弹药、装填/冷却、射界及既有火控条件；向上层船壳禁射方向开火须有明确拒绝原因 |
| 装填与实际发射 | 装填按批次扣统一资源并增加待发弹；在权威发射边界原子减少待发弹并生成弹丸，不重复扣库。命令被接受不等于动作已提交，重复命令/回执丢失不重复装填、发射或消费，失败不交付半次操作 |
| 弹丸与画布 | 弹丸从实际武器位置出发，按固定步推进；画布显示其运动和命中/未命中结果，视觉效果不决定权威碰撞，不要求完整尾迹爆炸美术 |
| 命中与伤害 | 根据实际目标船壳和模块位置求命中，接入既有装甲/弹种规则，将结果写入船壳与相关模块耐久；被装甲阻挡的命中不能一律伪装成扣血 |
| 受损后反馈 | 显示命中部位及损伤结果；发动机损毁影响实际推进/转向能力，武器损毁阻止其继续开火，必要指挥失效沿现有规则生效 |
| 持久数据来源 | 战后状态直接取自实际弹药账本与毁伤结果，记录来源边界；不能另写“测试用扣血/扣弹”替代真实过程 |

武器资源、弹药状态和损伤结果从本片开始使用 P1 的稳定舰艇/模块身份，避免完成武器后再重写持久映射。未支持的武器类型明确限制，不用普通炮弹适配伪装完整武器系统。

## 针对性验证

- 锁定精度：相同技术武器/运动场景覆盖正常锁定、未锁定、失锁、来源雷达损毁和重新获得有效锁定，核对估计/射向误差参数与实际结果；只有正常/降级两档，所有无锁定原因引用同一降级配置，目标信息失效不额外生成精度档。降级仍产生合法射击，不能仅通过禁止开火制造精度差异。用固定种子及独立预期核对误差，不要求每一发正常锁定都比降级更接近目标。覆盖锁错目标、指定模块、备用有效来源、估计超期、暂停/重载及重复命令，界面与随机结果不漂移；P2b 由实际弹丸命中雷达触发后续发射降级，已发射弹丸保持原状态。
- 双模式火炮：新场默认自动且无目标；右键选本舰火炮、左键分别指定移动敌舰/模块，核对提前量、实际炮向、自动射速及装填消费。手动鼠标跟随与单次左键发射不依赖敌舰绑定，受机械转速和己舰遮挡约束。切换模式/目标、目标失效、失焦、暂停恢复、重复/迟到输入、低频瞄准更新均不能造成双重发射或瞬时转炮；模块重叠点选和镜头/UI 操作不误发射。P2a 验证真实发射，P2b 再验证真实命中，不以只做按钮单发替代双模式验收。
- P1 可用船壳 72%、某发动机损毁等人工样本做字段往返检查；P2b/P3 则必须使用实际发射和命中产生的损伤，不能为凑指定比例直接修改 HP。写入与重启后仍是同舰同模块，下一场能力与损伤吻合。
- 同一统一资源池分别按“小型弹仓一批多发”“弹链一批大量发数”“主炮多点换一发”的具名规则装填；这些装填合同用例不要求先把三类武器全部接入 UI。验证不同 C/N 配比、容量不足和多武器资源争用，不能退化成统一逐发扣点。
- 实际装填只扣一次资源，射击只扣待发弹；保留未打完的弹仓/弹链，跨场景不补满、不再次收取已完成装填的成本。资源消耗、发射数和损毁损失分别核对，旧按弹种库存不可静默一比一导入。
- 特殊弹接口用例覆盖空附加成本、单种/多种货物、货物身份与单位、实际待发弹种及预留往返；未接线配方明确拒绝。后续接入真实货舱消费时，再验证缺货整批不扣、并发预留不超额、重复命令不重复消费、中断/来源损毁按政策处理，以及跨战斗不返还货物或重复收费。切换配方不能改变已经装入的弹种，也不能据接口测试宣称特殊弹战斗效果已实现。
- 两舰结算中任一实例版本冲突，整批不落盘；中途写入失败保留可读取旧状态；保存成功但回执丢失可安全查询/重试。
- 共享货舱验证：两个 125 m³ 货舱提供 250 m³；单位体积 5 m³ 的同类货物可装 50 件，第 51 件拒绝。另覆盖混合货物、零货舱、恰好装满、消费释放容量、预留不释放容量及存读后数量/容积一致。部分掉血不缩容，损毁只减容量、库存和货物预留不变；全部货舱损毁后仍可保存/载入及消费现有库存。超容禁止新装载，不能借修复或重建自动增加货物；不增加货物毁损算法用例。这些合同样本不替代实际战斗消费验收。
- 结算画面每舰各资源的前后值、分类变动和最终存档一致；资源点、发数、货物计量单位与 m³ 不混算，损管配件同一货物不重复入账。覆盖零变化、资源转换、已定义损失、战损超容，以及提交前失败、提交后回执丢失、重开画面和连续多场；重试不能修改结果或产生二次消费。
- 新战斗拒绝旧战斗输入；同一结果重复应用无副作用；已毁舰不能无授权重新以完好状态出战。
- 区分结算前退出回到入战存档与已生成结算的重启恢复；不要求同场检查点续玩，重开结算不得重复消费或提交。
- 性能重点是代表性小规模交战、保存/载入/结算延迟及重复进入/退出后的内存/资源释放。场次数与短测时长按具体负载确定，单场按最大预期 15 分钟设计，两小时测试需求彻底取消。必要时通过多场测试覆盖长期应用驻留。
