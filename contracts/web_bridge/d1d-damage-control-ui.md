# D1d 损管准备、操作与结算界面

日期：2026-09-11。状态：`D1D_UI_SCOPED_PASS`。承接 D1a—D1c 后台规则，交付玩家可操作的战前准备与旗舰损管界面。仍是编辑器、战术及战略衔接基础设施，不表示战略玩法已经实现。

## 玩家操作

1. 在战前准备中导入包含损管设备的栖装设计，新实例采用 `d1c-preparation-policy.v5.json`，保留穿甲弹能力并启用有限损管资源、火灾与维修。
2. 装载工程零件；空设备可勾选“预准备”，每具当前消耗 2 份零件准备 100 点资源。已有余量不能补满。核对时显示缺料，提交后一次性更新全部舰船及共享物资，预准备不会执行维修。
3. 进入交战并开始运行后，在“旗舰损管”中启动设备，选择自动维修或本舰部件。启动同时通过设备资源域申请 active 模式，照常计算供电与人员需求；不绕过毁伤、失控或人力不足。
4. 显示设备资源（最小 0.001 点）、火情、维修目标、待机/工作/不可用原因、准备剩余时间以及工程零件可用与预留数量。灭火抢占维修，耗尽后自动尝试准备；关闭取消未完成准备、释放预留并关闭设备。暂停冻结全部推进。
5. 结算逐舰展示工程零件与设备资源变动，区分准备、灭火、部件维修和船壳维修成本；耐久表显示伤害与修复后的净结果，不把净变化误称为总维修量。未灭火情保留。保存后重新准备、再入战，耐久和物资保留，启动/目标意图重置。

只操纵旗舰损管；未增加对其他友舰的远程损管命令。技术试航旧舰仍使用旧配置，测试此功能应从战前准备导入新实例。普通弹/穿甲弹没有新增点燃效果；界面验证使用独立目录中的真实初始火情与受损部件，不向玩家 RPC 开放测试点燃。

## 接线与兼容

- `tactical.realtime.damage_control` 只接受 enabled / repair_target，并校验场景、运行代次、顺序与本舰身份。精确重试可在暂停后查询，冲突或旧代次的新输入拒绝。丢失回复时界面读取当前状态，不自动重复发令。
- 启停先记为待执行命令，资源模式操作在下一原子步骤执行；实际模式变化、修复与库存扣费一并成功，失败不消耗或丢弃待执行操作。停止准备的取消沿用库存原子事务。
- 新旧设计继续绑定各自保存的策略；导入请求重试优先返回既有实例，不以新默认策略重新编译旧实例。没有免费的存量舰船迁移。
- 有限测试物资库首次扩展时，仅为新增货物“工程零件”增加 100 份。已有弹药、合金余量不变，后续重启/准备不再补给。新增供给提升供给版本，旧的未提交草稿需要重新核对；已保存回执与旧舰战损保持。
- 共享供给允许包含本次舰队不支持的货物，但必须通过供给自身定义校验；本舰只能装载自己定义的货物，跨舰同名货物的单位必须一致。旧舰单独准备、新旧舰共同准备均保留未使用的工程零件供给。
- 结算后的旧准备回执不是新战斗授权：必须根据当前舰船状态再次准备，避免使用旧修订覆盖战损。
