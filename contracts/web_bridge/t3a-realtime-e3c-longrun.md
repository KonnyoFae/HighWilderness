# E3c 长跑准备与真实后台验证

当前调度修正（2026-09-10）：用户确认战术为小规模交战，取消固定 2 小时迁移门槛，优先 [P1—P3 战后舰艇状态与跨战斗衔接](./tactical-persistent-ship-state-plan.md)。下文保留本次测量时的阈值、结果与当时接续安排；其中 2 小时必经门和 E4a 优先顺序已被本修正取代，原始测量证据不改写。

日期：2026-09-10。基线：`400105f` 加本片测量工具。状态：`E3C_STDIO_30MIN_PASS / E4A_NEXT / FULL_E3_NOT_PASSED / DEFAULT_BACKEND_NOT_MIGRATED`。

## 本片范围

沿用 [E3b 实验入口](./t3a-realtime-e3b-view.md) 的真实 Python sidecar、标准 JSON 行协议、领域线程、60 Hz 调度器、静态资源和低频显示发布。独立客户端持续收取与确认快照、回执、可靠事件；所有操纵通过公开实验方法进入，读取不驱动物理步。使用原具名两舰样例，战术推进不消耗燃料。

本片不修改产品模拟规则，也不增加前端必须调用的诊断接口。[观测子进程](../../tools/realtime_longrun_probe.py)只在测试进程内给原队列和实验服务附加有界计数。队列峰值在原队列锁内更新；每次 pump/请求后观察领域容器，每秒记录一次内存和状态。观测本身耗时包含在真实后台运行中，没有全量参考重放、逐步来源指纹、对象遍历或性能剖析器。队列、回执、事件与显示缓存的条目数用于核对保留上限，不把 GC 分配次数当作存活对象数。

进程 RSS 和 Windows private bytes 同时采样；只测后台进程，不包含客户端日志、浏览器、Rust 宿主或 GPU 内存。本轮不会据此宣称原生画布长时间运行或完整 E3 全项通过。既有 E3b 浏览器与 Rust 联调证据继续适用其短时范围。

## 运行前冻结的口径

正式运行 1800 秒墙钟，包含正常飞行及明确安排的暂停时间；报告同时给出实际提交步数。每 60 秒重复以下周期，整个过程交替全速/半速推进、顺逆时针转向与解除转向，每约 2 秒发出一次操纵。

| 时间与动作 | 检查 |
| --- | --- |
| 平常约 15 Hz 读取 | 场景身份和步号不回退，静态缓存命中，可靠事件连续，执行回执与指定步一致 |
| 周期第 40—45 秒降为 2 Hz 读取 | 允许显示覆盖旧帧，可靠结果须保留并确认 |
| 第 46 秒断开读取 2.3 秒 | 租约暂停，重新读取不能自动恢复；显式恢复后继续发令 |
| 第 50 秒主动暂停至少 0.25 秒 | 暂停期间步号固定，恢复后重新发令 |
| 第 53 秒返回编辑至少 0.25 秒 | 后台先暂停，返回战术仍须显式恢复 |
| 结束 | 暂停后读尽并确认结果，回执、事件和待执行输入清空，正常关闭子进程 |

客户端每次最多一个请求在途，不以请求洪泛代替正常使用；本片的慢读取与租约用例不替代 E3a 队列饱和边界测试。操纵指定新读取步号之后第 2 步，回执必须在该步完成后报告执行；错过接受窗口视为本次运行失败，不悄悄重发或更改目标步。

| 指标 | 本片阈值 |
| --- | --- |
| 正常读取区间模拟秒/墙钟秒 | 0.995—1.005；不跨控制发令、慢读取、暂停/恢复间隔计算 |
| 读取往返延迟 | p99 ≤ 100 ms、最大 ≤ 500 ms |
| 暂停与模式切换往返 | 最大 ≤ 250 ms；包含通信、排队和响应 |
| 首次读到执行回执的时间 | 自发令起最大 ≤ 750 ms，包含 2 Hz 读取下的观察等待，不声称精确内核执行时刻 |
| 显示快照落后状态 | 最多 16 步 |
| 调度欠账 | 请求/pump 后观测不超过既定 15 步；任何意外暂停、错误或丢失事件失败 |
| 保留量 | 输入队列 8、输出队列 16；待执行输入 64、回执 256、可靠事件 128、动态显示缓存 1 |
| 内存 | RSS/private 各不超过 256 MiB；预热 120 秒后按分钟取中位数 |
| 内存平台 | 至少 10 个有效分钟窗口，每窗至少 45 样本；后 5 窗与前 5 窗中位数之差 ≤ 16 MiB，分钟中位数线性斜率 ≤ 0.25 MiB/分钟 |

内存门不是“绝无泄漏”的证明；它限定本机、本样例、本持续时间的增长预算。缺失 private bytes 或样本不足不能通过长期稳定性门。30 分钟门及迁移前 2 小时门均使用实际墙钟，不用加速模拟步替代。

[`verify_realtime_longrun.py`](../../tools/verify_realtime_longrun.py)在启动子进程前冻结 `rules.json`、源码/资源清单与归档。每次运行必须使用新目录，失败也保留 `result.json` 和全部证据。短于 1800 秒只允许标记 `PREFLIGHT_PASS / LONGRUN_NOT_MEASURED`；不能抬高为长跑通过。阈值调整须保存旧运行并解释原因。

## 验证与后续

准备专项覆盖稳态通过、持续增长失败、短样本及缺失指标拒绝、超预算的平坦内存拒绝、队列高水位保留和进程内存读取。测量工具、既有实时接线与调度相关 **31 项测试通过**。

证据：[60 秒预检](../../artifacts/t3a-realtime-experiment/e3c-20260910-preflight/result.json)、[正式 30 分钟结果](../../artifacts/t3a-realtime-experiment/e3c-20260910-30min/result.json)、[源码/证据核对与正常/慢速读取延迟分组](../../artifacts/t3a-realtime-experiment/e3c-20260910-review/review.json)。正式运行之前只补充了清单中的测量版本说明与两项判定测试，没有调整预检时使用的阈值；各次源码归档单独保留。

正常/慢读取的延迟分组是运行后的补充描述，按输入发送时处于哪个既定周期区间划分；没有以分组替换或放宽运行前冻结的最大 750 ms 门。主机启动握手与严格场景创建单列，不混入稳态读取延迟；本次场景创建约 382 ms，只在进入场景时发生。

本机两舰后台在本次负载和时长下通过 `E3C_30MIN_STDIO_PASS`。内存出现约半 MiB 的小幅增长，符合预先冻结的预算；不能把有限时长测试写成“绝无泄漏”。原生画布/Rust/GPU 长跑、迁移前 2 小时门以及产品保存与续跑仍未覆盖，完整 E3 和默认迁移保持未通过状态。

下一实际实施项为 **E4a：普通武器与命中毁伤接线准备**。先核对现有武器/弹丸/射界/命中纯计算规则，明确战术入口需要预编译的武器资源与动态弹药/冷却状态，再接单次开火、弹丸推进、命中到部件耐久的最小闭环；毁伤继续走已接好的事件通道更新推进能力和指挥状态。开火/命中边界可验证，稳定飞行时不新增整舰重复解析。持续交战长跑和复杂事故覆盖后续分片进行。

E4 最小接线可基于本片后台范围内通过继续推进；原生界面长期稳定性、迁移前 2 小时门和产品保存兼容仍是默认切换前须补齐的工作。玩家设计出航及默认后端迁移继续按 E5 处理。
