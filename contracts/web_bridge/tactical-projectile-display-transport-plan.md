# 炮弹与导弹显示传输优化实施规划

日期：2026-09-21。状态：[D0首轮基线与D1通路](./tactical-projectile-display-d0-d1.md)、[D2炮弹插值与本地尾迹](./tactical-projectile-display-d2.md)、[D3导弹显示](./tactical-projectile-display-d3.md)、[D4生命周期与黄色细尾迹](./tactical-projectile-display-d4.md)及[D5联合验收](./tactical-projectile-display-d5.md)均已完成本轮范围。D包收尾，下一步接回6c及舰队收尾；近防规则和数值不变。弹体传输减少58.41%、发布/读取CPU减少58.04%，三层同输入战斗结果一致，前端采样/画布CPU的P95无回退。Windows可见性/最小化按用户要求停止排查，不计为通过、不阻塞本轮交付；9对9与数小时全系统稳定性仍属工作包7总验收。

## 目标与现有基线

后台给出弹体状态与已发生的关键事件，前端生成连续运动、曳光和尾迹，停止每次刷新重复传送一段滚动轨迹历史。覆盖普通炮弹、近防炮弹、反舰导弹和拦截导弹。

当前后台60 Hz推进、约15 Hz发布，前端采用100毫秒缓冲，只播放至已提交状态。`FlightHistory`为每发活动弹维护最近约33个位置采样；A5已经将发送轨迹压缩到不超过5厘米的时间插值误差，但后台滚动记录、重复传输以及复制/编码仍存在。已结束弹体保留120步、最多128条，用于补足两次发布间出生并命中的高速弹；这套容量是旧实现的边界，不直接照搬为新方案的验收标准。

[A5测量](../../artifacts/hull-armor-a5-20260921/workload.json)包含29炮双舰、约180～190个在途弹体，响应峰值约383 KB，发布平均约6.7～6.9毫秒、读取/复制/转换约8.8～9.0毫秒；这些发布和读取开销发生在约15 Hz，而非每个60 Hz模拟步。近防威胁预测约9.2毫秒/模拟步是另外的计算项。本包不据此声称GPU绘制已成为瓶颈，也不承诺解决全部模拟落后。A5两组约6.6～6.7秒即自然结束，不能用作120秒持续负载证据。

## 保持的规则

2026-09-21尾迹外观补充已在D4落实：炮弹、近防炮弹、反舰导弹及拦截弹尾迹统一为黄色、固定1 CSS像素宽；取消额外粗描边/底色，缩放不放大线宽，DPR只改变物理像素密度。尾迹仍为世界坐标中的时间采样，红蓝点框作为独立追踪指示保留。

- 后台继续决定真实位置、速度、阻力、制导、换层、碰撞、拦截、毁伤和寿命。前端显示结果不回流火控、命中或结算，也不复制整套制导和碰撞模拟。
- 首轮保持60 Hz模拟、约15 Hz状态发布和100毫秒显示缓冲；优化依据是减少重复数据和加工，不降低射速、弹速、寿命、在途数量或模拟精度。
- 保留共同显示时钟、暂停对齐、隐藏/离场停止绘制、读数中断时冻结于最新已提交状态的原则；不向未知未来外推，不拉长短命弹飞行时间。
- 保留[炮弹追踪指示](./tactical-shell-indicators.md)：无耐久1像素点、有耐久3×3像素空心框，我方蓝色、敌方红色，尺寸不随缩放变化，位于天气前景之上。尾迹素材和指示分别处理，天气遮蔽物理效果不等于取消合法指示。
- 保留当前观察层、敌我和观测边界。无耐久小口径敌弹继续作为物理效果显示；有耐久敌弹及敌导弹仅根据有效观测显示。失联隐藏不得被当作命中、自毁或真实消失；不能从显示缓存恢复已经失效的敌方情报。
- 导弹仍以当前实际归属层参与碰撞，完成换层时才切换；显示保留连续高度及换层进度，不能提前切层。固定寿命、无动力上爬中止/回落等战斗规则不变。

## 传输和绘制方案

### 1. 简洁状态与事件

建立独立、带版本的弹体显示数据，避免继续在每个弹体中附带整段`trajectory`。完整界面中的库存、人员、火控面板数据保持各自职责，不能为省字段移除正在使用的功能。

| 数据 | 发送时机与用途 |
| --- | --- |
| 显示类型表 | 场景建立或版本变化时发送；缓存弹体外观和必要的显示参数，不把完整弹药目录反复附在单发弹体上 |
| 出现记录 | 实际出膛或首次进入合法观测时发送身份、起始采样时间/位置/速度、阵营、种类、耐久分类、归属层等；首次发现敌弹不伪造其真实出膛历史 |
| 状态采样 | 先保持每次发布的简洁位置/速度；导弹增加显示所需的朝向、高度及动力阶段。恒定身份、初始数据和已接收历史不重复携带 |
| 关键变化 | 在加减速/转弯插值误差超限、动力阶段切换、换层完成等边界，补充少量带时间的关键采样；只发送新发生的数据 |
| 终止记录 | 合法可见的命中、拦截、自毁等提供准确时刻和终点；补足发布间已经结束的弹体。火光、爆炸和弹体删除共用该时间 |
| 隐藏与重同步 | 失联、观察源切换等撤销显示资格；缓存缺口时重新取得合法的活动弹体和近期事件，不能将隐藏解释成战斗结果 |

显示流使用场景/后台身份、发布序号、适用观察源与基准序号。每个响应对应同一已提交步，状态、事件和观测资格不能混用不同时间。首轮保留“所有活动弹体的简洁状态”作为容易恢复的基础，不同时引入所有动态字段的复杂差分压缩；低频炮弹校正、二进制编码或额外压缩须由后续测量证明有必要后再做。

### 2. 炮弹：前端插值与局部轨迹缓存

优先用相邻、带时间的位置和速度生成受约束插值。匀速直线可直接插值；有阻力时必须体现速度变化，不能使用“初始位置＋当前速度×总飞行时间”。先验证位置/速度曲线是否足够，再决定是否需要共享简短弹道参数；不要求前端对每发炮弹再运行60 Hz全寿命积分。

跨层发射取后台已经折算后的实际初速，包含舰艇运动带来的继承速度，前端不再乘一次跨层降速系数。出生、到期和碰撞终点以记录为准。后台保留的临时采样只用于本次发布区间的误差核对和关键点生成，不继续对每发弹在每步复制最近32步的列表。

前端按弹体ID维护有限的已接收状态窗口，并用共同显示时钟采样轨迹。尾迹按显示时间间隔取样，长度和疏密不随屏幕帧率变化；切换镜头不使旧尾迹黏在屏幕上。出膛与命中在同一发布区间内时，仍可在其真实存续区间重建短暂飞行。

### 3. 导弹：状态校正与少量关键点

保持定期状态更新，前端只平滑表现，不自主搜索、预测目标机动或决定转向。位置、速度、连续高度与阶段信息共同生成显示姿态；普通飞行不重复传送历史轨迹，急转弯、转锁、换层边界等在需要时补采样。

换层失败回落、助推结束、动力耗尽等不能被一条平滑曲线抹掉；近零速不因插值过冲产生倒飞或原地异常旋转。拦截弹改追其他目标使用新的已提交运动状态，不在画面中瞬移。敌弹只能利用其合法观测样本，不能为让曲线更顺滑而读取其隐藏实时制导状态。

### 4. 有界恢复与显示生命周期

出现/终止记录采用有界的、按序号读取的近期事件缓冲；前端在成功接收和合并后推进显示游标。重复响应按事件身份去重，乱序响应不倒退游标。该游标与已有输入确认、战果保存分开，不给每发弹增加持久化事务。

短暂丢读可补回未读取事件；保留时长、事件数和字节预算由D0按实际高射速确定，覆盖正常100毫秒播放缓冲和约定抖动窗口，不简单沿用“128条结束轨迹”。状态与事件必须成批一致，不能先让显示时钟越过尚未收到的终止记录而出现穿舰或幽灵弹。

超过恢复窗口时显式重同步：清掉旧轨迹、重新建立当前合法弹体和可恢复的近期事件，不补播长时间积压。沿用现有超过0.5秒显示缺口即重新对齐的初值；事件保留窗口可以更长，但不据此扩大补播时间。因窗口溢出不可恢复的旧效果需要记录诊断数量，不能悄悄丢弹后宣称全部无遗漏；更不能保留无限内存。正常验收负载要求窗口内无遗漏。

观察源切换时撤销旧敌弹显示缓存；仍有合法数据来源时按新来源恢复，友方轨迹可保留。换层观察只控制可见层，不更改后台状态；暂停、恢复、窗口隐藏、强制清空、下一场和后台重启均有明确清理路径。VLS已出膛但尚未出现的导弹，在原出弹时刻才产生飞行显示；战斗结束时不补播尚未出现的导弹，也不改变其已消耗的结算含义。

## 验收标准

### 正确性与可见性

1. 同一输入下，后台逐步弹体状态、命中/拦截、伤害、弹药和战后结果一致。没有新增发射、提前命中、延长寿命或跨层误伤。
2. 2000/5000米每秒短命弹，以及单个模拟步内的出现/终止均有用例；不通过减慢弹速或延长显示存续“补可见性”。
3. 首轮沿用A5的5厘米显示位置误差基线，与相同时间的已提交轨迹核对；终点/事件时间准确。非线性段不足时补有限关键点，并记录成本；前端重建不自动继承旧压缩的精度结论。敌弹则对照其合法观测样本，不对照隐藏真值。
4. 30/50/75/120毫米各弹种、匀速/跨音速/高速、同层/跨层发射，及当前17型导弹的代表飞行段覆盖；数据链观测、失联、重捕、换观察舰后均不出现额外情报。
5. 在30/60/120等不同显示帧率、三层天气、缩放及DPR 1/2下，尾迹按时间稳定，1像素点/3×3空心框和敌我颜色保持。此处是测试帧率设置，不承诺所有设备都能达到120帧。
6. 故意重复、漏读、延迟、乱序和窗口超限能够恢复；恢复窗口内无遗漏，超窗明确重同步。暂停/隐藏不累积待绘制历史，连续两场及强制清空不留前场弹体。

### 性能目标与范围

- 在D0同机、同输入、相同观测范围的基线上，首轮目标为弹体显示数据累计传输量减少至少50%，发布＋读取/复制/编码的合计CPU总耗时减少至少30%。这是待验证的工程目标，不是现有测量结论；统计明确排除初次静态几何，另报告总响应与峰值。
- 前端解析、轨迹采样和绘制分项记录平均/P95/P99，并检查帧间隔与内存。不得仅把后台工作搬到前端造成同场景卡顿；原计划在D0冻结预算，实际未冻结完整绘制数字，D5以同输入配对和明确回归报警阈值补验，不能追称其为D0既定数字。实测采样/画布CPU的P95均未回退，详见D5。没有GPU计时证据时，只报告实际测到的CPU回调和帧间隔。
- 实时响应继续受1 MiB及桥接帧/队列预算约束，不以继续扩大上限作为本包主要成果。稳态不重复发送已接收历史、固定字段/目录不按帧膨胀，缓存和积压均有上限。
- A5原29炮短局用于同条件前后对照；另建能持续至少120秒的真实近防/导弹负载，写明舰型、武器、实际射击数与在途峰值。模拟自然结束不足时单列，不改成“持续120秒通过”。
- 联合测试覆盖合法编队；9对9最大编制和全战斗系统长期稳定性仍属工作包7总验收，不能用注入数百弹体的纯显示样本代替。近防威胁预测开销独立记录，本包成功不等于其瓶颈消失。

## 主要接入位置与实施前需要落定的技术参数

后台：`tactical_presentation.py`与`realtime_view.py`负责记录和发布；桥接读请求/响应接版本与显示游标。前端：`model.ts`、实时读取接口、`presentation.ts`、`observedView.ts`和`TacticalViewport.tsx`接缓存、观测过滤及绘制，继续复用`shellIndicators.ts`。A5负载脚本与现有短命弹/时间线/观测测试作为基线。

D0需要用测量决定：事件保留时间与容量、重同步批次预算、各类插值所需关键点、前端缓存长度和分项耗时预算。这些属于实现参数，不新增游戏规则；若5厘米基线或当前显示延迟不能在目标负载下同时满足，应给出数据和具体取舍再讨论，不能静默降低要求。工作量按六个可独立验收的阶段安排，属于中等规模的跨前后端改动，首个可实施交付为D0＋D1的炮弹最小通路。
