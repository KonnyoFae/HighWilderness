# W2b 文件保存与草稿恢复

日期：2026-09-07。延续 W0 传输信封与 W2a 串行执行器；会话快照升级为 `gaotian.editor-session/v2alpha1`。本切片只支持船壳文档，未修改战术存档或权威规则。

## 文件所有权

前端仅调用宿主 `bridge_choose_file`，传入后台实例、会话、预期修订和 open/save 意图。Windows 原生对话框返回的路径只交给宿主内部 `editor.bind_file`；公开编辑桥不允许此方法。前端只得到一次性 `destination_handle` 和文件名。取消选择不会修改会话。

句柄限 32 个、300 秒有效，绑定操作类型及保存时的会话/修订，后台重启失效。只接受已有目录中的普通 JSON 文件，单文件最大 8 MiB。项目舰艇资源包、Git 元数据和恢复目录不能成为保存目的地。

- `editor.open_file {destination_handle}`：验证选择后文件指纹未改变，编译合法源数据并打开会话。
- `editor.save {destination_handle: null|string, new_version: boolean}`：null 表示当前绑定文件；新版本必须选择另一文件。另存新版本调用既有版本派生逻辑，不覆盖来源文件。
- `editor.recovery_list {}`：列出未被活动会话占用的恢复记录。
- `editor.recover {recovery_key}`：验证记录、资源身份和材料依赖后重建会话。

会话快照新增 `file_label/can_save_current/recovered/recovery_available/recovery_warning`。保存操作仍需精确会话修订，不自动重试超时操作；结果未知时先检查会话与目标文件。

## 保存与冲突

合法性、材料依赖和预览重建均在写入前检查。非法草稿不能覆盖合法文件。当前文件使用上次打开/保存的原始字节 SHA-256 检查外部变化；重新选择同一文件也不能绕过冲突。新路径在选择后被创建同样拒绝覆盖。

在同目录独占创建临时文件，写入、flush/fsync，再复查指纹并以 `os.replace` 替换，失败清理本次临时文件。此为乐观冲突检测，不承诺跨进程事务锁或断电后的目录元数据持久性。未主动截断旧文件。

保存后更新干净基线，保留撤销历史；撤销到保存前版本会重新形成脏状态。文件已提交但恢复记录清理失败时返回成功和警告，不回滚内存伪装保存失败。

## 独立恢复记录

宿主配置应用数据目录的 `editor-recovery`。每份记录使用 `gaotian.editor-recovery/v1alpha1`，包含源草稿、基线哈希、修订、最多各 64 条撤销/重做历史、最近合法源数据以及精确材料依赖，用规范 SHA-256 校验完整性；最多 32 份，每份不超过 8 MiB。

每次已应用的修改先成功持久记录再确认；记录写入失败则拒绝本次编辑，保留原会话。清洁状态移除恢复记录。非法但结构可解析的草稿可恢复，并保留最近合法预览。恢复时重新编译，不信任缓存几何；损坏记录或变化的依赖不会自动应用。

记录不保存文件路径授权。恢复后明确标记为草稿，必须重新选保存位置，不能自动覆盖原文件。名称输入框尚未点击“应用”的文字不属于权威草稿。关闭脏会话有取消/放弃提示；关闭窗口可取消或保留恢复记录退出。
