# 战术阶段 2c：主动换层

日期：2026-09-15。状态：主动换层、独立换层指令与界面已实现，本页所列验证通过，桌面更新构建完成。对应[首版规划](./tactical-first-release-implementation-plan.md)工作包 2c；强制下坠与已毁储罐紧急抢修仍属 2d，工作包 2 尚未整体验收。

## 玩家操作

在共用战场选择本方舰艇，打开右侧“舰况”，可下达前往上层、云层或雨层的命令。面板显示实际层、当前相邻段、最终目标、进度、本段及全程预计剩余时间、入战基础耗时和升力损失修正。

上层前往雨层时，先走上层→云层，再走云层→雨层；反向同理。每段完成前舰艇仍属于原层，完成的固定步才切换实际层。更改目标从当前实际层重新开始本段；“取消换层”立即清除读条，已经到达的层不回退。换层不重置车钟、推进状态、火炮模式、目标或损管命令。选择友舰可下达换层命令，不移交旗舰直控权；敌舰只读。

观察层保持由玩家选择，不随换层命令改变。舰艇换到其他层后，可切换观察层，或用“聚焦所选舰”切到实际层。暂停冻结读条，恢复后继续既有换层进度；暂停期间沿用当前战术入口的禁止发令规则。回执丢失时读取权威状态，不自动重发或重置进度。

## 计算与权威状态

- 每相邻段为 5,000 米。入战时从编译设计取干重 `m`，从实际保存战损、工作模式、人员与供电结算取得可用总升力 `L0`。使用项目统一重力常数，`a0=(L0-m*g)/m`，`T0=2*sqrt(5000/a0)`；主动升降采用相同计时模型。
- 基线在创建战斗权威状态时一次计算，存储于每舰不可变状态；挂载、货物和战中质量变化不重算干重或 `T0`。升力相关生命周期判断也统一使用设计干重。
- `d=clamp(1-L_current/L0,0,1)`，当前完整相邻段时间为 `T0*(1+d)`。损失 25% 升力即增加 25% 耗时。途中受损保留当前完成比例，改变下一步推进速度；在开步设备变化、闭步设备变化和炮弹命中后均同步。
- 入战净升力非正时基础时间不可用；当前没有正冗余或已失去作战/接令资格时不能发起主动换层，已有主动段也会停止。此处不实现负冗余的强制下坠。现有升力失效导致失权/结束的旧生命周期仍须在 2d 替换为可抢救流程。
- 复用固定 60 Hz 机动积分中的相邻层计时状态，不逐步计算真实垂直速度，不提高全局物理频率。两段之间不跳层，也不为显示另开一个模拟计时器。

后台职责见 `tactical_layers.py`、`simplified_flight.py` 与 `tactical_scheduler.py`。调度器在同一已提交步边界接受换层命令，不推进物理步，也不清除已排队的操纵输入。场景、代际、序号、玩家阵营、旗舰权限与所选舰状态都在后台验证；重复请求只返回已确认状态。

`tactical.realtime.height` 使用 `{scene_id,input:{epoch,generation,sequence,ship_id,target_layer}}`，`target_layer=null` 表示取消。快照按舰提供 `height_navigation`，并以 `height_commands.command_sequence` 提供独立命令序号。原生桥接白名单及前端操作均已接通。

内部检查点升级为 `gaotian.tactical-checkpoint/e2.3-v2alpha1`，严格校验初始干重/升力基线、实际层、相邻段、最终目标、进度与当前 debuff，并支持换层中继续内部模拟。该接口不增加产品中的战斗断点续玩，旧版内部检查点明确拒绝。

## 与炮击、战果衔接

现有普通炮仍只在本舰实际层发射。自动目标位于其他层时保留目标并显示“等待同层交战”，不继续向无法命中的层消耗待发弹；重新同层后可继续执行。已发弹体保持发射时高度层。真实扫掠命中使用完成该固定步后的舰艇层归属，换层指令本身不能提前免疫原层来弹。正式选择跨层攻击及速度修正仍属工作包 3。

换层途中结束本场也可以正常结算保存、返回准备并开始新场。主动段、高度位置、命令序号属于战场状态；当前再次部署仍从准备规定的上层开始，重新计算入战基线，不把旧换层进度带入下一场。已有库存与战损保存语义继续保留。

## 验证

- 前端类型检查及 112 项测试通过，包括新增换层面板的层级/时间含义、敌舰只读、受损修正、不可用与未确认状态。
- 后台 153 项相关测试通过，本片新增 12 项高度专项，覆盖牛顿公式与非正净升力、载荷质量独立、逐段边界、第一/第二段取消、与推进及自动火炮并行、未毁储罐满升力、实际设备损毁后 25% 修正、开步/闭步/命中后的连续进度、候选失败回滚、内部检查点与篡改拒绝、暂停/恢复/重复请求/非法命令、友舰身份及真实准备舰保存再入战。回归范围包含检查点、调度、指挥、实时视图、炮击/毁伤、准备部署、结算与库存。旧自然结束测试补登记其直接注入弹丸的显示历史，保持与 2a 生产步进路径一致。
- 补充真实扫掠炮弹测试：段完成前命中原层舰体，完成步后原层弹不再命中新层舰体。
- 原生桥接专项 `real_realtime_view_controls_and_editor_pause` 通过，含换层命令、与操纵/火炮共存、暂停后的重复回执；使用独立测试仓库。
- [实际界面报告](../../artifacts/tactical-height-20260915/result.json)：两艘合法准备友舰与一艘技术敌舰，生产 React 面板连接实际 Python 后台。验证逐层到达、暂停、回执丢失、友舰命令、三层真实舰艇观察、默认桌面尺寸和换层中结束/保存/返回。为集中验证长航程操作，隔离测试宿主使用两倍外部时钟并关闭技术敌舰主动索敌；仍逐步执行真实 60 Hz 状态，不伪造换层完成快照，不将该场景作为性能或战斗平衡结论。

实际界面报告状态为 `TACTICAL_HEIGHT_UI_PASS`，参考舰相邻段基准耗时约 73.864 秒。TypeScript、Vite 及 Rust/Tauri 调试构建通过；保留现有主包体积提示，未阻断构建。原生证据覆盖桥接专项、构建与启动，浏览器界面证据不表述为原生窗口自动化操作。
