## 交付目标

用户能进入独立的两舰测试战术视角，看见真实船体、模块和朝向，选择舰艇、缩放平移镜头，使用暂停、单步、继续及车钟、转向、制动。首版固定蓝方旗舰为直控舰，红方只作检查对象；点选敌舰不授予控制权。当前产品仍使用完整推进安全路径；新政策保留非配平类安全并单独验收。返回编辑器后战术必须暂停，未提交表单与未保存编辑草稿不得丢失。

仍使用 T1a 固定技术舰，不接用户设计出航、普通弹交战、美术特效、复杂 RTS 或正式规模性能验证。后续依次为 T4a 普通弹/命中战损与两舰性能、X1a 用户设计出航/存档续跑。

## 落地顺序

### 1. 画布与模式切换（T2a）

- 在 `apps/desktop/src/tactical/` 增加 PixiJS 战术画布，扩展 `TacticalPanel`。复用已有相机数学，舰体/模块对象按静态指纹建立，动态帧只更新舰艇容器姿态。
- 显示两阵营颜色、船艏方向、选中轮廓与所选舰速度/船壳完整度；提供适应全场、缩放和平移。多甲板按高度叠画，首版不扩展云层和高度切换控制。
- `App.tsx` 接编辑/战术模式入口，编辑器保留挂载或上移完整状态。后台也明确模式所有权；战术运行时不接受编辑修改或文件写入，先暂停再恢复编辑权限。
- 暂停、切换场景、后台重启或静态指纹变化时清除旧插值轨迹。释放 Pixi 资源和监听器，隐藏画布不持续占用渲染循环。

### 2. 单步及直控（T3a 前段）

- 已接具名 I9/v7 单旗舰适配与固定蓝方直控身份，三端增加原子 `tactical.step`；控制输入与一步积分合为一次请求。始终步间暂停，暂停/继续调度留第 3 步。
- 已接离散车钟选择、前进/倒车、左右转单步与自动线性制动。车钟选择跨模式保留，转向只附着于点击的这一步，下一普通步显式归零；按住输入留第 3 步。暂停时不推进、不额外耗油。
- 单步仅在暂停状态接受，一次成功请求恰好推进 1/60 秒。通过已确认序号和状态回读处理未知结果，不盲目重发单步或控制命令。
- 车钟、转向、制动和 OverG 如有入口，均走完整安全链；状态显示区分玩家请求与实际受安全约束的输出，不将未达到目标当成输入无效。

### 3. 连续运行与可靠输入（T3a 后段）

- 权威线程以单调时钟安排 60 Hz 固定步，使用有界工作批次；以 10—20 Hz 发送动态全量快照，前端插值显示。用户界面刷新或轮询不得决定仿真是否推进。
- 连续输入新增明确版本的有限未来步调度：后台给出当前步、可接受窗口及已接受/已执行序号，前端指定窗口中的目标步；入队与序号更新原子完成。迟到、重复、错场景、越权及超窗口请求必须明确拒绝。窗口大小在小样例延迟检查后冻结，不预先承诺零延迟。
- T1a v1 校验语义保留；不得把 `target_step` 改成后台任意选择的时间。已接受但未执行的输入在暂停/模式退出时的处理须固定：临时控制清除、持续目标保留规则均显式可查询，不把积压按键带入恢复后的场景。
- 可替换的完整快照允许合并，命令确认和可靠事件不可静默丢失。暂停/退出应能及时处理；过载时显式暂停或减慢模拟墙钟进度，不能丢弃权威步来追赶。
- 快照序号、场景句柄、输入序号和事件身份分别处理。仍以 T1a 的资源身份重建场景，重启或释放后旧结果不能污染新视图。

T2a 与 T3a 前段已完成。第 3 步的产品目标保留，但先按新实验规划 E0—E2 验证独立战术内核，再由 E3 接连续运行及可靠实时输入；不以独立回放播放器或通用 ECS 为前置。最终仍以“用户可看见并连续操纵两舰样例”及实测实时门作为阶段完成条件。

## 验收与后续边界

1. 几何与镜头：比较内核坐标变换，核对舰体/模块不翻转、不重复旋转；选择、缩放和平移不修改权威状态。
2. 单步与权限：一次只推进一步；重复或过期输入不重复消费；只能直控指定蓝方旗舰，失去指挥能力后拒绝继续操纵。
3. 连续调度：暂停步号稳定、恢复步号连续；慢渲染不改变同一输入的权威结果；队满、失焦、切换编辑、后台重启均可恢复且不丢草稿。
4. 适配回归：I9 旧场景继续可用，既有 v7 安全证据保留；E1c 另验具名简化政策、非配平安全、资源身份与确定性，不伪造旧配平记录，不靠更新历史黄金掩盖行为变化。
5. 真实跨进程与桌面：跑相关 Python、Rust 和前端检查及构建；重新构建并启动桌面后验证进入场景、操纵和返回编辑。单独重启 Python 不能加载新的 Rust 命令。

T4a 再执行普通炮弹、命中/战损及 10 秒预热 + 60 秒测量。T2a/T3a 的运行联调不是 T4a 性能结论；正式 6/20/30 舰矩阵继续后移。O4 三舰规范实机留档仍保留为非阻塞收尾项，X1a 退出前补齐。
