# 显示传输D0／D1：基线、增量记录与恢复通路

2026-09-21。状态：D0首轮基线与D1通路已完成，当前接续D2炮弹前端插值。用户要求开始实施后，本轮先推进显示优化；6c仍待接续。本阶段不是D0～D5整包完成，尚未移除后台全部旧轨迹生成。

## 已交付

- 正式实时界面的读请求协商`gaotian.projectile-stream/d1-v1`。活动弹体不再在每次响应中重复携带出生资料和整段轨迹，而是携带动态状态；身份、阵营、种类、耐久分类及出生/到期信息通过出现记录补齐。
- 每次发布只新增本区间必要的路径点，以及出生/终止记录；前端按ID、步号和序号合并，恢复现有`PresentationTimeline`输入。D1沿用原绘制采样，D2/D3再将运动重建和局部尾迹分别接入炮弹/导弹。
- 终止记录使用真实命中、拦截或到期位置；普通高速弹在两次发布之间出生并命中也不会被“当前活动列表”漏掉。失败模拟步不生成显示事件。
- 显示游标只在完整响应合并成功后推进，与输入确认和结算分离。重复响应幂等、丢读可以补取；旧游标、过长发布缺口或过大补发请求转为完整重同步，未知身份或前端缓存不完整时丢弃缓存并重新请求。
- 快照与增量数据属于同一已提交发布步；后台继续推进时，读取不会把尚未发布的弹体位置或终止事件混进旧快照。显示通路不会推进模拟。
- 对超过128枚弹体同时结束增加独立终止缓存，避免继承旧显示历史的128条上限；300枚弹体在两次发布间出现并终止的专项用例通过。
- 旧请求和控制操作响应仍兼容原协议；新前端收到原格式后清空增量游标，再用完整同步恢复。新数据经现有观测过滤后才进入画布，有耐久敌弹仍使用有效观测位置，失联清除，红蓝点框规则保持。

当前界限：生产后台仍会构造原格式发布快照，D1额外生成增量资料，因此发布成本没有同步消除；常规新响应不同时发送两份轨迹，但生成端去重留在D2～D4。导弹换层/姿态细化、观察源专项恢复与更全面生命周期验收继续D3/D4。

## 首轮预算

保持60 Hz模拟、约15 Hz发布、100毫秒显示缓冲、0.5秒长缺口重新对齐及1 MiB实时响应硬上限。后台保留最多32个发布批次，最多120模拟步、2 MiB批次数据；独立终止缓存最多4096条、120步及2 MiB，按先达到的边界淘汰，并记录窗口内超限丢弃。单次增量超过384 KiB时转完整同步，最终仍受整体响应上限约束。

前端只保留最近约32步路径及必要前锚点，已结束飞行最多保留120步；所有缓存按场景/后台/几何身份隔离。全量同步也可能超过整体上限，当前不会突破上限或静默缩减活动弹体；超大场景分批恢复仍在D4/D5验证，不宣称已完成最大编制验收。
