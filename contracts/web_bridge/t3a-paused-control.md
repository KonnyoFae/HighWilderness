## 请求与原子性

沿用 W0 信封及独立 Rust 战术白名单，编辑 `session_id / expected_revision` 均为 null。新增 `tactical.step`，params 恰为 `{scene_id, input}`，只在战术模式接受。`input` 仍为 `gaotian.tactical-input/v1alpha1`，包含 `interface / scene_id / input_seq / target_step / command / arguments`；command 为 control，arguments 恰为 `{ship_id, control}`。

`target_step` 必须等于当前尚未积分的开边界，`input_seq` 必须是大于最近执行序号的安全整数。错场景、重复、旧步号、错误作用域和越权输入明确拒绝，不静默换步、不消费序号。控制使用现有定向推进合同，完整六通道随一步请求提交。此阶段没有输入队列或独立“设置后后台运行”的控制入口。

后台先完成仲裁、完整安全积分和候选表现快照，再一起发布场景、指挥状态及执行回执。投影失败不会提前消费权威步或输入序号。`inspect` 和模式切换不推进时钟，返回编辑器恢复编辑权限时仍暂停；释放场景清空回执。

## 仲裁与安全

新增 `gaotian.directional-direct-command-step/v1alpha1` 适配，复用 I9 的场景绑定、角色和生命周期同步，再向原 v7 内核传完整推进上下文与定向控制。指挥配置来自阶段 I 技术配置，配置引用和 SHA 受检；指挥状态每步重新绑定结果场景。

当前范围严格限定为 normal / active、一个玩家旗舰且无活跃 RTS 指令；固定直控 `ship.web.blue`，红方选择只影响检查。失去指挥能力、非 operational / scene_command、错误旗舰、配置或资源上下文不匹配均拒绝。其他舰显式使用中性控制，不提供隐藏的 NPC 输入入口。原 I9 旧入口及 v7 算法未修改。

燃料、供电、人员、损毁、结构/乘员安全、响应过程和换向互锁均走现有内核。界面未开放 OverG；底层输入即使请求 OverG，也不能绕过燃料等硬限制。技术舰没有倒车通道，倒车或自动制动可能报告缺失推进器；制动不会凭空产生反推，也不会瞬间清零惯性或残余发动机输出。

## 表现与交互

现有 render snapshot 增加可选 `control_state`，版本为 `gaotian.tactical-paused-control-state/v1alpha1`：固定直控舰、可用状态及原因，最近执行输入序号/规范 SHA/开边界，请求控制、指挥与配置指纹，各方向有效请求/安全上限/原因，各推进器目标/实际输出/阶段，燃料与缺失通道、简化仲裁审计。静态几何缓存仍按原指纹复用。

车钟为停车、2%、25%、50%、75%、100%，选择前进或倒车。转向力度按既有阶段取值；左右转按钮只在当前单步提交转向，普通单步显式归零转向请求。自动线性制动由内核选择反推方向，并清除平移和转向请求。车钟表单跨编辑/战术切换保留，新场景重置；此阶段不引入按住键或残留转向状态。

请求在途或结果不明时禁止第二次单步。前端在发送前记录场景、序号、目标步及与 Python 一致的规范输入 SHA。响应丢失后通过 `inspect` 判断“精确执行一次”“尚未执行”或“仍不明”，不自动重发。只有场景和完整回执吻合且当前步为目标步加一才认定执行；无法消歧则保持锁定，允许释放并重建场景。
