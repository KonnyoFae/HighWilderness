# U1：战术画布、覆盖面板与选择基础

日期：2026-09-20。状态：范围内已接入并验证；工作包 U 整体尚未完成，下一阶段为 U2。执行顺序见[优先实施计划](./tactical-ui-implementation-plan.md)。

## 本次接入

- 实际战斗页面使用完整画布作为基底；舰队、舰务、火控和旗舰操纵由半透明边缘面板覆盖，附着的小型图标标签负责折叠。面板变化不参与画布尺寸计算。
- 舰队列表只列本方舰艇，旗舰排第一并标识。删除独立选择旗舰按钮；默认圆点位于舰体上方，缩出画面后显示边缘方向提示。条目、连线与图标关联同一舰艇身份，选中高亮。
- 舰队列表单击只选舰，第一次双击平移聚焦，再次双击同一已聚焦舰艇才适配细节；手动移动镜头或换舰清除本次聚焦阶段。
- 左下舰务区含舰况、损管、货舱入口；右侧火控父层保留实际观测目标列表，下方切换火炮／导弹。两块面板的一级子页分别按舰艇记忆。
- 火控目标项单击复用现有锁定命令，双击使用该条目的观测位置定位，并保留本方操作舰；失联项不发锁定命令。目标选择不会自动向所有武器发令。
- 原感知设备与电子对抗移入火控的折叠区，取消在两个功能页重复显示整套干扰操作。普通武器、导弹发射／在途／后勤和损管功能继续复用现有组件。
- 画布武器输入需显式启用，打开火炮子页本身不会把查看点击变成射击。关闭火控、换舰或换武器页会清除画布瞄准／选点及待发送指针操作。普通友舰仍维持原权限，手动炮组操作限旗舰。
- 保留开始／暂停、结束本场、战果保存、返回准备及原强制清空入口。实验入口继续可用。

## 验证

- 前端类型检查与构建通过；36 个测试文件、158 项测试通过。
- 新增 `tools/verify_tactical_ui_u1.mjs`，使用实际 React 页面和独立 Python 后台、三艘实际准备舰艇验证。最新证据：[result.json](../../artifacts/tactical-ui-u1-1789838095134/result.json)。
- 实际锁定目标成功；目标聚焦不改本方操作舰、不隐式发送火炮命令；舰队项单击及面板开合／切页不改变画布边界、相机和静止图标位置。
- 按舰恢复舰务／武器子页；舰队首次双击保留缩放，第二次才进入细节。
- 覆盖 1920×1080、1366×768；结束交战后保存双方结果并返回战前准备成功。未将本次单场往返扩大为连续两场／重启已验收。

## U2／U3 待完成

- 武器、感知、电子对抗、损管的内部信息密度、快捷动作与详情仍需整理；当前优先保留全部真实功能，部分旧内容在面板内滚动。
- 独立旗舰操纵目前只迁入可折叠容器，保留旧控件作为过渡；具体操纵重设计仍归 U2，不视为旧方案重新获批。
- 货舱首轮仅汇总本舰现有燃料／弹药读数并链接现有导弹后勤，完整按库资源、占用和不足说明归 U2。
- 舾装自定义分类图标、密集／异层图标避让、完整观测展示边界、警报快捷定位、嵌套功能页与设备展开状态记忆继续在 U2 处理。
- 顶部测试流程与记录／视图入口继续整理；面板内详细内容与快捷按钮仍需按最终操作路径验收。
- 连续两场、重启、强制重置、完整导弹攻防及旧浏览器验收脚本的入口更新归 U3。

本次未替换正在运行的桌面程序，也未提交或推送。后续打包更新与发布单独记录，不能把网页构建当作桌面安装已更新。
