# E3a 固定频率调度与可靠输入

日期：2026-09-09。基线：`4bef488` 加工作树中的 E2/E3a 实现。状态：`E3A_IMPLEMENTED / E3B_NEXT / FULL_E3_NOT_PASSED / PRODUCT_REALTIME_NOT_PASSED`。

本片把已验证的独立飞行会话包在单一拥有者的调度器中。实现位于 [`tactical_scheduler.py`](../../backend/high_wilderness_sidecar/tactical_scheduler.py)，仍是内部实验 API，没有切换桌面默认后端，也没有启动产品后台线程。

## 调度与暂停合同

`TacticalScheduler(session)` 必须在会话所属线程建立，初态暂停；宿主通过 `resume()`、`pump()`、`pause(reason)` 驱动。每次 pump 后宿主应处理输入/输出，不在一个无限循环中占住界面线程。调度器持有会话的唯一写入权，外部自行推进原会话或回调重入调度器均被拒绝。

时钟默认使用 `monotonic_ns`，测试可注入整数纳秒时钟。欠账用“纳秒 × 60”的整数单位累计，每成功提交一步扣除 10 亿单位；内核始终以 1/60 秒推进，不把 16,666,666 纳秒的取整误差累积进长期计时。没有足够欠账时不运行，过载时不跳过权威步，也不扩大 dt。

首轮固定默认上限如下；测试夹具可以显式提供另一组不可变配置，不在运行中改配置。

| 项目 | 默认值与行为 |
| --- | --- |
| 每次 pump | 最多 4 步；墙钟处理预算 8 ms，步间检查 |
| 过载 | 欠账超过 15 步（250 ms）时暂停，保留全部欠账 |
| 未来操纵窗口 | 当前已提交边界 n 至 n+6；每个步首最多一条已接受操纵 |
| 待执行队列 | 最多 64 条；默认窗口和每步唯一约束会进一步限制实际条数 |
| 输入回执 | 最多保留 256 条；接受时预留终态位置，不淘汰未确认回执 |
| 可靠领域输出 | 最多 128 个含事件的 StepResult；不含历史世界引用链 |

预算不能抢占一个正在计算的 Python 固定步：单步阻塞仍可能超过 8 ms，随后停止追赶或进入过载暂停。8 ms 不是端到端响应承诺。

暂停采样截止时刻并停止累计后续墙钟时间；已有欠账保留。`recover_debt()` 只在暂停时显式处理已有欠账，同样受每批步数和处理预算约束，且不补算暂停期间经过的现实时间。过载欠账须降到阈值内才能恢复；没有静默舍弃欠账的入口。

手动暂停、返回编辑（`mode_exit`）、断连（`disconnected`）、过载、输出背压和步骤失败均取消待执行操纵。下一成功步骤清空之前保持的操纵，或使用恢复后新接受的指令；不会在恢复时重放旧队列。清空不修改已提交的暂停世界，也不瞬间清除船体惯性或绕过推进响应。真实 CIC/遥控/生命周期失权后也会取消待执行操纵，但继续运行坠落/惯性物理。

时钟倒退或非法返回值会锁存故障，必须重建调度器；不能靠再次暂停/恢复解除。保存重建后的新会话可以建立新调度器，使用新场景身份、空队列和暂停初态，首次推进也要求重新发令。

## 输入与回执合同

内部输入版本为 `gaotian.tactical-scheduled-control/e3a-v1alpha1`，恰含 `interface / epoch / generation / sequence / ship_id / target_step / control`。控制内容沿用严格的六方向控制合同。

- `epoch` 绑定会话身份；`generation` 在取消操纵时递增，阻止暂停前已经发出但尚未到达的输入在恢复后被接受。
- `sequence` 从 1 连续递增，仅成功接受才占用序号。每条指令指定步首 `target_step`，在该区间成功提交后转为 `executed`，回执的 `resolved_at_step` 是区间结束边界。因此窗口大小不能直接当作 UI 最大延迟承诺。
- `accepted` 只表示入队；随后为 `executed`、`cancelled` 或 `failed`。`executed` 表示控制已经参加该步计算，输出仍受同边界领域变化、安全和权限约束，不保证发动机当步产生推力。
- 保留期内完全相同的请求返回已有回执；相同序号不同内容拒绝。即便失权或暂停，仍可查询此前的终态，不会重新执行。
- 调用者显式确认终态后释放存储；仅保留单调高水位。已确认旧序号查询返回 `expired` 并禁止重执行，新序号查询返回 `not_received`。不是把查不到的旧请求当作从未执行。
- 越权、旧身份、旧代次、过期/过远目标、同边界冲突、队列或回执容量不足均拒绝，不占用新序号。未确认回执不会被新输入挤掉。

可靠领域输出使用独立连续序号，可以重复读取，必须先连续读取再累计确认；过期游标和跳读确认被拒绝。每步前预留一个可靠输出位置；容量已满则在计算前暂停。取消输入使用已预留的回执位置，背压情况下也能查询取消结果。空事件区间不占输出位置，动态显示快照将在 E3b 单独合并，不冒充可靠事件。

内核继续保留“候选投影失败则本步不提交”的语义：当前请求记为失败，未来请求取消，世界和领域结果保持旧提交边界。请求回执与领域输出均在单一拥有者内更新。当前不提供跨进程崩溃持久化、断线传输协议或磁盘回执恢复。

## 验证与冻结证据

新增 [`test_tactical_scheduler.py`](../../tools/test_tactical_scheduler.py) 15 项测试；相关回归 **123 项通过（31.961 秒）**。随后补强类型拒绝入口，调度专项 15 项再次通过。覆盖整数频率、时钟抖动与批次、未来步/重复/冲突输入、容量/确认、三种主动暂停、过载欠账恢复、单步计算预算、输出背压、投影回滚、真实 CIC 损毁、时钟错误锁存、线程/重入限制、加载新身份及稳定循环不重算。

验证工具：[`verify_tactical_scheduler.py`](../../tools/verify_tactical_scheduler.py)。冻结结果：[`e3a-20260909-scheduler/result.json`](../../artifacts/t3a-realtime-experiment/e3a-20260909-scheduler/result.json)，同目录保留来源归档、资源/输入、各终态、逐步计时、画像和真实时钟样本。

三负载使用 E2.2b/E2.3 的人工电力/人员蓝舰与红方观察舰。每类在 7/21/11/40/3 ms 的循环抖动下运行 4200 步，在每个提交候选处与直接逐步运行的完整舰状态及 StepResult 对照，合计 **12603 个边界一致**；可靠事件读取内容与顺序也一致。每类执行 4269 次 pump，回执存储峰值 1 条、可靠输出峰值分别为 1/2/1。此负载仅有一条初始操纵，不能用这个峰值证明高频玩家输入下的容量或内存平台；多条操纵、限流和积压由专项测试覆盖。

吞吐测量使用可控时钟且不节流，每类预热 600 步、测量 3600 步、三轮重复。计时包括宿主的输入入队、pump、回执查询/确认和可靠事件读取/确认；不含创建、参考对照和画像，也不含 UI/IPC。

| 调度负载 | 最差平均 ms/步 | 最差 P95 ms | 最差 P99 ms | 最大单步 ms |
| --- | --- | --- | --- | --- |
| 稳定飞行 | 0.309 | 0.408 | 0.568 | 1.904 |
| 资源故障、恢复与复位 | 0.330 | 0.540 | 0.853 | 2.995 |
| CIC 停用后恢复，直控保持失效 | 0.342 | 0.468 | 0.600 | 1.727 |

九轮均通过范围内吞吐门。静态哈希、旧完整运行参数编译、配平、快照指纹及时间能力解析为零；三负载供电/人员分配各为 0/156/3 次。请求进入边界的严格解析保留，不属于稳定飞行重复解析。

独立真实时钟短测采用约 1 ms 宿主轮询、机动输入带和真实 `monotonic_ns`：**10.001 秒内完成 599 步（9.983 秒模拟）**，结束时模拟相差 18.002 ms；运行样本最大欠账 **0.999866 步**，未触发过载。结束时直接暂停，未补算最后一次轮询后的到期步，欠账仍保留。单次暂停调用耗时 0.056 ms，最终舰状态与事后运行的直接参考一致。

这是一段本机后台短测，不是端到端 P95、精确每秒必有 60 次宿主唤醒、内存无泄漏或长跑验收。30 分钟/2 小时墙钟实验、慢消费者长期存储平台及完整 E3 仍未通过。
