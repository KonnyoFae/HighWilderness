## 1. 本次冻结的规则

- 进场时编译每台发动机的固定方向贡献及全舰完好能力；战损后按仍可用的贡献计算剩余能力。
- 推进与转向独立汇总。推进发动机不因偏置安装或单侧损毁产生额外转向；转向发动机不产生需要抵消的残余平移。战术运行时不做配平，也不要求健康发动机为受损发动机降功率。
- 首版沿用现有六个控制方向：四个平移方向和两个转向方向。各方向独立存储，不能把左转能力挪给右转。没有对应设备的方向能力为零，保留缺失方向反馈。
- 毁伤系统持有血量；推进系统接收可用性变化。首版部分掉血本身不减推力，完全损毁使该设备失效；修复使其重新可用的条件由毁伤/设备规则决定。不得继续隐式套用旧半耐久 75% 功能曲线。
- 供电、人员、宿主、工作模式等既有可用性约束仍须显式接入；与血量分离不等于忽略这些条件。未接入的条件在实验报告中列为 NOT_COVERED，不得据此切换产品默认路线。
- 保留固定 1/60 秒、指挥权限、响应计时、换向互锁、非配平类安全限制、既有步内因果顺序和战术推进不耗油。试航推力倍率仅属于具名技术样例。
- 发动机损毁降低后续输出，保留既有速度和角速度；不把部件损毁直接当作部件质量消失。

这里改变的是战术推进模型。编辑文件及其版本、安装合法性、旧严格推进入口均不因本规划修改；如编辑器显示旧配平派生性能，后续出航预览须明确展示新战术能力，避免两个口径混用。

## 2. 编译结果与运行数据

无需枚举 N 台发动机的 2^N 个损毁组合。使用每台固定贡献向量，任意剩余组合都可通过求和获得，存储为 O(N×6)。

| 数据 | 内容 | 生命周期 |
| --- | --- | --- |
| 只读贡献表 | 稳定发动机索引、来源模块、六方向贡献、响应参数、相关依赖 | 创建/载入严格验证后编译一次 |
| 完好能力基准 | 每方向完好贡献之和、质量/惯量与单位、规则版本及资源身份 | 当前资源版本内固定 |
| 设备可用状态 | 可用性原因集合、来源事件版本、启动/响应状态、下一到期时间 | 相关事件或到期转换时更新 |
| 当前能力汇总 | 六方向剩余上限、剩余比值、实际输出贡献及版本 | 可用性或实际输出变化时更新 |
| 舰船运动 | 位置、速度、航向、角速度 | 每固定步积分 |
| 毁伤状态 | 血量、损毁、修复过程 | 独立毁伤通道维护，推进不逐步读取全部血量 |

对方向 d，编译贡献记为 C[i,d]，完好总量 B[d] = Σ C[i,d]；设备可用标记 A[i] 为 0 或 1，当前剩余上限 T[d] = Σ A[i]×C[i,d]。B[d] > 0 时剩余比值 R[d] = T[d]/B[d]；B[d] = 0 时能力和显示比值均为 0，并标记该方向不存在。

部分受损初始舰仍以完好资源的 B 为分母，不能把受损初态重新定义成 100%。完全失效、全舰无发动机、不同额定贡献都必须有明确结果。

平移贡献使用力单位；转向贡献使用等效力矩单位，不能直接把推力数值当角加速度。首版在编译时依据完好设计的固定力臂计算转向发动机的方向力矩，随后只汇总这个标量；这不是运行时配平。推进发动机的偏置力矩、转向发动机的平移副作用明确丢弃，不重新分配给其他方向。编译器不得直接复用已经经过旧配平或耐久效率缩放的结果。

运动仍由合力/质量、合力矩/惯量及保留的机动规则决定。合法质量/惯量变化需更新运动参数；不据此重新引入配平或动态力臂求解。结构脱落导致的几何重编译属于后续独立切片，首版不声称覆盖。

实际输出另乘设备当前响应比例，再应用适用的通道安全限制。剩余 70% 能力不代表当前立即输出 70%。首版保留已有启动/档位响应语义，编译时间参数，管理活跃转换；稳定发动机不每步解析，响应中的设备只在必要到期或改令时更新贡献。若以后改成整舰统一响应，须另行记录规则变更。

## 3. 事件与提交边界

概念事件 `EngineAvailabilityChanged` 至少携带资源/会话身份、发动机索引、原因与新状态、来源版本、固定步及阶段。该名称是计划中的内部事件，不是已发布协议。

1. 毁伤、供电等领域在受控写入点产生变化；外部输入不能直接提交“可信可用性”或能力比值。
2. 更新对应原因，再由全部原因共同决定 A。发动机修复但仍断电时不能恢复推力；重复失效不得重复扣减。
3. 从旧标记到新标记仅计算一次差量：ΔT[d] = (A新−A旧)×C[i,d]。实际输出汇总同步扣除/恢复对应贡献，恢复还须经过启动和响应规则。
4. 单个设备事件更新至多六个方向；同批多个原因先合成最终状态，避免中途虚假恢复。顺序使用稳定来源版本；重复事件幂等，陈旧事件不覆盖新状态，错资源/越界事件拒绝。
5. 步首已失效设备本步不输出；步内命中按既有收边界生效，对下一交付区间断推，不追溯撤销本步已积分运动。到期转换与损毁同边界时先按可用性约束决定能否输出。
6. 可用性、响应排程、贡献汇总、世界与回执一起候选提交。失败后全部保持原提交边界，不能只回滚血量却留下已扣推力。

原型使用确定的定点或 Decimal 贡献值，方向与累加顺序固定，避免反复损毁/修复造成浮点增减漂移。具体数值表示在 E1c.1 冻结；热循环性能另测，不能用截断误差掩盖能力差异。

保存记录规则版本、精确资源身份、可用性原因/来源版本、响应状态和必要事件序列，不持久化内存缓存证明。载入时从贡献表及状态重建汇总并核对。新政策不得冒充旧 v7 语义或生成伪造的旧配平审计；不兼容存档明确拒绝，具名转换另测。

## 5. 验证矩阵

| 案例 | 预期 |
| --- | --- |
| 推进贡献 40/30/30，损毁第二台 | 剩余 70%；未受损设备贡献不变；偏置安装不增加偏航 |
| 独立的左转/右转设备，只毁左转设备 | 仅左转能力下降，右转和平移上限不变 |
| 多额定值、零设备、全毁、初始受损 | 按贡献权重而非台数计算；无除零/负能力/错误的 100% 基准 |
| 部分掉血、完全损毁 | 前者不直接改变推进能力；后者一次性清除该设备贡献，血量仍准确保存 |
| 重复/陈旧/错资源事件，多原因失效 | 不重复扣加；修复不绕过断电/宿主等仍有效的限制 |
| 恢复、改令、反转、启动中损毁、同一步到期与损毁 | 不瞬间满输出、不带出幽灵推力，原有响应和互锁的保留语义成立 |
| 稳定飞行和反复损毁/恢复 | 无变化不重建贡献；增量总量与独立全量求和严格一致，不积累漂移 |
| 已有速度/角速度时断推 | 不瞬间停车；后续按保留运动规则继续演化 |
| 步首/步末事件与失败候选 | 生效阶段准确；推进、血量、排程、事件和回执不出现半提交 |
| 保存重载与跨会话污染 | 同边界同输入续跑一致；错政策/错来源拒绝；缓存与内部地址不进入存档 |
| 指挥权限和非配平安全边界 | 仍限制实际输出；失败拒绝原因可追溯，不能通过新推进入口绕过 |

新规则参考实现必须独立按贡献表全量求和，不复用被测差量更新函数。运动案例使用可解析的合力/力矩与既有积分约定校验；选取本来不触发配平/耐久衰减差异的案例时，才与旧路径比较公共运动字段。

E0/E1a/E1b 的旧黄金、SHA 和完整对照报告不改写。为新政策冻结独立资源、输入、事件及期望；记录预期规则差异，检查未变领域。旧路径只提供历史性能与未变子规则参考，不能把规则简化带来的提速全部归因于缓存优化，也不能删掉不一致字段让旧黄金“通过”。

## 6. 性能和阶段完成标准

- 分别统计创建编译、每步积分、响应到期、单次/批量战损更新、表现投影和保存开销。
- 稳态每步：旧配平调用、完整发动机/整舰推进记录解析、全量血量扫描、能力全量重建均为 0。必要的运动、安全计算和活跃到期过程继续执行。
- 复杂度目标：无变化时推进能力维护为常数开销；设备事件 O(6)，多设备变化按实际受影响数更新，不扩散到配平组。依赖事件生产者的扫描成本也要单列，不能只把旧成本移到别处。
- E1c.3 先做三次短测，再按主计划做 10 秒模拟预热及 3600 步吞吐测量；两舰平均 <16.67 ms、P95 ≤12 ms、P99 ≤16.67 ms 为工程门。包含响应与集中战损负载，报告最差重复和超时比例。
- E3 仍需 30 分钟墙钟飞行、迁移前 2 小时长跑和输入/内存/队列检查；E4 仍需真实交战验证。短测通过不能称为产品实时完成。

E1c.1、E1c.2 原型及 E1c.3 范围内验证/吞吐门已完成。E2.1 设备耐久及宿主事件已接，下一次实施进入 E3c 长跑准备与验证；E1d 暂缓，实际生产者接线后若出现重复来源/诊断成本再恢复。桌面默认后端继续保留。
