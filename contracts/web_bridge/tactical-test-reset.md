# 战术测试清空与结算恢复修复

日期：2026-09-15。用户反馈保存战果后下一场准备仍被锁定，并要求能够放弃现有测试成果、清空状态后重新测试。

## 使用方法

战术模式顶部提供 **“清空战术测试数据”**。在战前准备、旧战果恢复、正在交战或结算失败页面均可打开。

点击后说明清空范围，选择 **“确认清空并重新开始”** 即执行；选择“取消”不会清除数据。成功后直接返回新的战前准备，无需先保存战果或完成当前交战。

清除范围：当前战斗与画布状态、全部已保存及待保存战果、导入的测试舰艇实例、战前准备草稿和回执、测试物资库存、入战身份及舰艇占用记录。清空后重新导入舰艇，有限测试物资按初始配置重新建立。

保留范围：用户保存的船壳、舾装设计文件、编辑器会话及恢复草稿、项目美术和模块资源。清空操作只删除战术仓库内列明的数据表内容，不递归删除项目目录。

若清空回执丢失，使用“重试清空”查询同一次操作。确认结果前不继续旧场景；已完成的清空不会因重试再次删除新一轮测试。另一个窗口仍持有实际战斗时，需要先关闭那个窗口，以免一个窗口清空、另一个窗口回写旧战果。

## 保存锁定的原因与修复

本地仓库存在多份旧待保存结算。恢复页原先保存一份后仍停留在该份已保存结果上，但返回准备要求整个队列清空；提示却继续要求保存“当前结果”。现在显示剩余份数，保存一份后自动打开下一份待保存结果。

同时修复两处回执衔接：恢复页刷新时重新读取当前结算，能够识别“实际上已保存、只是回执丢失”；交战页收到成功保存回执后立即更新当前结算的保存状态，随后场景读取失败也不会重新锁住下一场准备。保存另一份历史结果仍不能解锁当前未保存场景。

发现实时视图后台测试曾使用默认战术仓库，可能向用户入口遗留测试结算。相关测试及其标准输入输出后台进程现已显式使用独立临时目录。

## 实现与验证

`tactical.reset_test_state` 通过原生桥接转到同一个串行战术工作线程。持有战斗占用锁后，在一个数据库事务中清除固定表清单；成功提交后替换内存战斗服务并返回准备模式。失败则回滚全部删除并保留原场景与占用锁。无需解析损坏的结算内容，读取或保存失败的记录不会挡住清空。

数据库保留最小重置回执，仅用于跨重启识别重复请求，不属于可恢复的舰艇或战果。编辑器与设计文件不参与重置。
