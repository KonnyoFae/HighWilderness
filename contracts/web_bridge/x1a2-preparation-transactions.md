# X1a.2 战前库存与预装填事务

日期：2026-09-11。状态：`X1A2_SCOPED_PASS / X1A3_NEXT`。基线为 `438a73a` 加 X1a.1/X1a.2 工作区实现。下一步是[战前准备界面](./x1a-battle-preparation-plan.md)；本片是后台事务，不包含新的可操作页面或自建设计实战入口。

## 已实现

`PreparationStore` 与 P3 使用同一个 SQLite 舰船表，新增设计归档、有限供给及准备回执表。新舰保持独立身份和空库存；重复创建同一设计实例返回当前状态，不能复活、重置战损或补满。已有供给不能靠重新初始化恢复数量。设计/供给初始化为受信应用操作，之后的玩家操作只提交绑定现有记录的准备草稿。

逐舰的库存目标表示“预装填前希望装载的数量”；预览同时显示装填后的实际余量。全部舰船先卸载、再装载，因此从另一艘舰卸下的资源可以经指定供给方转入本舰，不依赖舰船排序。弹药按资源点管理，货物按共享容积管理，后台保留实际供弹库来源。容量、模块损毁及来源库存不足都不会产生半完成保存。

预装填复用 P1b 的供弹分配与完成扣费规则。新增离线准备动作按整批计算 C 点换 N 发，多个批次一次完成；不推进战斗时钟，不清除原冷却。可以保留半条弹链并补入能容纳的完整批次；未勾选的武器保持原待发弹。多舰或多武器缺料时预览汇总缺口，无法完整执行的准备不提交任何部分。

显式“弃置并重装”记录旧待发弹损失，不退款；新弹仍按配方付费。该方法禁止对已挂接实时战斗的库存调用，战斗内不能使用它跳过装填等待。特殊配方可按批同时消费货物；特殊弹的实际效果和用户可选范围仍受资源政策控制，本片不启用新的特殊弹效果。

货舱损毁超容可保持、消费、卸载和保存；新增货物必须满足容量。损毁或宿主损毁的武器不能预装填，不可用弹药库不能供弹或新增装载。准备不修复舰体、局部装甲、模块、故障或旧余弹，也不要求所有武器必须有弹。

## 保存和失败边界

- 预览只生成私有候选，不修改舰船和供给。任一错误的预览返回问题列表及空的可提交结果；丢弃草稿不扣资源。
- 提交在同一 SQLite 事务中重读原状态、核对设计/实例/供给修订，再提交全部舰船、供给及稳定准备回执。每次成功准备推进一次版本；保留现状的成功准备也形成明确的新入战基线。
- 同一准备 ID 和相同请求的重试直接读取原回执，重启或更晚已有新准备也不会重新扣费；同 ID 不同内容明确拒绝。新的准备 ID 携带过期状态或供给版本时拒绝覆盖。
- 写入中途失败或进程退出会回滚全部舰船、供给及回执；既无只更新第一艘舰，也无成功回执对应失败库存。不同舰船同时争用同一供给修订时也不能重复支出。
- 已有未提交 P3 战后结果的舰船不能准备。提供持久入战占用接口，防止被战斗占用的实例再被准备改写；对应场景的 P3 结算提交与释放占用同事务完成，其他场景不得覆盖该实例。
- 准备结果中逐舰保存前后状态、容量、动作选择和资源变动原因，供给前后值独立列示。战斗统计应从该已准备状态开始，不能再把预装填成本扣一遍。

入战占用尚未接到现有技术舰 UI。X1a.4 需要在创建新场景时接入占用、进入失败后的处理与幂等场景请求；本片不宣称已提供完整的场景创建事务。原型校验、库存解析、数据库操作只在准备/保存边界发生，未加入正常飞行热循环。装载质量及惯量仍沿用当前静态政策。

## 验证结果

相关测试分组执行，累计 **127 项通过**：

- 19 项新事务测试：纯预览、全部缺口、跨舰转移、多武器缺料、冷却及部分弹链、整批容量、弃置/特殊材料扣费、离线动作隔离、损毁限制、超容、旧版本/回执重试、仓库损坏、并发供给及非法输入。
- 44 项原库存和结算测试：既有装填预留、战后完成和持久保存兼容性。
- 64 项火炮、毁伤、设计准备及持久状态测试：共用装填代码的实际交战路径回归。

故障测试包括在第一艘舰 SQL 写入后执行独立进程退出，随后重新打开仓库并重试；还覆盖舰船写入后供给写入失败、提交回执丢失、并发的两份独立舰船准备争用相同物资版本。

运行 `python -X utf8 -m tools.verify_preparation_transactions` 可重建[事务往返证据](../../artifacts/x1a2-preparation-transactions/result.json)：两舰分别装载 20 点弹药资源与 2 份货物，按选择完成武器预装填；供给从 100 点降到 60 点。重新打开仓库并重复提交费用不变，下一份保留现状准备没有额外消费。具体逐舰余弹、资源及版本见[准备结果](../../artifacts/x1a2-preparation-transactions/preparation-result.json)。验证使用临时仓库，不修改玩家实际存档。
