# 7c.1b 观测公共输入复用证据

输入沿用 `../tactical-7b-20261009` 的六套冻结战局。参考为 `c0554da` 的观测/电子战方法，新旧两侧都保留已经交付的 7c.1a 区域遮挡优化；本目录只评估 7c.1b 的增量，不用两日前不同机器负载下的计时相减。

- `validation.json`：两批回归共执行 118 项，去重 112 项；新增 7 项涉及候选阶段隔离、距离边界、设备/人员、共享航迹、显示结果与失败步骤。
- `validated-source.json`：验证使用的生产代码、冻结参考、对照工具与测试代码哈希。
- `verify/<case>/source.json`：来源与工具指纹，以及六个参考方法和 `c0554da` 原代码的语法树核对结果。
- `verify/<case>/verification.json`：每场逐步完整状态比较、18 类状态、原 7b 摘要核对、最终负载和诊断计数；`expanded-tape.json` 保存每步各状态的哈希。
- `measure/<case>/`：无分析器/无调用计数的串行独立计时。每场三组，顺序旧→新、新→旧、旧→新；重建相同战局，清空跨战局预测/射程缓存，分别记录步进、发布、读取和服务 CPU。
- `summary.json`：已完成对照的调用计数、逐场核对及配对计时差值汇总；正百分比表示耗时增加。

诊断中的 `observation_hypot` 仅统计观测模块的距离函数调用，`effect` 统计该模块的设备/人员能力计算，不是整个后台所有同类操作。`visible` 是实际可见性判定调用数；结果复用不降低其调用频率。`verify` 可与其他正确性检查并行，其耗时不作为性能结论；正式 `measure` 单独串行运行。

扩展状态比较不包含墙钟、测试计数或派生缓存；失败步骤另验已提交状态、已有缓存与运行时属性不变。单次观测/显示的临时对象和单次电子场回调中的位置表不保存到运行时或战斗存档。

六套状态对照与两套 9 对 9 性能样本仍为离线 900 步窗口，不代替墙钟调度、原生绘制或完整自然战斗。正常速度和将来的自动降速验收保持分开；本片没有实现 7c.4b。

实施与范围见[7c.1b 记录](../../contracts/web_bridge/tactical-stage7c1b-observation.md)。
