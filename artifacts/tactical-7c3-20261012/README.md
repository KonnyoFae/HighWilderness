# 7c.3 导弹防御与碰撞优化证据

参考为已经推送的 `3a4dc2c`，新旧均保留 7c.1a、7c.1b、7c.2。输入完全沿用 `../tactical-7b-20261009`，不重建身份或补充负载。

- `before-hotspots-mixed-9v9/`、`after-hotspots-mixed-9v9/`：第 1～60 和 601～660 步的调用分析，另核对整个 900 步原摘要。工具的范围文字更新为明确标注所测源码版本，避免旧的“尚无生产优化”说明混淆当前基线。分析器耗时不能用于计算加速比例。
- `validation.json`、`validated-source.json`：134 项通过的回归及受测源码指纹。
- `verify-<case>/`：每场 900 步的 18 类权威状态对照、原 7b 摘要、诊断调用数及运行前指纹。
- `measure-<case>/`：所有诊断/正确性进程结束后独立串行测量，每场三组 AB/BA/AB。无调用计数或分析器，每轮清空共享物理预测缓存并恢复同一冻结战局；每步摘要和最终扩展状态仍核对。
- `interleaved-mixed-9v9/`：独立计时出现波动后追加的逐步交替补测。每步交换先运行的一方，缩短前后比较的时间间隔；两场战局共享进程物理缓存，不能与独立轮次合并统计。运行脚本为 `supplement_interleaved.py`，入口与来源单独留档。
- `summary.json`：状态摘要重新哈希、来源核对、调用计数和三组计时汇总。正百分比表示耗时增加。
- `collision-trial/`：已撤下的碰撞优化试验，独立保存源码、六场状态对照和纯炮计时，不计入最终版本结果。最终碰撞实现保持 `3a4dc2c` 原样。

诊断 `commitments` 只计导弹防御模块的调用，不含其他模块的别名；`segment` 和 `_segment_aabb_entry_fraction` 为毁伤模块的精确线段/格子求交；`guidance.contact` 为导引头候选检查，`guidance.blocked_channels` 只计导引头模块经当前函数入口的遮挡调用，不含航空/舰艇模块预先导入的别名。减少不可能合法的候选不改变实际采样时刻。计数与性能测量分离。

冻结函数只供对照工具执行，原型/物资/炮弹/人员等规则保持不变。18 类权威状态不包含派生缓存/计数/墙钟；失败回退测试另核对已有预测缓存和指标未提交。单次准备的索引与筛选列表均不持久保存。工具保留两份参考函数，最终版本的碰撞函数已恢复原实现，因此它在新旧两侧相同。

可从仓库根目录运行 `./artifacts/tactical-7c3-20261012/audit.ps1`，重新核对完整扩展摘要、前片结果、每次运行的源码指纹、测量末态并生成汇总。正式计时的正负波动全部保留，不挑选最佳组作为结论。

实施范围与最终结果见 [7c.3 记录](../../contracts/web_bridge/tactical-stage7c3-defense.md)。本片没有实现自动降速，仍不代表固定 1× 实时通路、原生绘制或完整自然战斗验收通过。
