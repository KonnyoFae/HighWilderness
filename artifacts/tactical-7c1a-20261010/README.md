# 7c.0 / 7c.1a 实施证据

输入沿用 `../tactical-7b-20261009` 的冻结战局，未重新生成舰艇、人员、库存或脚本命令。生产改动只有 `missile_guidance.py` 的两个区域遮挡函数；规则和采样频率保持不变。

- `validation.json`：76 项专项回归结果，含随机/相切边界、敌我/层/导引组合、状态快照和事务回滚验证。
- `verify/<case>/source.json`：来源、工具哈希和旧函数与 `79db27e` 语法树一致的核对结果。
- `verify/<case>/verification.json`：逐步匹配数、18 类状态范围、冻结输入哈希、最终负载及诊断调用数。
- `verify/<case>/expanded-tape.json`：每一步的 18 类状态哈希，整体哈希记在对应报告中。运行中实际比较完整状态树，失败会另写字段路径与两份状态。
- `measure/<case>/`：单独的无分析器、无调用计数计时；每组旧/新各一次，共 3 组，第二组交换顺序。每次重建战局，并清空跨战局的物理预测/射程缓存，避免后运行的版本直接继承前一版的预测结果。保留每轮报告和原始分布摘要。
- `interleaved/guns-9v9/`：针对纯炮波动的补充对照，每步交替新旧版本的执行顺序；两局共享进程缓存，单列记录，不与独立战局计时分布混合。
- `verification-audit.json`：按原契约的排序、两空格缩进及末尾换行重新核对 900 步扩展摘要哈希；输入与原 7b 一致。
- `measurement-summary.json`：三组原始计时的差值汇总，正百分比表示耗时增加；12 轮均核对原 7b 摘要。
- `validated-source.json`：通过回归的生产改动、参考实现、扩展状态工具及专项测试指纹。

诊断计数中，`input_regions` 是传入函数的区域数，不等于优化后实际访问数；`irrelevant_*` 是按输入判定的无关区域数；`geometry_calls` 是实际几何调用次数。`geometry_hits` 只表示区域相交，不是战斗命中计数。旧/新版可能检查不同数量的重复遮挡，但其权威观测、锁定、伤害和资源必须一致。

`verify` 会增加状态序列化与计数开销，不拿其墙钟时间计算收益。`measure` 的 `service_wall_s` / `service_cpu_s` 仅覆盖步进、发布和读取，不包含战局恢复和摘要记录，也不是按墙钟推进的实时验收。

每次运行保留独立指纹。首个混合场景对照后，计时工具补充每轮清空全局物理预测缓存；独立计时完成后增加逐步交替补测入口。这些工具变动没有改动已完成对照使用的生产函数、参考函数或扩展状态记录。
