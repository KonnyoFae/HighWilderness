# 7c.4b 显示与操纵延迟收尾证据

2026-10-13，基于 `ecafbff`，生产改动仅为前端显示时钟相位恢复。新增和更新显示测试，另加只在诊断时加载的 Python/浏览器测量工具。后台模拟、调度、指令目标步和六步窗口未改。

## 采集阶段

- `live-mixed-9v9/`：首轮对象绑定，20 次命令执行。误用按钮正文识别点击，未记录点击起点，只有提交后的计时有效；不作为完整点击链验收。
- `final-mixed-9v9/`：修正为按钮的可访问名称，完整对象绑定链，20 次命令执行。
- `final-guns-4v4/`：扩大操纵样本时，20 次尝试中一次被六步窗口拒绝，19 次接受并执行。保留 `failure.txt`/图片/所有命令，不能称为全通过；该轮串行批次在断言失败后终止，其他两场未采集。
- `verified-guns-4v4/`：首轮 JSON 文本绑定，20 次命令全部执行，约 42 秒时自然终局。旧测试断言只接受仍在运行，误将正常终局记为失败；该轮证据保留，后续工具允许正常终局，保护暂停仍失败。
- `complete-*/`：JSON 文本绑定的四场最终采集。Python 仍使用真实服务，Node 将同一响应序列化，浏览器解析后交给同一个测试入口；不改变前后端业务载荷、命令或调度。此项分离自动化工具的对象序列化开销，不是生产代码优化，也不等于原生 Tauri IPC 验收。对象模式的失败记录继续保留。

早期采集与最终采集的工具指纹不同，分别记录在各目录 `source.json`；生产来源一致。不要把前几轮旧工具的哈希与最后工具直接相等比较，也不能混算不同桥接通路的收益。

每场观察至 45 现实秒或自然终局，从真实操纵面板点击 20 次，并在运行中采集舰艇选择反馈。最终验收仍要求 20 次全部接受、执行和到达显示步，不能以正常终局放宽命令计数。动作改变战局，所以不同实时运行的战况不逐步等价；只在同一场内部比较两个显示时钟。

## 可比较的时钟与分段计时

每次提交给真实显示时钟的已提交状态和采样时间，同时交给旧时钟的影子实例。影子复用同一类的其他方法，只有 `advance()` 换回 `ecafbff` 的原算法；本片对该类的唯一生产改动恰好也是该方法。因此新旧时钟比较使用同一条数据交付轨迹和同一帧时刻，不受两场战斗波动影响。影子不下发命令、不推进模拟，也不绘制；其额外采样 CPU 成本仍包含在实际页面运行环境中，这不是无测量开销的吞吐基准。

- 浏览器：点击、等待旧读取/前置新读取、提交、接受响应、收到执行回执、收到包含执行步的视图、进入时间线、画布绘制提交；`calls`、`commands`、`deliveries` 保留原始时间。
- Python：请求执行起止、命令接受/执行、视图发布及读取；用请求 ID 对应 Node 与浏览器请求。只在本进程的单调时钟内计算差值，不直接相减不同进程的绝对时间。
- Node：实际 stdio 请求往返；与同一请求的 Python 执行耗时比较，可估算队列/stdio/解析等剩余成本。浏览器绑定往返减 Node 往返用于识别自动化交付开销；这些嵌套统计不能重复相加。
- “画布”是绘制提交，未测量 GPU 或实际屏幕像素。选择反馈为点击后的两帧时长。P95 沿用 `floor((n-1)*.95)`，每场 20 次仍是短样本。

新时钟仅遍历已提交历史，保留原 100 ms 缓冲参数、单调推进、最新状态上限、暂停/换场清理和事件规则。极低速或断流使权威数据稀疏时，仍可在最新状态上停留。显示相位改善不消除目标模拟步等待，更不代表 250 ms 完整交互目标或 1× 性能通过。

```powershell
node tools/verify_tactical_7c4b_closeout.mjs artifacts/tactical-7b-20261009/mixed-9v9 <新的输出目录> --seconds 45 --commands 20 --json-bridge
```

