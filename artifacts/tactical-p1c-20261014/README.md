# P1c 碰撞资格前筛与层切分复用证据

基线为已推送的 `ad3870c`。仅替换 `DamageKernel.advance`；参考方法冻结在 `tools/tactical_p1c_reference.py`，每次启动先核对原提交的 AST。两条路径都保留 P1a 手动箔条、P1b 观测能力复用及既有物理/调度规则。

- `backend-tests.txt`、`validation.json`：185 项相关回归及完整命令，含新增六项 P1c 边界测试。回归和状态对照可并行，正式计时没有其他本任务的测试进程竞争资源。
- `verify-<case>/`：六套冻结场景各 900 步、18 类权威状态与原 7b 摘要逐步一致，每场 227 次公开读取一致。附带的调用计数仅作归因，不作性能结果。
- `verify-chaff/`：沿用 P1a 冻结舰艇和 P1b 补充工具，前后两条路径均执行同一份手动投放/测试注入到期命令。200 步对照通过，保留正常锁定→干扰降级→恢复过程。工具注入的短到期边界不是生产持续时间改动。
- `measure-<case>/`：纯炮/混合 9 对 9 各三组独立计时，顺序 AB/BA/AB。每轮重建战局、清空预测与射程缓存，单独记录步进、发布、读取编码和服务 CPU；逐步匹配原 7b 摘要，并比较最终扩展状态。无分析器或计数包装。
- `paced-final-<case>/`：两场各一组旧/新实现与固定/自动模式的串行真实服务复查。观察上限均为 300 现实秒，目标为完成 900 步；记录实际步数、速度变化、积压、暂停原因及最终负载。生产速度策略和保护阈值未改；单组服务结果不用于宣称稳定加速。
- `interleaved-guns-9v9-final/`、`interleaved-mixed-9v9/`：针对独立运行波动的补充诊断，每一步交换新旧实现的执行顺序。两场共享进程中的物理缓存，因此与独立运行的分布分列，不合并计算平均收益。
- `paced-guns-9v9/`：独立混合计时三组出现回退后中止了原串行服务测量，转而先查明性能方向。保留已经完成的参考固定/自动、新版固定记录，不当作完整配对。
- `interleaved-guns-9v9/`：第一次交替补测启动后，进程核对短暂观察到两组本工具的 Python 进程，说明先前停止后的子进程退出存在延迟。随后仅余当前补测进程。该纯炮样本可能受重叠负载影响，保留但不作为最终性能结论；另在无重叠条件下复测到 `-final` 目录。混合交替测试在旧进程退出、第一轮纯炮结束后才启动。
- `collision-mixed-9v9/`：混合真实服务用时也回退后，补充同一输入的碰撞函数成对计时。每个实际战斗边界交替执行两个方法，先精确比较返回的弹体、毁伤与操作结果，再只提交新版结果；原 7b 摘要逐步核对。保留所有有弹体边界的原始样本。该分项诊断共享进程缓存，不包含其他模拟、发布与传输，也不替代整体性能验收。

两场 9 对 9 的弹体层切分调用约减少 94.4%；局部扫掠、精确边求交、包围盒求交、甲板接触和甲板选择调用数全部保持一致。调用数下降不等于整体耗时同比下降。

本片没有修改前端，也不新增页面延迟或原生验收声明。此前 P1b 页面记录保留原范围；固定 1×、250 ms、完整战斗和原生验收分别跟踪。

结果：纯炮独立均值两组改善、一组回退；混合三组独立计时均回退。干净交替诊断中，纯炮均值减少约 8.95%，混合约 2.31%；相同混合输入的碰撞函数均值减少约 14.51%。四次最终自动服务均完成 900 步，固定 1× 均过载；自动服务纯炮 98.22 → 57.23 秒、混合 197.04 → 235.78 秒。保留计算复用，但不申报整场稳定提速；混合独立与服务回退继续作为 P2 需复核的限制。

最终复核入口为 `node artifacts/tactical-p1c-20261014/audit.mjs`；索引覆盖原始证据字节。该入口同时核对当前生产/输入指纹和本片测试工具，因此后续生产代码变更后需在本片对应版本复核。历史 P1a/P1b 证据未修改。结果与后续见[P1c 实施记录](../../contracts/web_bridge/tactical-p1c-collision.md)。
